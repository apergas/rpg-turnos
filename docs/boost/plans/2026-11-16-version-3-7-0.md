# Version 3.7.0: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use boost:subagent-driven-development (recommended) or boost:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Four changes from the spec `docs/boost/specs/2026-11-16-version-3-7-0-design.md`: the pause menu's «Volver al título» becomes «Salir» and, on the web only, «Buscar actualizaciones» checks the published version and installs a newer one (M-101); the game's version shows in the bottom right corner while the pause menu is open, exactly as on the title screen (M-102); the Incienso is gone, and a save carrying one gets its sell price in gold (M-103); the Equipo page no longer shows the ATK / DEF / VEL totals line (M-106). The save stays at version 16.

**Architecture:** One new pure class, `GameVersion` (`scripts/game/game_version.gd`): the build's version (`current()`) and how a published one compares (`check()`, number by number). One constructor, `UiTheme.version_label(parent)`, used by `TitleScreen` and `PauseMenu`. The existing `WebUpdate` (today a `RefCounted` with three static functions for the title's "Hay una versión nueva" notice) becomes a `Node` piece of `Game` that keeps those statics and adds the pause menu's check (`HTTPRequest` child reading `version.json`, which `pages.yml` writes) and install (`JavaScriptBridge.eval()` with a `create_callback()` answer). `WebUpdate.setup(ctx, pause)` wires itself to the `PauseMenu` both ways (as `FigureTalk` and `CaravanFlow` are handed the `ShopWindow`), so `game.gd` only gains four lines. `PauseMenu` only emits `update_check_requested` / `update_requested` and shows what `WebUpdate` reports. The Incienso's removal is subtraction across `Inventory`, `Shop`, `GameState`, `Game`, `World`, `MapMonsters` and `PauseMenu`; `SaveData.apply()` sells a carried Incienso through `RETIRED_ITEMS`.

**Tech Stack:** Godot 4.7.2 (Compatibility), GDScript, scenes as text, web PWA single-threaded, GitHub Actions (`pages.yml`), browser JavaScript (service worker, Cache Storage, `fetch`).

## Adaptations to the spec

1. **The name `WebUpdate` is taken** by the title's helper (since 2.x, commit 2685bdc). The spec's new piece takes that name: the class becomes `extends Node`, keeps `watch()`, `is_ready()` and `apply()` as static functions (the title has no session; a static function on a `Node` class needs no instance) and adds the piece. One class, both ways a deploy reaches a player; the title's calls do not change.
2. **The comparison rule is a pure class**, `GameVersion` (`RefCounted`, static only: `current()`, `parse()`, `check()` with `enum Check { LATEST, NEWER, UNKNOWN }`), not a static function inside the `Node`: it also gives `current()` to `UiTheme.version_label()`.
3. **The install order.** The old service worker keeps answering this page until it reloads, even after `unregister()`, and it serves `index.*` from its cache whatever `cache: 'reload'` says. So the JavaScript clears this game's caches **first** (as the spec lists), unregisters, downloads (the worker, missing its cache, goes to the network past the HTTP cache), and **clears again** (the worker stored the downloads in a cache of the old name), then answers. Besides `index.html` it also downloads the page's own address (`location.href` without `#`): Pages serves the game at `.../rpg-turnos/`, a different HTTP cache entry.
4. **The Incienso's price after it is gone.** `SaveData.RETIRED_ITEMS := {"incienso": 10}`: what `Shop.sell_price()` paid for one (half of 20 G). `apply()` sells them before `set_items()`.
5. **`WebUpdate` is handed the `PauseMenu`** in `setup()` and connects both ways (the menu's two request signals to `check()` / `install()`, its own `reported` / `found` signals to the menu): `Game` stays within its budget, as `FigureTalk` and `CaravanFlow` take the `ShopWindow`.
6. **Pause.** The pause menu pauses the tree: `WebUpdate` sets `PROCESS_MODE_ALWAYS` (its `HTTPRequest` child inherits it), or the answer and the 10 s timeout would wait until the menu closed.
7. **«Buscando actualizaciones…» comes from `WebUpdate`** (`reported`), not from the menu: a press during a search (or during a download) then changes nothing at all, not even the line.
8. **An answer after the player left the main page.** Its line still goes to the main page's message (seen on coming back). A newer version opens the Actualizar page only while the main page shows; otherwise the line is cleared and the next press asks again.
9. **A failed save at «Actualizar»** (the spec does not say): «No se pudo guardar.» (the text of «Guardar») and no download.
10. **The message wraps** at `MESSAGE_WIDTH` (`autowrap_mode`): «Ya tienes la versión más reciente (v3.7.0).» is wider than the system window, and a message must never move the buttons (QA-06).
11. **Where the label sits in the menu:** a child of `PauseMenu` added right after the shade, before the windows: it is not darkened, and if a window ever reached the corner the window would cover the label, never the reverse. The frames check that none does.
12. **`world.gd` is 743 lines**, already above the 725 the brief gave. This plan only removes lines from it (`set_repel()`, the hunter's `is_repelled()` test: expected 738); reaching 725 would need an unrelated extraction and is left out.
13. **The local web server** uses port 8370, not the QA brief's 8060, so no saves of another `localhost` origin are touched.
14. **M-106** (added to the spec after M-101 to M-103) goes in the pause-menu task (Task 3), with a frame of the Equipo page.

## The game's version, "mayor.menor.parche" (application/config/version): the one this build
## is (current(), which UiTheme.version_label() shows) and how a published one compares with it

const SETTING := "application/config/version"

static func current() -> String:

## The three numbers of text ("3.10.0" -> [3, 10, 0]; spaces around it are ignored), or [] if
## it is not three whole numbers, digits only, joined by dots.
static func parse(text: String) -> Array[int]:
	var numbers: Array[int] = []
	var parts := text.strip_edges().split(".")
	if parts.size() != 3:
		return numbers
	for part in parts:
		if part.is_empty() or part.lstrip(DIGITS) != "":
			numbers.clear()
			return numbers
		numbers.append(part.to_int())
	return numbers


## Compares published with mine number by number, so 3.10.0 is newer than 3.9.2: NEWER only if
## published is greater, LATEST if it is the same or older, UNKNOWN if either can't be read.
static func check(published: String, mine: String) -> Check:
	var theirs := parse(published)
	var ours := parse(mine)
	if theirs.is_empty() or ours.is_empty():
		return Check.UNKNOWN
	for i in theirs.size():
		if theirs[i] != ours[i]:
			return Check.NEWER if theirs[i] > ours[i] else Check.LATEST
	return Check.LATEST
```

## Node, a piece of Game, and the web build's updates; off the web (available() false) it does
## nothing. Two ways a new deploy reaches a player:
## - The title screen (static, no session): a new service worker installs and waits until

##   unregisters this page's service worker, downloads the new files past the HTTP cache and

## A line for the pause menu's message (PauseMenu.show_update_line()).
signal reported(text: String)
## A newer version is published (PauseMenu.show_update_found()).

const LATEST_TEXT := "Ya tienes la versión más reciente (v%s)."

## (apergas.github.io) is shared with other projects: only these are ever deleted.

window.villaclaroUpdate = false;
if ('serviceWorker' in navigator) {
	navigator.serviceWorker.getRegistration().then(function (reg) {
		if (!reg) { return; }
		var mark = function () { if (reg.waiting) { window.villaclaroUpdate = true; } };

			if (reg.installing) { reg.installing.addEventListener('statechange', mark); }

const APPLY_JS := """
navigator.serviceWorker.getRegistration().then(function (reg) {
	if (reg && reg.waiting) { reg.waiting.postMessage('update'); }

"""
## install()'s JavaScript, formatted with the cache prefix as a JSON string. The old worker
## keeps answering this page until it reloads and serves index.* from its cache whatever the
## request asks, so its caches go first; it then fetches from the network (cache 'reload'
## refreshes the HTTP cache too) and stores the files again, so they are cleared once more.
## Answers window.villaclaroUpdateDone(true), or (false) if anything failed.
const INSTALL_JS := """
(function (prefix) {
	var done = window.villaclaroUpdateDone;
	var page = location.href.split('#')[0];
	var files = [page, 'index.html', 'index.js', 'index.wasm', 'index.pck'];

		if (!('caches' in window)) { return Promise.resolve(); }
		return caches.keys().then(function (keys) {
			return Promise.all(keys.filter(function (key) {
				return key.indexOf(prefix) === 0;
			}).map(function (key) { return caches.delete(key); }));
		});

		return navigator.serviceWorker.getRegistration().then(function (reg) {
			return reg ? reg.unregister() : false;
		});

				return response.arrayBuffer();
			});
		}));
	}).then(clear).then(function () { done(true); }, function (error) {
		console.error('Villaclaro update:', error);
		done(false);
	});
})(%s);
"""

var _ctx: SessionContext
var _request: HTTPRequest
var _checking := false
var _installing := false
## Kept alive: JavaScript calls it when install() ends (JavaScriptBridge.create_callback()).
var _install_done: JavaScriptObject


func setup(ctx: SessionContext, pause: PauseMenu) -> void:
	_ctx = ctx
	pause.update_check_requested.connect(check)
	pause.update_requested.connect(install)
	reported.connect(pause.show_update_line)
	found.connect(pause.show_update_found)


func _ready() -> void:
	# The pause menu pauses the tree, and its answer (and the timeout) must still come.
	process_mode = Node.PROCESS_MODE_ALWAYS


static func available() -> bool:
	return OS.has_feature("web")


static func cache_prefix() -> String:
	return String(ProjectSettings.get_setting("application/config/name")).substr(0,
		CACHE_NAME_LENGTH) + "-sw-cache-"


static func watch() -> void:
	if available():
		JavaScriptBridge.eval(WATCH_JS, true)


## eval() hands a JavaScript boolean back as 1 or 0, which can't be compared with a bool.
static func is_ready() -> bool:
	return available() and int(JavaScriptBridge.eval(FLAG + " ? 1 : 0", true)) == 1


static func apply() -> void:
	if available():
		JavaScriptBridge.eval(APPLY_JS, true)


## Asks for VERSION_FILE; nothing while a check or an install is under way.
func check() -> void:
	if not available() or _checking or _installing:
		return
	if _request == null:
		_request = HTTPRequest.new()
		_request.timeout = CHECK_TIMEOUT
		_request.request_completed.connect(_on_version_read)
		add_child(_request)
	reported.emit(SEARCHING_TEXT)
	if _request.request(_version_url()) != OK:
		reported.emit(UNKNOWN_TEXT)
		return
	_checking = true


## VERSION_FILE next to the page, with the time in its query so no HTTP cache answers for it
## (GitHub Pages sends max-age=600). It is in no list of the worker: the network serves it.
static func _version_url() -> String:
	var page := String(JavaScriptBridge.eval("location.href.split('#')[0].split('?')[0]", true))
	return "%s%s?t=%d" % [page.substr(0, page.rfind("/") + 1), VERSION_FILE,
		int(Time.get_unix_time_from_system() * 1000.0)]


## No answer, an error, a timeout or a body that is not {"version": "x.y.z"}: UNKNOWN.
func _on_version_read(result: int, code: int, _headers: PackedStringArray,
		body: PackedByteArray) -> void:
	_checking = false
	var published := ""
	var json := JSON.new()
	if result == HTTPRequest.RESULT_SUCCESS and code == 200 \
			and json.parse(body.get_string_from_utf8()) == OK and json.data is Dictionary:
		var version: Variant = (json.data as Dictionary).get("version")
		if version is String:
			published = version
	match GameVersion.check(published, GameVersion.current()):
		GameVersion.Check.NEWER:
			found.emit(published.strip_edges())
		GameVersion.Check.LATEST:
			reported.emit(LATEST_TEXT % GameVersion.current())
		_:
			reported.emit(UNKNOWN_TEXT)


## «Actualizar»: saves like «Guardar», then INSTALL_JS; nothing while one is under way. A
## failed save stops it.
func install() -> void:
	if not available() or _installing:
		return
	var saved: Dictionary = _ctx.autosave.call(false)
	if saved.is_empty():
		reported.emit(SAVE_FAILED_TEXT)
		return
	_installing = true
	reported.emit(DOWNLOADING_TEXT)
	if _install_done == null:
		_install_done = JavaScriptBridge.create_callback(_on_install_done)
		JavaScriptBridge.get_interface("window").set(DONE_NAME, _install_done)
	JavaScriptBridge.eval(INSTALL_JS % JSON.stringify(cache_prefix()), true)


## INSTALL_JS's answer: everything new is in the HTTP cache and the old worker and its caches
## are gone, so the reload starts the new version; otherwise the old one goes on running.
func _on_install_done(args: Array) -> void:
	_installing = false
	if not args.is_empty() and bool(args[0]):
		JavaScriptBridge.eval("location.reload();", true)
		return
	reported.emit(DOWNLOAD_FAILED_TEXT)
```
