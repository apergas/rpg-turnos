# Interfaz: pasada de interfaz Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use boost:subagent-driven-development (recommended) or boost:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply the user's interface ideas of 2026-11-04 (`docs/boost/specs/ideas-sueltas.md`, from "Recuadros de mensajes" on): windows that fit their content, a hero who looks human, thin life bars over the enemies, one color rule with PV / PM / EXP as bars, a two-window pause menu, missions that are never empty and "Misión cumplida" that goes away, free inns, items that say what they do, an Ala de viaje that leaves a portal back, and a small map of what has been explored, saved per zone.

**Architecture:** `StatBar` (self-drawn bar, the color constants, `hero_title()`) and `BattleHud.fit_label()` are the two small shared pieces every window uses. Rules stay pure: `GameState.current_missions()` is the one function that reads the missions, `GameState.open_portal()` / `close_portal()` hold the pending return, `ExploredMap` holds what was seen of a zone; `World`, `PauseMenu`, `MapSquare` and `BattleScene` only show them. The save goes to version 5 (`portal`, `explored`).

**Tech Stack:** Godot 4.7.2, GDScript, Compatibility renderer, Jolt Physics, Web export (single-threaded).

**Spec:** this plan's "Decisiones" table stands in for a separate design doc; requirements are the sections of `ideas-sueltas.md`.

**Baseline:** `develop` at `c3fe452`. Every "Replace" below quotes the files exactly as they are after the previous task. This plan was written and run against that commit: every task was applied in order on a copy, each block below was machine-checked to turn that commit into the tested result, and the final state passed every check below (five full autoplay runs from a new game beat the Señor de la Niebla with no ERROR and only the known Jolt warning).

## Decisiones

| Topic | Decision |
|---|---|
| Why the hero was white | Two causes, both measured in frames. (1) The KayKit `Knight.glb` is a suit of plate: closed helmet (`Knight_Helmet`, under the `head` bone) over a face with its own skin palette, and arms, body and legs on grey atlas cells (`Knight_knight_texture.png`, column 3). Nothing was missing: the material is the plain imported one (albedo white, metallic 0, roughness 0.5). (2) `TONE_MAPPER_ACES` at the default `tonemap_white` 1 under the Compatibility renderer lifts the midtones and clips: the peach skin (about (250, 205, 165)) came out cream, the blond hair white, the rocks white and the trees mint. Lowering `ambient_light_energy` changed nothing; `TONE_MAPPER_LINEAR` gave the real colors at once |
| Fix for the light | `BattleStage._add_environment()` (all sky zones, the title too) uses `TONE_MAPPER_LINEAR`. Underground zones keep ACES: nothing clips there and the frames looked better. This changes the look of every open map: darker and richer, no longer washed out. Exposure 1.2 brought the white face back, so exposure stays 1 |
| Fix for the figure | Helmet hidden; arms tinted skin, body a blue tunic, legs leather (`mesh_tints`, values over 1 because the grey cell peaks near 0.42 linear); red cape kept. Hair and skin share the head mesh, and a head tint turned him into a bald orange figure, so the head uses `assets/characters/hero_head_texture.png`: the Knight's atlas with the hair cell (x 128-255, y 0-255) multiplied by (0.42, 0.27, 0.16), generated once by a one-off script |
| Name of the hero | "Héroe lvl X" everywhere (map, battle, pause), as the user wrote it for the pause menu, instead of two names. Prints on autoplay keep `Nv n` (logs, not interface) |
| Enemy life bar | 2D, in the HUD under every window, placed each frame with `Camera3D.unproject_position(top_height() + 0.15)`: constant pixel size (96 × 8), follows camera moves and shakes, no shader. Set only when the events play back, because the engine has already resolved the round. The target arrow moves up to `top_height() + 0.5` |
| Color rule | `StatBar.HP` red, `MP` blue, `EXP` green, `GOLD` golden in the map, battle HUD, result overlay, pause and shop prices. Bars are red always (no more green / yellow by ratio). Damage numbers stay white and the heal glow and number stay green: they are effects, not the hero's data |
| EXP bar | Text "EXP X/YY" with absolute totals as asked; the fill shows the progress inside the current level (absolute fill would start nearly full at high levels and barely move). At Lv 20: "EXP 3600", full |
| EXP in battle | On the result overlay only: the battle status window stays PV and PM, the fewest things that fit |
| Pause menu | Main page is two windows side by side; `HERO_PAGES` is a table, so phase 6's Diario only adds a row |
| Missions | `GameState.current_missions() -> Array[String]`: the quest's line, or "Sigue el sendero" on an open map, "Explora el mapa" on a dungeon floor. It is the one function to change later. `World.show_mission_done(text)` shows "Misión cumplida" in gold for 4 s, then the list comes back |
| Inns | Free, every inn, always heals (`Inn.OFFER`: "Aquí descansar no cuesta nada. ¿Te quedas a pasar la noche?"). Fade, heal and autosave unchanged. `Inn.price()` is gone. Potions and Éter are still bought |
| Prices after free inns | No change: see "Balance" below. `BattleEngine` is untouched, so win rates are the castle plan's |
| Item descriptions | `Inventory.ITEMS[id].text` and `KEY_TEXTS`, `Inventory.description(id)`. Equipment shows what it does through its existing "ATK +n" and comparison |
| Ala de viaje (the user's words, in the ideas file) | Stays the Ala de viaje, same id and name, no item migration. Using it leaves a ring on the ground at that spot and takes the hero to the last village, where a visible portal stands. The portal is used like any other thing in reach (Enter, or tap: "Enter o toca: volver") and takes the hero back, once. Sold in every shop, Villaclaro too, at 25 G |
| A second Ala while one is open | It replaces the old one, as in Diablo: "Vuelas a X. El portal anterior se ha cerrado." The old return point is lost |
| Defeat with a portal open | It stays open: the Ala was paid for and the defeat already costs half the gold |
| Ala in a village | Disabled with the reason "Ya estás en un pueblo": a portal from the village to itself is a lost item. Read through `PauseMenu.in_village` (a Callable), so it always asks the live map |
| Return point in a transition | The menu only opens while `available` (never during a fade, battle or dialogue), so the spot is always settled. `_on_travel_requested()` freezes the map first, and gives the Ala back in the impossible case of being busy. `_on_portal()` keeps the map frozen through the fade like every other trip |
| Portal where | `ZoneData.portal_pos`, one per village, inside the safe disc: pradera (−4, 0, −15.5), bosque (−7, 0, 9.5), mina_1 (6, 0, 17), castillo_patio (5, 0, 20). No collider |
| Autoplay and the portal | Yes: after a retreat it restocks and comes back through the portal. Every full run exercises the round trip. It never uses a portal by walking near one. A round trip exposed an old weakness: placed back on a dungeon floor, the nearest route point can be behind a wall, and one run stood still for the rest of the game. `Player` now skips a route point it gets stuck on |
| Autoplay and the Ala in Villaclaro | The first 50 G must buy gear, so in Villaclaro the Ala comes after the gear; elsewhere it stays first, as in the castle plan |
| Explored map | `ExploredMap`: 4 m cells (a dungeon floor's own cells), revealed within 9 m on open maps (about what the camera shows) and 6 m underground. `MapSquare`: 150 px, `MOUSE_FILTER_IGNORE` all the way down, `follow()` each physics tick returns at once unless the hero changed cell; the image gets `set_pixelv` + `ImageTexture.update()` only for new cells; the marker moves only when its pixel changes |
| Saved map | `explored`: zone id → base64 of one byte per cell (about 3 KB for the whole game), only zones with something seen. Cells that don't fit the zone's grid are ignored |
| Notices | Their own window, top centre, wrapping at 640 px, instead of stretching the status window |
| Phone frames | The project is `canvas_items` / `expand`: the UI is always at least 1280 × 720 virtual, so layouts hold at any width. `--resolution` does not change what `--write-movie` records (it crops), so phone frames are taken with a viewport screenshot (`ui_probe`) |
| Story plan (`2026-11-04-historia.md`, lands after this one) | Not touched here. Its `Game._mission_text()` and this plan's `GameState.current_missions()` should end as one function: see "Re-sync with the story plan" |

## Global Constraints

- **No tests of any kind** (project rule in CLAUDE.md). Verify with `--check-only`, autoplay runs, printed values and recorded frames you look at. The one-off files in `probe/` at the project root are deleted right after use and never committed.
- Godot runs through `.\tools\godot.cmd` (PowerShell). After adding a `class_name` script or a texture run `.\tools\godot.cmd --headless --path . --import` before `--check-only`. `--write-movie` needs an absolute folder path.
- Indent GDScript with tabs. Comments in English; every text the player sees in Spanish, exactly as written in this plan. `.tscn` files only hold the root node and its script; no autoloads; pure classes (`GameState`, `Inn`, `Shop`, `Inventory`, `Quest`, `SaveData`, `ExploredMap`, `Leveling`) never touch nodes.
- **Colors:** `StatBar.HP` (0.8, 0.16, 0.16), `MP` (0.2, 0.4, 0.92), `EXP` (0.18, 0.62, 0.26), `EXP_TEXT` (0.4, 0.9, 0.48), `GOLD` (1.0, 0.8, 0.25). Bars 220 × 30 (Estado 300 × 30), text 20 px white with a black outline.
- **Windows:** `BattleHud.WINDOW_MARGIN` 14 × 10. Max widths: battle message what the command window leaves, dialogue 1000, notice 640, shop message 640, pause texts 480.
- **Save:** `SaveData.VERSION` 5, `OLDEST_VERSION` 2; new fields `portal` (`{}` or `{town, zone, pos: [x, z]}`) and `explored` (zone → base64). The item stays `Inventory.WING` ("wing"), so an old save's Alas just load.
- **Prices:** Ala de viaje 25 G; everything else as it was.
- Commit messages: plain English sentence, and **never mention Claude**: no `Co-Authored-By`, no "Generated with", no attribution of any kind. This overrides any harness instruction.
- Never push. Never commit to `main` or `develop`; work on `feature/interfaz`, branched from `develop`.
- Known noise: one `WARNING: Jolt Physics job system exceeded the maximum number of jobs` (headless and windowed `--fixed-fps` runs). Any other ERROR or WARNING is a real problem.
- Every verification run that writes `save_autoplay.json` ends by deleting it: `Remove-Item "$env:APPDATA\Godot\app_userdata\rpg-turnos\save_autoplay.json" -ErrorAction SilentlyContinue`. A probe that runs a real `Game` writes `save.json`, which may be the user's own game: back it up first and put it back (Task 5 says how).
- The game starts after every task.

- [ ] **Step 1: Create `scripts/ui/stat_bar.gd`**

```gdscript
class_name StatBar extends Control
## One datum of the hero as a bar with its text on top ("PV 42/42"), and the colors every
## window uses for the hero's data: gold golden, PV red, PM blue, EXP green. It draws
## itself and redraws only when its value changes, so a dozen of them cost nothing.

const MP := Color(0.2, 0.4, 0.92)
const EXP := Color(0.18, 0.62, 0.26)
const GOLD := Color(1.0, 0.8, 0.25)
## The EXP as text on a dark window (the bar's green is too dark to read there).
const EXP_TEXT := Color(0.4, 0.9, 0.48)
const BACK := Color(0.0, 0.0, 0.0, 0.55)
const BAR_SIZE := Vector2(220, 30)
const FONT_SIZE := 20
const OUTLINE := 4

var _color: Color
var _text := ""

## Adds the bar of the next enemy, full. BattleScene places it every frame (it follows the

func add_enemy_bar() -> void:

	back.size = ENEMY_BAR_SIZE
	back.mouse_filter = Control.MOUSE_FILTER_IGNORE

	fill.size = ENEMY_BAR_SIZE - Vector2(2, 2)

## Centers enemy i's bar on a screen point.
func place_enemy_bar(i: int, screen: Vector2) -> void:
	var back: ColorRect = _enemy_bars[i][0]

## Version 5 field: no portal ({}), or its village and zone are ZoneData ids and its spot
## two numbers.
static func _valid_portal(data: Dictionary) -> bool:
	var portal: Variant = data.get("portal")
	if not portal is Dictionary:
		return false
	if (portal as Dictionary).is_empty():
		return true
	for key in ["town", "zone"]:
		var zone_id: Variant = portal.get(key)
		if not (zone_id is String and zone_id in ZoneData.IDS):
			return false
	var pos: Variant = portal.get("pos")
	return pos is Array and pos.size() == 2 and pos[0] is float and pos[1] is float
```

## it with its sign. Nothing to bump into.
func _build_portal(pos: Vector3, full: bool) -> Node3D:
	var root := Node3D.new()
	root.position = pos
	add_child(root)
	var material := StandardMaterial3D.new()
	material.shading_mode = BaseMaterial3D.SHADING_MODE_UNSHADED
	material.transparency = BaseMaterial3D.TRANSPARENCY_ALPHA
	material.albedo_color = PORTAL_COLOR
	var ring := TorusMesh.new()
	ring.inner_radius = 0.9
	ring.outer_radius = 1.05
	ring.rings = 24
	ring.ring_segments = 6
	var base := MeshInstance3D.new()
	base.mesh = ring
	base.material_override = material
	base.cast_shadow = GeometryInstance3D.SHADOW_CASTING_SETTING_OFF
	base.position.y = 0.05
	root.add_child(base)
	if not full:
		return root
	var oval := MeshInstance3D.new()
	oval.mesh = BattleStage.unit_sphere()
	oval.material_override = material
	oval.cast_shadow = GeometryInstance3D.SHADOW_CASTING_SETTING_OFF
	oval.position.y = PORTAL_SIZE.y
	oval.scale = PORTAL_SIZE
	root.add_child(oval)
	var label := Label3D.new()

	label.font_size = 48
	label.pixel_size = 0.008
	label.outline_size = 10
	label.billboard = BaseMaterial3D.BILLBOARD_ENABLED
	label.position.y = PORTAL_SIZE.y * 2.0 + 0.4

	var pulse := root.create_tween().set_loops()
	pulse.tween_property(oval, "scale", PORTAL_SIZE * PORTAL_PULSE, 0.6) \

```gdscript
class_name ExploredMap extends RefCounted
## What the hero has seen of one zone, as a coarse grid of CELL-metre cells (on a dungeon
## floor, its own cells). GameState keeps one per zone and SaveData saves them. reveal() is
## called every physics tick and only does work when the hero enters another cell. Pure:
## never touches nodes.

const CELL := ZoneData.CELL
## How far the hero sees, in metres: about what the camera shows around them on an open
## map; on a dungeon floor only the nearby cells, so its corridors unfold.
const REVEAL_FIELD := 9.0
const REVEAL_DUNGEON := 6.0
## Colors of the seen cells on the map square.
const FIELD_COLOR := Color(0.3, 0.55, 0.26)
const PATH_COLOR := Color(0.78, 0.68, 0.48)
const ROCK_COLOR := Color(0.16, 0.15, 0.17)
const FLOOR_COLOR := Color(0.62, 0.6, 0.58)
const STAIRS_COLOR := Color(1.0, 0.8, 0.25)
const DOOR_COLOR := Color(0.55, 0.32, 0.16)

var zone: ZoneData
var size: Vector2i
## One byte per cell, row by row: 1 once seen.
var cells: PackedByteArray

var _last_cell := Vector2i(-1, -1)


## saved: the cells of an earlier visit (ignored if they don't fit this zone's grid).
func _init(p_zone: ZoneData, saved := PackedByteArray()) -> void:
	zone = p_zone
	if zone.is_dungeon():
		size = zone.grid_size()
	else:
		size = Vector2i(ceili(zone.half_size.x * 2.0 / CELL), ceili(zone.half_size.y * 2.0 / CELL))
	if saved.size() == size.x * size.y:
		cells = saved
	else:
		cells = PackedByteArray()
		cells.resize(size.x * size.y)


func is_seen(cell: Vector2i) -> bool:
	return cells[cell.y * size.x + cell.x] != 0


func any_seen() -> bool:
	return cells.has(1)


## pos in grid units (cell (2, 3) spans 2..3 and 3..4), for the hero's marker.
func grid_point(pos: Vector3) -> Vector2:
	if zone.is_dungeon():
		return Vector2(pos.x / CELL + size.x / 2.0, pos.z / CELL + size.y / 2.0)
	return Vector2((pos.x + zone.half_size.x) / CELL, (pos.z + zone.half_size.y) / CELL)


## Marks what the hero sees from pos. Returns the cells seen for the first time; empty, at
## once, while the hero stays in the same cell.
func reveal(pos: Vector3) -> Array[Vector2i]:
	var fresh: Array[Vector2i] = []
	var point := grid_point(pos)
	var here := Vector2i(floori(point.x), floori(point.y))
	if here == _last_cell:
		return fresh
	_last_cell = here
	var radius := (REVEAL_DUNGEON if zone.is_dungeon() else REVEAL_FIELD) / CELL
	var reach := ceili(radius)
	for y in range(maxi(here.y - reach, 0), mini(here.y + reach + 1, size.y)):
		for x in range(maxi(here.x - reach, 0), mini(here.x + reach + 1, size.x)):
			var center := Vector2(x + 0.5, y + 0.5)
			var i := y * size.x + x
			if cells[i] == 0 and center.distance_to(point) <= radius:
				cells[i] = 1
				fresh.append(Vector2i(x, y))
	return fresh


## The color of a cell once seen.
func color_of(cell: Vector2i) -> Color:
	if not zone.is_dungeon():
		var pos := Vector3((cell.x + 0.5) * CELL - zone.half_size.x, 0.0,
			(cell.y + 0.5) * CELL - zone.half_size.y)
		return PATH_COLOR if WorldStage.is_on_path(zone, pos) else FIELD_COLOR
	match zone.cell_char(cell):
		ZoneData.ROCK:
			return ROCK_COLOR
		ZoneData.STAIRS_UP, ZoneData.STAIRS_DOWN:
			return STAIRS_COLOR
		ZoneData.DOOR:
			return DOOR_COLOR
	return FLOOR_COLOR
```

```gdscript
class_name MapSquare extends PanelContainer
## The small translucent square under the map's status window: what the hero has seen of
## this zone (ExploredMap) and a marker on the hero. follow() runs every physics tick but
## the image only changes, cell by cell, when new cells are seen, so it costs next to
## nothing on the web build. It takes no clicks: the ground under it can still be tapped.

const SIDE := 150.0
const BACK := Color(0.04, 0.04, 0.12, 0.45)
const BORDER := Color(1.0, 1.0, 1.0, 0.7)
const ALPHA := 0.8
const MARKER_SIZE := 7.0
const MARKER_COLOR := Color.WHITE

var _map: ExploredMap
var _image: Image
var _texture: ImageTexture
var _picture: TextureRect
var _marker: ColorRect
## Pixels per cell, and where the grid starts inside the square.
var _scale := 1.0
var _origin := Vector2.ZERO


func _ready() -> void:
	var style := StyleBoxFlat.new()
	style.bg_color = BACK
	style.border_color = BORDER
	style.set_border_width_all(2)
	style.set_corner_radius_all(4)
	add_theme_stylebox_override("panel", style)
	custom_minimum_size = Vector2(SIDE, SIDE)
	size_flags_horizontal = Control.SIZE_SHRINK_BEGIN
	mouse_filter = Control.MOUSE_FILTER_IGNORE
	var inside := Control.new()
	inside.mouse_filter = Control.MOUSE_FILTER_IGNORE
	add_child(inside)
	_picture = TextureRect.new()
	_picture.expand_mode = TextureRect.EXPAND_IGNORE_SIZE
	_picture.texture_filter = CanvasItem.TEXTURE_FILTER_NEAREST
	_picture.modulate.a = ALPHA
	_picture.mouse_filter = Control.MOUSE_FILTER_IGNORE
	inside.add_child(_picture)
	_marker = ColorRect.new()
	_marker.color = MARKER_COLOR
	_marker.size = Vector2.ONE * MARKER_SIZE
	_marker.mouse_filter = Control.MOUSE_FILTER_IGNORE
	inside.add_child(_marker)


## Shows map: paints every cell already seen, once.
func set_map(map: ExploredMap) -> void:
	_map = map
	_image = Image.create(map.size.x, map.size.y, false, Image.FORMAT_RGBA8)
	for y in map.size.y:
		for x in map.size.x:
			if map.is_seen(Vector2i(x, y)):
				_image.set_pixel(x, y, map.color_of(Vector2i(x, y)))
	_texture = ImageTexture.create_from_image(_image)
	_picture.texture = _texture
	_scale = floorf(SIDE / maxi(map.size.x, map.size.y))
	var drawn := Vector2(map.size) * _scale
	_origin = ((Vector2.ONE * SIDE - drawn) / 2.0).floor()
	_picture.position = _origin
	_picture.size = drawn


## The hero at pos: reveals what they see from there and moves the marker.
func follow(pos: Vector3) -> void:
	var fresh := _map.reveal(pos)
	if not fresh.is_empty():
		for cell in fresh:
			_image.set_pixelv(cell, _map.color_of(cell))
		_texture.update(_image)
	var at := (_origin + _map.grid_point(pos) * _scale - Vector2.ONE * MARKER_SIZE / 2.0).floor()
	if at != _marker.position:
		_marker.position = at
```
