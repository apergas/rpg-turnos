# Adapting the game to phones Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use boost:subagent-driven-development (recommended) or boost:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The web build can be played from start to finish in a phone's browser, in landscape, with no keyboard.

**Architecture:** `Device` says whether this is a phone. `DisplaySettings` scales the 2D layer, the 3D resolution and the frame rate from it, and a global theme makes the buttons taller. On the map a `TouchPad` turns touches into a tap, a floating stick and a pinch. The desktop never takes any of these paths.

**Tech Stack:** Godot 4.7.2, GDScript, Compatibility renderer, Web export (single-threaded).

**Spec:** `docs/boost/specs/2026-11-06-moviles-design.md`. Where the plan and the code differ, the code wins: this plan gives the new classes in full and describes the edits to existing files, so read each file first.

- [ ] **Step 1: `Device`**

```gdscript
class_name Device extends RefCounted
## Whether the game runs on a phone or tablet. Only the web build gets there; `--touch` fakes
## it on the desktop, with the mouse acting as a finger, to check the layout. A laptop with a
## touch screen is not one: it keeps the desktop interface. iPads say they are Macs, but Macs
## have no touch screen.

static func is_touch() -> bool:
	if OS.get_cmdline_user_args().has("--touch"):
		return true
	if OS.has_feature("web_android") or OS.has_feature("web_ios"):
		return true
	return OS.has_feature("web_macos") and DisplayServer.is_touchscreen_available()


static func is_ios() -> bool:
	return OS.has_feature("web_ios") or OS.has_feature("web_macos")
```

### Task 2: Touch controls on the map

**Files:**
- Create: `scripts/world/touch_pad.gd`
- Modify: `scripts/world/world.gd`, `scripts/world/player.gd`, `scripts/world/follow_camera.gd`

**Interfaces:**
- Consumes: `Device.is_touch()`.
- Produces: `TouchPad` with `tapped(screen: Vector2)`, `pinched(ratio: float)`, `direction: Vector2`, `handle(event: InputEvent) -> bool`, `reset()`; `Player.stick_direction: Vector2`; `FollowCamera.zoom_by(ratio: float)`.

- [ ] **Step 1: `TouchPad`**

```gdscript
class_name TouchPad extends Control
## Turns fingers on the map into what the hero does. A short touch is a tap. A touch that
## slides past DEAD_ZONE becomes a stick that floats where the finger came down. A second
## finger cancels both and pinches. Draws the stick. Fed by World; touches on a window or
## button never get here.

signal tapped(screen: Vector2)
## The fingers' distance now over before: above 1 they are spreading.
signal pinched(ratio: float)

const DEAD_ZONE := 24.0
const RADIUS := 90.0
const RING_COLOR := Color(1, 1, 1, 0.35)
const KNOB_COLOR := Color(1, 1, 1, 0.6)
const KNOB_RADIUS := 34.0

## Where the stick points, screen axes, length 0..1.
var direction := Vector2.ZERO

var _touches := {}
var _origin := Vector2.ZERO
var _finger := Vector2.ZERO
var _sliding := false
## The first finger's touch can still become a tap.
var _can_tap := false
var _pinch_length := 0.0


func _ready() -> void:
	set_anchors_preset(Control.PRESET_FULL_RECT)
	mouse_filter = Control.MOUSE_FILTER_IGNORE


## Returns true when event was a touch this pad used.
func handle(event: InputEvent) -> bool:
	var touch := event as InputEventScreenTouch
	if touch != null:
		_on_touch(touch)
		return true
	var drag := event as InputEventScreenDrag
	if drag != null and _touches.has(drag.index):
		_on_drag(drag)
		return true
	return false


## Forgets every finger: a battle or a window took over.
func reset() -> void:
	_touches.clear()
	direction = Vector2.ZERO
	_sliding = false
	_can_tap = false
	_pinch_length = 0.0
	queue_redraw()


func _on_touch(touch: InputEventScreenTouch) -> void:
	if touch.pressed:
		_touches[touch.index] = touch.position
		if _touches.size() == 1:
			_origin = touch.position
			_finger = touch.position
			_can_tap = true
		else:
			direction = Vector2.ZERO
			_sliding = false
			_can_tap = false
			_pinch_length = _touch_spread()
		queue_redraw()
		return
	_touches.erase(touch.index)
	if _touches.is_empty():
		var tap := _can_tap
		reset()
		if tap:
			tapped.emit(touch.position)
	else:
		_pinch_length = 0.0


func _on_drag(drag: InputEventScreenDrag) -> void:
	_touches[drag.index] = drag.position
	if _touches.size() >= 2:
		var spread := _touch_spread()
		if _pinch_length > 0.0 and spread > 0.0:
			pinched.emit(spread / _pinch_length)
		_pinch_length = spread
		return
	if not _can_tap and not _sliding:
		return  # what is left of a pinch: no stick until every finger lifts
	_finger = drag.position
	var offset := _finger - _origin
	if not _sliding and offset.length() < DEAD_ZONE:
		return
	_sliding = true
	_can_tap = false
	direction = offset.limit_length(RADIUS) / RADIUS
	queue_redraw()


func _touch_spread() -> float:
	var points: Array = _touches.values()
	return (points[0] as Vector2).distance_to(points[1]) if points.size() >= 2 else 0.0


func _draw() -> void:
	if not _sliding:
		return
	draw_arc(_origin, RADIUS, 0.0, TAU, 48, RING_COLOR, 4.0, true)
	draw_circle(_origin + direction * RADIUS, KNOB_RADIUS, KNOB_COLOR)
```

- [ ] **Step 2: `Player` and `FollowCamera`**

`Player`: add `var stick_direction := Vector2.ZERO`. In `_wanted_direction()`, after reading the keys: if `keys == Vector2.ZERO`, use `stick_direction` as `keys`. So the stick cancels `move_target` as a key does. The speed stays the player's, as with the keys; the stick's length only counts for the dead zone.

`FollowCamera`: add

```gdscript
## Two fingers: spreading them brings the camera closer.
func zoom_by(ratio: float) -> void:
	if ratio > 0.0:
		_zoom_goal = clampf(_zoom_goal / ratio, MIN_DISTANCE, MAX_DISTANCE)
```

- [ ] **Step 3: `World`**

- In the UI build, when `Device.is_touch()`, add a `TouchPad` to `_ui` **behind** the status column and the prompt (first child, or moved to index 0), connect `tapped` to a method that does what a click does today (`_pointer_on_ground`'s projection, then `_use_on_arrival = _tapped_use(point)` and `_player.move_to(point)`), and `pinched` to `_camera.zoom_by`.
- In `_unhandled_input`, when the pad exists: after the `_waiting or _talking` check and the accept check, `if _pad.handle(event): get_viewport().set_input_as_handled(); return`, then ignore any `InputEventMouse` event (those are the touches again, emulated). Without a pad the code stays as it is. Split the screen-to-ground projection out of `_pointer_on_ground` so both paths share it.
- Each physics frame, `_player.stick_direction = _pad.direction` when the pad exists.
- `_pad.reset()` wherever the map gets frozen or leaves: `set_active()`, `freeze()`, `begin_cutscene()`, and when `_waiting` or `_talking` turn on. Otherwise the hero could keep walking under a dialogue. The player must also not walk from the stick while frozen: check `input_enabled` and `scripted` cover `_wanted_direction()`.
- Pinch zoom must not run in a cutscene: the mouse wheel's `_zoom_goal` rules apply, so `zoom_by` needs no more than the wheel has.

- [ ] **Step 4: The use button**

On a phone `_prompt` stays hidden and a `Button` `_use_button` shows instead: anchored bottom-right, `UI_EDGE` from the edges, `focus_mode` none, font 28, at least 180 × 72. Its text is the verb of `PROMPTS[near.kind]`, the part after `": "`, with a capital (`"Hablar"`, `"Abrir"`). Pressed: `_use(_nearest_use(_player.global_position))`. It follows every place `_prompt` shows or hides (lines using `_prompt.visible` and `_prompt.hide()`); a small `_show_prompt(near)` / `_hide_prompt()` pair keeps that in one place. It must not show while frozen, in a dialogue or in a cutscene, just as `_prompt` doesn't. Don't let a press also start a stick: the button consumes it, which you check in Step 5.
