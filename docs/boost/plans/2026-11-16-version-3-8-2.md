# Version 3.8.2: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use boost:subagent-driven-development (recommended) or boost:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The fixes of the spec `docs/boost/specs/2026-11-16-version-3-8-2-design.md` (two QA passes over 3.8.0):

- M-111: a warning before the boss of a land that closes, when something of it is still missing; an Ala de viaje's portal into that land closes with it.
- M-112: the caravan's quests get their `gone` flags, and a taken quest that can no longer be finished is «perdida», kept out of the mission lines.
- M-113: the v3's last question ignores Esc and a tap outside.
- M-114: saves of versions 2 to 8 load again.
- M-115: the slots say «Partida de una versión más nueva» and ask before replacing any slot that holds a file.
- M-116: safer saving: a temporary file renamed over the slot, and a hand-edited file's numbers capped.
- M-117: Estado scrolls with large text.
- M-118: Salir focuses «No».
- M-119: the key items, with their texts, in the Diario.
- M-120: text fixes.

Then the 3.8.2 release. The save stays at version 16.

**Architecture:** One new pure rule, `ClosingLands` (`scripts/game/closing_lands.gd`). It works out from the zones' data which lands close behind which boss: a village exit whose `gone` is a boss, plus every zone reached from it. It also says what such a land still hides and words the warning. `QuestLog.is_lost()` (worked out, not saved) uses it, and so do `BattleFlow` (the question, through `World.ask()`, before the boss battle), `GameState.on_boss_defeated()` (the portal) and `SaveData.apply()` (an old save's portal).

One new UI node, `StatusPage` (`scripts/ui/status_page.gd`). It is the Estado page's content, moved out of `PauseMenu` and put in a `ScrollBox` like the Diario. That fixes the overflow and takes about 48 lines out of `pause_menu.gd`, so the menu's other changes fit in its budget.

`ChoiceWindow.ask()` and `World.ask()` gain a `cancel := true` parameter. `World.ask()` changes no line count. The rest are edits in place: `SaveData`, `SaveStore`, `SlotList`, `QuestLog`, `Quest`, `JournalPage`, `KeyMap`, `CaravanFlow`, `CreditsData`, `StoryFlow` and 20 quest `.tres`.

**Tech Stack:** Godot 4.7.2 (Compatibility), GDScript, `.tres` resources, scenes as text, Git Bash, `scripts/tools/autoplay_all.sh`.

## Adaptations to the spec

1. **The key items go to the Diario, not Objetos.** The brief this plan was asked from said "Objetos". But the QA brief (`docs/brief-qa-agentes.md` §3.5 and T-067) says Objetos shows only what can be used. Commit e55355d took the key items out of Objetos on purpose. `_fill_items()` says "the Diario follows them". The spec's decision table records this.
2. **`ClosingLands` keeps a static cache** (`_lands`) of what it found in the zones' data, built on first use. It is a pure rule: the cache is a memo of constant data, never game state, like a constructor's cache.
3. **The warning lives in `BattleFlow`**, the piece that starts every battle, before `battle_started`. «Volver» calls `World.set_active(true)`, which already clears the encounter's wait, gives the input back and calms the groups for `MonsterGroups.CALM_MS`. `World` gains no function: `world.gd` may not grow. The boss waits, unarmed, until the hero has walked `BOSS_REARM_RADIUS` away, as after any boss battle.
4. **On autoplay the question is asked.** `World.ask()` prints `Pregunta: ... -> Luchar ahora` and returns 0, so `ANSWERS` keeps «Luchar ahora» first and «Volver» last (Esc, tap and focus). The logs then show what each run left behind.
5. **The portal** (found while checking QA1-03, not in the QA reports). An Ala portal opened in a land before its boss stays open after the land closes. In the city's case, in the part 3, the Caravana's portal leads to `ciudad_2`; `ZoneTravel.on_portal()` autosaves there and the slot is «Partida dañada» from then on (`_valid_caravan()`).
   - The fix closes it in `GameState.on_boss_defeated()`.
   - `SaveData.apply()` drops such a portal from an older save, and one into another part's zones (QA2-13's hand-edited case), instead of rejecting the save.
6. **Lost quests are worked out, not stored.** `QuestLog.is_lost(id, flags, inventory)`: taken, and of an earlier part, or gone with a closed land (`ClosingLands`) while not ready to hand in. `talk()` stops a lost quest's waiting lines. A lost quest that somehow becomes ready (a v1 one delivered in the part 3's Villaclaro) is still paid by `talk()`: nothing is taken away.
7. **QA2-13's numbers** go through one helper, `SaveData.whole()` (`clampf` to `[0, MAX_NUMBER]` before `int()`, since `int(1e30)` is negative). `QuestLog.set_from()` uses it too. The play time is capped at `MAX_NUMBER` seconds. The bad base64 is rejected in `_valid_explored()`. The newline in a name is left, as the spec says.
8. **Estado's content becomes `StatusPage`** (an `HBoxContainer`, built like `JournalPage`), so `pause_menu.gd` loses `_fill_status()`, eight vars and most of `_build_status()`. The width constants stay in `PauseMenu` (`STATUS_BAR_WIDTH` is also the Hechizos page's) and `StatusPage` reads them.
9. **The village quest's prefix.** `Quest.GOAL_PREFIX := "Objetivo: "`; `QuestLog.journal()` trims it instead of `STATUS_PREFIX`. `StoryState.GOALS[PROLOGUE]` and `[MEADOW]` stay: `goal_text()` indexes `GOALS` by chapter, and the debug panel can put a game in any chapter.
10. **The temporary file.** `SaveStore.TEMP_SUFFIX := ".tmp"`, off the web only. `DirAccess.rename_absolute()` over an existing file may remove the target first (on Windows). So `SaveStore.recover_writes()`, called first in `TitleScreen._ready()` (before the options load), turns a lone `.tmp` back into its file. It is never called on autoplay, which never touches the slots.
11. **Newer saves.** `SaveData.is_newer(data)` (also used by `from_json()`). `SaveStore.slot_info()` adds `"newer": bool` to a damaged slot's info. `SlotList` shows `NEWER_TEXT` for it.
12. **`autoplay_expected.json`** only changes if a full run leaves its margin (Task 8). Nothing here touches the balance. The v2's `misiones de la caravana n/8` may drop by quests the autoplay used to take after their land closed; the JSON does not check that number.

```gdscript
## crash mid-write leaves the old file whole. On the web user:// is IndexedDB, stored when a file
## closes and not on a rename: there the file is written in place, as before 3.8.2.
static func _write(path: String, data: Dictionary) -> bool:
	var target := path if OS.has_feature("web") else path + TEMP_SUFFIX
	var file := FileAccess.open(target, FileAccess.WRITE)
	if file == null:
		push_warning("No se pudo guardar %s (error %d)" % [path, FileAccess.get_open_error()])
		return false

	if not ok or target == path:
		return ok
	var error := DirAccess.rename_absolute(target, path)
	if error != OK:
		push_warning("No se pudo guardar %s (error %d)" % [path, error])
```

```gdscript
class_name ClosingLands extends RefCounted
## The lands that close for good behind their boss. A village exit whose "gone" flag is a boss
## (an EnemyLibrary id) leads into one: that exit's zone and every zone reached from it by exits
## and stairs, never back through the village. From the zones' data: the v2's jungle, desert,
## mountain and city (the Caravana's exits) and the v3's Ciénaga, Cuevas and Ruinas
## (Brumaclara's). The v1 closes on leaving with the caravan, not behind a boss, and the Fuente
## never closes. QuestLog.is_lost() asks which lands are closed. Pure: reads ZoneData and the
## flags it is given, changes nothing.

## Boss id -> the zones of its land, found once from the zones' data (_all()): a memo of data
## that never changes, not game state.
static var _lands := {}


## The zones of the land that closes behind boss_id, [] if none does.
static func zones_of(boss_id: String) -> Array[String]:
	var zones: Array[String] = []
	zones.assign(_all().get(boss_id, []))
	return zones


## True if zone_id is in a land whose boss these flags say is beaten.
static func is_closed(zone_id: String, flags: Dictionary) -> bool:
	var lands := _all()
	for boss: String in lands:
		if flags.get(boss, false) and zone_id in lands[boss]:
			return true
	return false


static func _all() -> Dictionary:
	if _lands.is_empty():
		_lands = _find()
	return _lands


## Every village exit whose gone flag is a boss: boss id -> its land's zones.
static func _find() -> Dictionary:
	var lands := {}
	for hub_id in ZoneData.IDS:
		for exit: Dictionary in ZoneData.by_id(hub_id).exits:
			var boss: String = exit.get("gone", "")
			if EnemyLibrary.ENEMIES.has(boss):
				lands[boss] = _reach(exit.to, hub_id)
	return lands


## start and every zone its exits and stairs lead to, without going through hub_id.
static func _reach(start: String, hub_id: String) -> Array[String]:
	var zones: Array[String] = [start]
	var i := 0
	while i < zones.size():
		var zone := ZoneData.by_id(zones[i])
		i += 1
		if zone == null:
			continue
```
