# Version 3.8.0: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use boost:subagent-driven-development (recommended) or boost:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three changes from the spec `docs/boost/specs/2026-11-16-version-3-8-0-design.md`: the hero can reach level 60 in the v3, every enemy of the v3 gives 30 % more EXP (gold unchanged), and the `brumaclara` autoplay run ends between Nv 53 and 55 with 0 or 1 defeats (M-104); Brumaclara's people get a look of their own: the Niebla's skin, a hood, a glowing crystal pendant, Orvalla's lantern, the Curandera's bowl, the Herrero's crystal arms and the Tendero's own look (M-105); at level 60 a soft golden aura surrounds the hero on the map, in battle and in the cutscenes, lit with a short flash when he reaches 60 in a battle (M-107). The save stays at version 16.

**Architecture:** The level cap is a rule: `Leveling.MAX_LEVEL` 60 and ten more `EXP_TABLE` entries; `GameState.level_cap()`, `SaveData` and the debug panel already read `MAX_LEVEL`. Where the v3 ends is set by data: the `exp_reward` of the 25 v3-only enemies (`data/enemies/*.tres`), multiplied by 1.3 and rounded (tuned between 1.25 and 1.35; Adaptation 1). The EXP table is the spec's and is never tuned; the Fuente's `autoplay_boss_level` stays at 50 unless the tuning loop's last resort needs it. The new looks are data in `ActorLooksV3` (new keys `"hood"`, `"pendant"`, `"carry"`, `"crystal_arms"`; four new heads and `SKIN_MIST`); the pieces are built by a new constructor, `MistDress` (`scripts/battle/mist_dress.gd`), which `CharacterBuilder.build()` calls with one line, so `CharacterBuilder` stays under ~280 lines. The heads are written by `scripts/tools/head_textures.gd` with a new skin, `bruma`. One new `Look`, `MIST_SHOPKEEPER` (the Tendero), appended to the enum of `actor_looks.gd` on its last line: that file gains no line. The aura is a node piece, `HeroAura` (`scripts/battle/hero_aura.gd`, a `Node3D` with one job) with its own shader (`shaders/hero_aura.gdshader`: additive fresnel envelope, rising ripple, slow breath) and a `CPUParticles3D` of about 12 sparks; whether it shows is a pure rule, `Leveling.at_max(hero)`. Its owners hang it on the hero's `BattleActor`: `Player` on the map (`Player.set_aura()`, through `World.set_hero_aura()` from `Game._refresh_status()`; the cutscenes move that same figure, so it is there too) and `BattleScene` in battle (at the start, or after the `LEVEL_UP` event of level 60, with `flash()`). `battle_actor.gd` does not change.

**Tech Stack:** Godot 4.7.2 (Compatibility), GDScript, scenes as text, web PWA single-threaded.

**Assumes (3.7.0, planned in parallel, merged before this one):** `config/version="3.7.0"` in `project.godot`; the Incienso is gone, the pause menu has «Salir», «Buscar actualizaciones» and the version label. This plan touches none of 3.7.0's subjects (pause menu, `WebUpdate`, `Inventory`, `Shop`, `pages.yml`). Line numbers below are today's (3.6.2); **always search by the quoted text**: where 3.7.0 moved a line, the quoted text wins and the difference goes in the commit message.

## Adaptations to the spec

1. **More EXP in the v3 (the spec as updated on 2026-11-16).** Today `clamp_exp()` drops the EXP past the cap, and the autoplay stops hunting at each v3 zone's `autoplay_boss_level` (42, 45, 48, 50); with the cap alone the `brumaclara` run would end with about 47 900 EXP, Nv 51 (the 3.6.0 run's EXP lines add 23 775 to the Caravana's 24 100). So every **v3-only enemy** gives `exp_reward × 1.3`, rounded half up. "v3-only" means: in the `formations` of `cienaga`, `cuevas_1`, `cuevas_2`, `ruinas_1`, `ruinas_2` and `fuente`, or their `boss_id`, or called into battle by one of them (`slime_bruma_ayuda`, the Slime de bruma's call for help). These 25 are exactly `Bestiary.V3_ENEMIES` plus `slime_bruma_ayuda`; none of them stands in a v1 or v2 zone's formations (checked with `grep`). Gold (`gold_reward`) and drops do not change. No screen shows an enemy's EXP before the battle (the bestiary page shows none; the QA brief's enemy table is the v1's), so only the «Obtienes n EXP» line changes. **Caution for the tuning:** below 50 the hunt stops at each threshold, so more EXP mostly shortens the hunts; the levels past 50 come from the fights on the route past the thresholds and the Eco (3900 instead of 3000). Whether that reaches 53 is measured in Task 1 Step 6; the loop moves the multiplier within 1.25-1.35 and, only if 1.35 still ends below 53, raises the Fuente's `autoplay_boss_level` one level at a time (the coordinator's "unless the tuning loop needs it").
2. **`--autoplay-zone=albor`** keeps its 44 600 EXP (Lv 50): the Fuente's threshold stays 50, so it still goes straight to the Eco. Only if the loop's last resort raises the threshold to T does its `"experience"` become `Leveling.EXP_TABLE[T - 1]`.
3. **"Si el héroe llega demasiado fuerte al Eco de Albor no es un fallo, mientras el combate no dure menos de la mitad que hoy"**: "hoy" is measured in Task 1 Step 2 on the 3.7.0 code with the `albor` start (Lv 50), as hero turns in the Eco fight; the reference from 3.6.0 is 51 turns. The 3.8.0 fight must take at least half of the 3.7.0 count.
4. **"Cargar una partida de la 3.7.0 al Nv 50 en Brumaclara"**: Task 1 Step 2 writes a real 3.7.0 save at Nv 50 (the `albor` start with `--autoplay-save`), and Step 7 loads it with the 3.8.0 code in a scratch script, with its zone set to `brumaclara`. Its stored EXP is 44 600 (the old cap dropped the rest), so it rises from there: the changelog says so honestly.
5. **Heads.** The spec's four heads (`head_gris_bruma.png`, `head_rubio_bruma.png`, `head_pelirrojo_bruma.png`, `head_castano_bruma.png`). The skin `bruma` is made by desaturating the face cell (70 %) and then multiplying by a blue (`Color(0.84, 0.86, 1.04)`); the tool's skins become `[factor, desaturate, tint]` so the six heads of today come out byte for byte the same (checked with `git status`). The tool also prints each head's mean face colour: `SKIN_MIST`'s starting value comes from it (Task 2 Step 4), then close frames.
6. **The hood's colour** is the cape's for those who wear one (Orvalla night blue, the Curandera light blue, the Vecino / Pescador grey blue). The Vecina wears no cape: her hood gets its own muted plum (`NEIGHBOUR_HOOD`, from her pink smock). The Tendero's hood and cape are sage green (`SHOPKEEPER_CLOAK`), the "otro tono"; his smock is pale green. Each look sets its cape and hood from one constant (`ORVALLA_CLOAK`...), so they cannot drift.
7. **The Herrero keeps his beard** (the spec's table: «Capucha: No»), and his skin is the mist one on the face; his arms are crystal from shoulder to hand: the Knight's arm meshes (`Knight_ArmLeft` / `Knight_ArmRight`) are each one piece, which is what the spec's "el material de `Knight_ArmLeft` y `Knight_ArmRight` es el de cristal" means.
8. **Hand pieces.** The Knight's hand slots (`BattleActor.HAND_R` / `HAND_L`, already bone attachments of `handslot.r` / `handslot.l`) carry the lantern and the bowl. Each is built inside a pivot node whose position and turn (`LANTERN_POS` / `LANTERN_ROT`, `BOWL_POS` / `BOWL_ROT`) are tuned in close frames of the idle pose, like `HAIR_PIECES` was.
9. **The pendant hangs from the `chest` bone** through `CharacterBuilder._hang_on_bone()`, which becomes public (`hang_on_bone()`) and returns its mesh, so `MistDress` does not copy it.
10. **Glow without light.** A glowing piece is an `add_mesh()` / `add_blob()` mesh whose own material gets `emission` (so it still fades with the figure, as every builder mesh); the crystal arms take `Crystals.material(0)`. No `OmniLight3D` anywhere.
11. **The aura's envelope** is a `CapsuleMesh` round the figure (`RADIUS` 0.55 m, `HEIGHT_SHARE` 1.1 of the figure's `top_height()`), drawn with `cull_back` so only its front shell shows: by the fresnel term its middle, in front of the face and the gear, is almost nothing, its edges and its lower part glow. The ripple is value noise of the angle round the hero and the height minus the time (it rises); the breath is a sine of period `breath_s` 2 s. The shader computes the height in `vertex()` from the capsule's own `VERTEX.y`, not from `UV`, so the "more alive below" does not depend on how `CapsuleMesh` lays its UVs.
12. **"Fewer on phones, following what `DisplaySettings` already lowers":** the sparks read `ZoneParticles.half` (a phone: 6 instead of 12) and `ZoneParticles.enabled` (low quality: none). The envelope stays in every case: it is the aura.
13. **The flash** comes after the level-up's two messages (the level and the gains), as "tras el aviso de subida de nivel"; the aura then stays to the end of the battle, and the map's `Player` lights it on the next `Game._refresh_status()` (the hero is back on the map). Loading a game at 60 lights it in that same refresh, with no flash.
14. **Seeing it at 60 with the real game.** The autoplay never reaches 60 (it ends at 53-55). So the map is checked with the real `Game` from a save at 60 (Task 5 makes one in the scratch `APPDATA` from Task 1's 3.7.0 save, by a scratch script that sets the hero to 60 with `Leveling.set_level()`), and the battle with the real `BattleScene` set up by a scratch script, the hero at 60 (aura from the start) or at 59 one EXP short of 60 (the flash), on autoplay. The debug panel's +1 is not needed: it would take ten clicks in a window nobody can click in a scripted run.

```gdscript
class_name MistDress extends RefCounted
## Constructor: what makes Brumaclara's people look like people of the Niebla (3.8.0), on the
## KayKit Knight that CharacterBuilder.build() has just made from their ActorLooksV3 entry: the
## hood (LOOKS "hood": its colour; a look asks for "hair" or "hood", never both) and the

const HEAD_SLOT := "Rig/Skeleton3D/head"
## The hood, in the head bone's space (the Knight faces +Z there, before the turn), like
## ActorLooks.HAIR_PIECES: a faceted dome over the head, set back so the face shows in front
## of it, and a flap over the nape a touch darker (NAPE_DARKEN). Tuned with close frames; its

	Vector2(0.56, 0.75), Vector2(0.36, 0.98), Vector2(0, 1.05)]

const HOOD_SCALE := Vector3(1.0, 1.0, 0.85)
const NAPE_PROFILE: Array[Vector2] = [Vector2(0, 0.0), Vector2(0.5, 0.12), Vector2(0.44, 0.7),
	Vector2(0, 1.0)]
const NAPE_POS := Vector3(0, 0.2, -0.5)
const NAPE_ROT := Vector3(180, 0, 0)
const NAPE_SCALE := Vector3(0.9, 0.5, 0.35)
const NAPE_DARKEN := 0.15
## The crystal pendant: a small double point of light blue crystal (Crystals.COLORS[0]) on the
## chest bone, placed in the rig's rest pose (the Knight faces +Z there), with a soft glow.
const PENDANT_PROFILE: Array[Vector2] = [Vector2(0, 0.0), Vector2(0.5, 0.45), Vector2(0, 1.0)]
const PENDANT_SIDES := 6
const PENDANT_BONE := "chest"
const PENDANT_AT := Vector3(0, 1.05, 0.5)
const PENDANT_SIZE := 0.16
const PENDANT_COLOR := Color(0.45, 0.72, 1.0)
const PENDANT_GLOW := 1.2


## Dresses actor's Knight model with what data (its LOOKS entry) asks for of the pieces above;
## a look that asks for none is left as it is.
static func dress(actor: BattleActor, model: Node3D, data: Dictionary) -> void:
	var bones := model.get_node(CharacterBuilder.SKELETON_PATH) as Skeleton3D
	if data.has("hood"):
		_add_hood(actor, model.get_node(HEAD_SLOT) as Node3D, data.hood)
	if data.get("pendant", false):
		_add_pendant(actor, bones)


## The dome and the nape flap, in the hood's colour (the cape's, ActorLooksV3's *_CLOAK).
static func _add_hood(actor: BattleActor, head: Node3D, color: Color) -> void:
	actor.add_blob(head, HOOD_PROFILE, ActorLooks.HAIR_SEGMENTS, color, HOOD_POS, Vector3.ZERO,
		HOOD_SCALE)
	actor.add_blob(head, NAPE_PROFILE, ActorLooks.HAIR_SEGMENTS, color.darkened(NAPE_DARKEN),
		NAPE_POS, NAPE_ROT, NAPE_SCALE)


static func _add_pendant(actor: BattleActor, bones: Skeleton3D) -> void:
	var stone := LowPoly.blob(PENDANT_PROFILE, PENDANT_SIDES)
	var at := Transform3D(Basis.from_scale(Vector3.ONE * PENDANT_SIZE), PENDANT_AT)
	_glow(CharacterBuilder.hang_on_bone(actor, bones, PENDANT_BONE, stone, PENDANT_COLOR, at),
		PENDANT_GLOW)


## Lights mi's own material (BattleActor.add_mesh()'s, so it still fades with the figure) in its
## colour, energy strong: it glows, it lights nothing.
static func _glow(mi: MeshInstance3D, energy: float) -> void:
	var mat := mi.material_override as StandardMaterial3D
	mat.emission_enabled = true
	mat.emission = mat.albedo_color
	mat.emission_energy_multiplier = energy
	mat.roughness = 0.3
```

`shaders/hero_aura.gdshader`:

```glsl
// The golden aura of the hero at the game's top level (HeroAura, 3.8.0): a see-through
// envelope added on top of the scene. Brighter at its edges (fresnel) and at the feet, almost
// nothing in its middle, so the face and the gear show through it; value noise that rises
// with the time ripples it like a slow flame, and a slow sine makes it breathe. Works in the
// Compatibility renderer (the web and the phones), like hero_rim.gdshader.
shader_type spatial;
render_mode unshaded, blend_add, depth_draw_never, cull_back, shadows_disabled, fog_disabled;

uniform vec3 aura_color : source_color = vec3(1.0, 0.85, 0.45);
// The whole glow (HeroAura.flash() raises it for a moment).
uniform float strength = 0.55;
uniform float rim_power = 2.2;
// The envelope's height in its own units (HeroAura: the capsule is centred on its origin).
uniform float height = 1.9;
// Seconds of one breath, and how fine and how fast the ripple rises.
uniform float breath_s = 2.0;
uniform float ripple = 5.0;
uniform float rise_speed = 0.7;

// 0 at the feet, 1 at the top; and a coordinate across the envelope with no seam.
varying float rel_height;
varying float across;

float hash(vec2 p) {
	return fract(sin(dot(p, vec2(127.1, 311.7))) * 43758.5453);
}

float value_noise(vec2 p) {
	vec2 i = floor(p);
	vec2 f = fract(p);
	f = f * f * (3.0 - 2.0 * f);
	return mix(mix(hash(i), hash(i + vec2(1.0, 0.0)), f.x),
		mix(hash(i + vec2(0.0, 1.0)), hash(i + vec2(1.0, 1.0)), f.x), f.y);
}

void vertex() {
	rel_height = clamp(VERTEX.y / height + 0.5, 0.0, 1.0);
	across = (VERTEX.x - VERTEX.z) * 3.0;
}

void fragment() {
	float facing = clamp(dot(NORMAL, VIEW), 0.0, 1.0);
	float rim = pow(1.0 - facing, rim_power);
	float feet = (1.0 - rel_height) * (1.0 - rel_height);
	float flame = value_noise(vec2(across, rel_height * ripple - TIME * rise_speed));
	float breath = 0.75 + 0.25 * sin(TIME * TAU / breath_s);
	float glow = (rim + feet * 0.4) * (0.5 + 0.7 * flame) * (1.0 - 0.5 * rel_height);
	ALBEDO = aura_color * glow * breath * strength;
}
```

```gdscript
class_name HeroAura extends Node3D
## Node: the golden aura of the hero at the game's top level (M-107, 3.8.0; Leveling.at_max()):
## a see-through envelope a little bigger than him (shaders/hero_aura.gdshader: additive, no
## shadow, its edges and its lower part glowing, rippling up like a slow flame and breathing
## every BREATH_S) and a few golden sparks that rise from his feet and fade at his head
## (CPUParticles3D: SPARKS at a time, PHONE_SPARKS on a phone and none on low quality, as
## ZoneParticles.half and .enabled say). Its owner builds it with build() and hangs it on the
## hero's BattleActor: Player on the map (the cutscenes move that same figure), BattleScene in
## battle. flash() is a short burst of light, when he reaches the top level in a battle. Only
## the hero wears it. It makes no light and keeps no game state.

const SHADER := preload("res://shaders/hero_aura.gdshader")
## Pale gold, the same on the map and in battle (a 3D colour: not a UiTokens value).
const COLOR := Color(1.0, 0.85, 0.45)
## The envelope: a capsule RADIUS wide round the figure, HEIGHT_SHARE of its top tall
## (BattleActor.top_height(), where the damage numbers and the sign go: a little over the head).
const RADIUS := 0.55
const HEIGHT_SHARE := 1.0
const SIDES := 12
const RINGS := 4
const STRENGTH := 0.55
const BREATH_S := 2.0
## The sparks: how many at a time, how long each lives, how big, how wide the ring at the feet
## they start from and how far up (share of the top) they fade.
const SPARKS := 12
const PHONE_SPARKS := 6
const SPARK_LIFETIME := 1.6
const SPARK_SIZE := 0.05
const SPARK_RING := 0.35
const SPARK_RISE := 0.85
## The flash: the glow FLASH_PEAK times stronger, back to STRENGTH in FLASH_S seconds.
const FLASH_PEAK := 4.0
const FLASH_S := 0.8

var _material: ShaderMaterial
var _sparks: CPUParticles3D = null


## Builds the envelope and the sparks round a figure top metres tall.
func build(top: float) -> void:
	var height := top * HEIGHT_SHARE
	var capsule := CapsuleMesh.new()
	capsule.radius = RADIUS
	capsule.height = height
	capsule.radial_segments = SIDES
	capsule.rings = RINGS
	_material = ShaderMaterial.new()
	_material.shader = SHADER
	_material.set_shader_parameter("aura_color", COLOR)
	_material.set_shader_parameter("strength", STRENGTH)
	_material.set_shader_parameter("height", height)
	_material.set_shader_parameter("breath_s", BREATH_S)
	var shell := MeshInstance3D.new()
	shell.mesh = capsule
	shell.material_override = _material
	shell.cast_shadow = GeometryInstance3D.SHADOW_CASTING_SETTING_OFF
	shell.position.y = height * 0.5
	add_child(shell)
	if ZoneParticles.enabled:
		_add_sparks(top, PHONE_SPARKS if ZoneParticles.half else SPARKS)


## A short burst of light, then the aura as always (BattleScene, after the level-up to the top
## level). The node must be in the tree.
func flash() -> void:
	create_tween().tween_method(_set_strength, STRENGTH * FLASH_PEAK, STRENGTH, FLASH_S)
	if _sparks != null:
		_sparks.restart()


func _set_strength(value: float) -> void:
	_material.set_shader_parameter("strength", value)


## count golden dots that rise from a ring at the feet and shrink to nothing by the head.
func _add_sparks(top: float, count: int) -> void:
	_sparks = CPUParticles3D.new()
	_sparks.amount = count
	_sparks.lifetime = SPARK_LIFETIME
	_sparks.local_coords = true
	_sparks.emission_shape = CPUParticles3D.EMISSION_SHAPE_RING
	_sparks.emission_ring_axis = Vector3.UP
	_sparks.emission_ring_radius = SPARK_RING
	_sparks.emission_ring_inner_radius = SPARK_RING * 0.5
	_sparks.emission_ring_height = 0.0
	_sparks.direction = Vector3.UP
	_sparks.spread = 8.0
	_sparks.gravity = Vector3.ZERO
	_sparks.initial_velocity_max = top * SPARK_RISE / SPARK_LIFETIME
	_sparks.initial_velocity_min = _sparks.initial_velocity_max * 0.8
	var fade := Curve.new()
	fade.add_point(Vector2(0, 1))
	fade.add_point(Vector2(1, 0))
	_sparks.scale_amount_curve = fade
	var dot := QuadMesh.new()
	dot.size = Vector2.ONE * SPARK_SIZE
	var mat := StandardMaterial3D.new()
	mat.shading_mode = BaseMaterial3D.SHADING_MODE_UNSHADED
	mat.blend_mode = BaseMaterial3D.BLEND_MODE_ADD
	mat.billboard_mode = BaseMaterial3D.BILLBOARD_ENABLED
	mat.albedo_color = COLOR
	dot.material = mat
	_sparks.mesh = dot
	_sparks.cast_shadow = GeometryInstance3D.SHADOW_CASTING_SETTING_OFF
	add_child(_sparks)
```
