# Version 3.6.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use boost:subagent-driven-development (recommended) or boost:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split the design system into a reusable core, `addons/design_system/` (tools, generic tokens, the theme's base `DsTheme`, `MenuCursor`, the hook and the generic docs), and Villaclaro's layer (its palette, fonts, own tokens, the values it gives the core's tokens, its components, voice and `UiTheme`), with the game looking exactly the same. Spec: [2026-11-15-version-3-6-1-design-system-nucleo-design.md](../specs/2026-11-15-version-3-6-1-design-system-nucleo-design.md) (M-98). Only the spec's step 1 (the in-repo split) is planned; step 2 (the core as a git submodule) stays described in the spec and in the core's README.

**Architecture:** The generator moves to `addons/design_system/tools/` and reads every path from `res://design_system.json`. It merges the core's `tokens/base.json` with the game's `tokens.json` (`"extends"` plus `"overrides"`, a clash is an error) into the same in-memory shape today's `tokens.json` has, so `UiTokens` and `tokens.css` come out with the same constants and values. `UiTheme`'s generic part becomes the static constructor `DsTheme` (only `UiTokens` and `MenuCursor`, no game class: `Device.is_touch()` becomes `DsTheme.touch`); `UiTheme extends DsTheme`, keeps its whole API and hands its own part to `DsTheme.build()` as a `Callable`. The hook moves to the core and asks the generator which paths to watch (`-- --files`).

**Tech Stack:** Godot 4.7.2 GDScript (tools run with `--headless --path . --script`), JSON, bash (the hook), GitHub Actions, Python 3 only for one throwaway helper outside the repo.

~~~markdown
El núcleo de un design system para juegos hechos con Godot 4: las herramientas que generan los tokens y comprueban la interfaz, los tokens genéricos, la base del tema (`DsTheme`), el cursor de los menús (`MenuCursor`), el hook de git y las guías que valen para cualquier juego. ## El tokens.json del juego

```json
{
 "name": "Mi juego",
 "extends": "res://addons/design_system/tokens/base.json",
 "overrides": [
  {"name": "text-accent", "value": "{oro-300}", "usage": "Títulos y quien habla, en el dorado del juego."}
 ],
 "color": {
  "themes": [
   {"id": "normal", "name": "Normal", "role": "normal"},
   {"id": "alto-contraste", "name": "Alto contraste", "role": "contrast"}
  ],
  "tokens": [
   {"name": "oro-300", "value": "#ffd94d", "usage": "Dorado de acento."}
  ]
 },
 "type": {
  "fonts": [
   {"family": "Mi letra", "godot_path": "res://assets/fonts/MiLetra.ttf", "role": "ui"}
  ],
  "families": {"ui": "\"Mi letra\", system-ui, sans-serif"}
 }
}
```

- **`"overrides"`** da valor, por nombre, a un token del núcleo. Cada campo que lleva, salvo `name`, sustituye al del núcleo.
- **Pisar sin querer es un error:** un token del juego con el nombre de uno del núcleo, fuera de `"overrides"`, hace fallar el generador y dice cuál. Lo mismo un override de un token que el núcleo no tiene.
- **Los temas:** el juego pone los ids. El de `role` `normal` y el de `role` `contrast` dan nombre a los dos diccionarios de `UiTokens` (`alto-contraste` → `ALTO_CONTRASTE`) y al selector `[data-theme="…"]` de `tokens.css`. Un color de dos temas lleva un valor por id.
- **`{nombre}`** apunta a otro color de cualquiera de las dos capas.
- **Las fuentes:** cada una lleva el `role` de una familia del núcleo (`display` o `ui`). Una familia sin fuente usa la letra del motor. `type.families` da la pila CSS de cada familia del núcleo; una familia que el núcleo no tiene es un error.
- Las demás secciones (`spacing`, `radius`, `border`, `outline`, `shadow`, `size`, `opacity`, `layer`) se suman a las del núcleo; `type.groups` añade estilos.

## Como submódulo de git

Hoy el núcleo vive dentro del repositorio del primer juego. Cuando haya un segundo:

1. Se crea su repositorio con `git subtree split --prefix=addons/design_system`, que conserva el historial.
2. En cada juego, la carpeta pasa a ser `git submodule add <url> addons/design_system`.
3. Los flujos de publicación ponen `submodules: true` en su `actions/checkout`; se clona con `--recurse-submodules`.
4. El `.githooks/pre-commit` del juego sigue llamando al hook del submódulo.
5. Un juego nuevo añade el submódulo, copia las dos plantillas de arriba, pone su paleta y sus fuentes y genera.

Un cambio del núcleo son entonces dos commits: uno en su repositorio y otro en el juego, para apuntar a la nueva versión.
~~~

~~~markdown
# Interacción

## Selección y foco

- La fila elegida lleva siempre fondo `surface-selected` y el cursor ▶ en `border-focus`, igual con teclado, ratón o dedo.

| Desactivado | `text-disabled` + motivo en `caption` |

- Mover el cursor suena, salvo cuando el código mueve el foco por su cuenta.
~~~

~~~markdown
# Accesibilidad

## Contraste

Todo texto llega al menos a 4,5:1 sobre su fondo en el tema normal y a 7:1 en el de alto contraste (4,5:1 para el texto sobre barras, que es grande y grueso). - Ventanas opacas.
- Texto secundario y desactivado más claros.
- Separadores visibles.
~~~

~~~markdown
# Implementación en Godot

Un solo camino lleva un valor de la interfaz hasta la pantalla:

```
base.json + tokens.json  →  gen_ui_tokens.gd  →  UiTokens  →  DsTheme + el tema del juego  →  pantallas
(núcleo)    (juego)          (generador)          (generado)   (el Theme)                      (variaciones y UiTokens.color())
                                   ↓
                              tokens.css  →  bundle.css del núcleo y del juego
                              (generado)     (las fichas)
```

## Las piezas

| Pieza | Dónde | Qué es |
| --- | --- | --- |
| `base.json` | `addons/design_system/tokens/` | Los tokens genéricos, con valores neutros. |
| `tokens.json` | el juego (`tokens` en `design_system.json`) | Lo del juego: `"extends"` el `base.json`, su paleta, sus fuentes, sus tokens y, en `"overrides"`, el valor que da a los del núcleo. |
| `design_system.json` | la raíz del juego | Todas las rutas que leen las herramientas y el hook. |
| Generador | `addons/design_system/tools/gen_ui_tokens.gd` | Junta las dos capas y escribe enteros `UiTokens` y `tokens.css`. No usa clases del juego. |
| `UiTokens` | el juego (`gd_out`) | **Generado: no se edita a mano.** Siempre `class_name UiTokens`: el núcleo lo usa. Los colores de los dos temas en dos diccionarios con el id de cada tema en mayúsculas (`UiTokens.color(&"text-accent")`; con `UiTokens.high_contrast`, el de alto contraste), las escalas como constantes (`SPACE_4`, `RADIUS_M`, `BORDER_3`, `OUTLINE_M`, `TOUCH_TARGET`, `TYPE_BODY_SIZE`…), `TYPE`, `FAMILY_DISPLAY` y `FAMILY_UI`, `FONT_DISPLAY_PATH` y `FONT_UI_PATH` (vacías si el juego no da letra) y la sombra de ventana. |
| `tokens.css` | el juego (`css_out`) | **Generado.** Las variables CSS (`--text-accent`, `--space-4`…) de los `bundle.css`: los colores del tema normal en `:root` y, en `[data-theme="…"]`, los que cambian en alto contraste. |
| `DsTheme` | `addons/design_system/runtime/ds_theme.gd` | La base del `Theme`, construida desde `UiTokens`. |
| `MenuCursor` | `addons/design_system/runtime/menu_cursor.gd` | El cursor ▶ de cada ventana con filas. |
| El tema del juego | el juego | Hereda de `DsTheme` y añade lo suyo. |

## DsTheme

Un constructor estático (`## Constructor:`). Solo depende de `UiTokens` y `MenuCursor`.

- `apply(window, high_contrast, extend)`: pone el tema sobre el tema por defecto (un `Control` bajo un `CanvasLayer` solo recibe ese, por eso hace `merge_with` sobre `ThemeDB.get_default_theme()`), con la letra `ui` en `body` para todos los tipos. Lo rehace en vivo si cambia el alto contraste. `ensure(window, extend)` lo pone una vez, para escenas que corren solas. `build(extend)` devuelve el `Theme`. `extend` es un `Callable` que recibe el `Theme` y le añade lo del juego.
- `DsTheme.touch`: `true` en un móvil o una tableta. Lo pone el juego antes de `apply()` o `ensure()`. Con él, las filas miden `touch-target` × `touch-min-width` y el cursor se acerca al borde.
- **Variaciones de `Label`**: `TITLE`, `SECTION`, `SMALL`, `CAPTION`, `NOTE`, `REASON`, `MONEY`, `POSITIVE`, `NEGATIVE`, `BADGE`, `MICRO`, `OUTLINED`. Se usan con `label.theme_type_variation = DsTheme.CAPTION` (o por el nombre del tema del juego, que las hereda).
- **Variaciones de ventana y botón**: `CARD`, `SELECTED_ROW`, `SELECTOR`, `KEY`, `CARD_HIT`, `MENU_BUTTON`, `TITLE_ROW`, `ACTION_BUTTON`, `STATUS_LINE`.
- **Estilos sueltos**: `window_style()`, `selected_style()` (fondo de la fila elegida), `row_style()`.
- **Ayudantes**: `font_for(style)` (la letra de un estilo: familia, peso y, en `display`, el interlineado recortado), `font(path, weight)`, `style_label(label, style, color, outline)`, `style_3d(label3d, ...)`, `menu_row(button)` (una fila de menú plana, con sangría para el cursor y del tamaño de un dedo en móvil; el ratón mueve la selección), `add_cursor(window)` y `row_indent()`.

### El tema del juego

```gdscript
class_name GameTheme extends DsTheme

static func apply(window: Window, high_contrast := false, extend := Callable()) -> void:
	DsTheme.touch = OS.has_feature("mobile")  # lo decide el juego
	DsTheme.apply(window, high_contrast, _extend if extend.is_null() else extend)


static func _extend(theme: Theme) -> void:
	theme.set_type_variation(&"MapWindow", &"PanelContainer")
```

`ensure()` y `build()` se redefinen igual. En GDScript una función estática no se despacha por la subclase, por eso lo del juego entra con el `Callable` y no sobrescribiendo funciones de `DsTheme`; y una función estática redefinida debe tener la misma firma que la de `DsTheme` (GDScript lo comprueba). Las pantallas siguen llamando a todo por el nombre del tema del juego: lo heredado también se llama así.

## MenuCursor

El ▶ dibujado (no es un glifo, así se ve igual en la web) sobre la fila con foco de su ventana, sea con teclado, ratón o dedo. Sigue a un botón de menú o, si el foco está en un selector (`SELECTOR`) o un deslizador, a la fila que lo contiene. Las teclas y las tarjetas dibujan su propio marco y no llevan cursor. No dibuja el fondo de la fila elegida: es el estilo de foco del botón (`selected_style()`). Se pone con `add_cursor(window)`.

## El hook y la publicación

`hooks/pre-commit`, que el juego llama desde su `.githooks/pre-commit`:

1. Si lo preparado no tiene ningún `.gd`, `.json`, `.md` ni `.css`, no hace nada.
2. Busca Godot (`tools/godot.cmd` o `godot` del PATH; sin él avisa y deja pasar) y le pide a `gen_ui_tokens.gd -- --files` qué rutas vigilar.
3. Si lo preparado no toca ninguna de ellas ni un `.gd`, no hace nada.
4. Falla si las fuentes (`base.json`, `tokens.json`, `design_system.json`) o los generados tienen cambios sin añadir: las comprobaciones leen el árbol de trabajo, no lo preparado.
5. Pasa las dos comprobaciones. Cada llamada a Godot lleva `timeout 120` si existe `timeout`.

La publicación las repite después de `--import`; si fallan, no se publica.

## Cómo añadir un token

1. Decide la capa: uno que valga para cualquier juego va en `base.json` y en estas guías; uno de un solo juego, en el `tokens.json` del juego y sus guías. Para darle otro valor a uno del núcleo, `"overrides"`.
2. Escríbelo con su `usage` (y su valor de alto contraste si es un color semántico).
3. Documéntalo como `` `nombre` `` en el `2-fundamentos.md` o la ficha del componente de su capa: `--check` falla si falta.
4. Regenera.
5. Úsalo: `UiTokens.color(&"nuevo")` o `UiTokens.NUEVO`. Nunca escribas el valor en un script.
6. Añade el archivo de tokens y los dos generados al mismo commit: el hook lo exige.
~~~

```gdscript
extends SceneTree
## Development tool of the design system core: writes the game's generated UiTokens script and
## its tokens.css from the core's base tokens plus the game's tokens.json, at the paths
## res://design_system.json gives.
## Run: godot --headless --path . --script res://addons/design_system/tools/gen_ui_tokens.gd
## With `-- --check` it writes nothing: exit 1 if either generated file is not what it would
## write, if a core token is not written as `name` in the core's docs (2-fundamentos.md or
## components/*.md) or a game token or override in the game's, or if a bundle.css uses a
## var(--x) it may not; 0 otherwise. A game token named like a core one, or an override of a
## token the core lacks, fails every mode.
## With `-- --files` it only prints the paths the pre-commit hook watches, one per line:
## "ds-file: <source|generated|docs> <path>".
## Excluded from the export. It uses no game class (a --script run compiles before them).

const CONFIG_PATH := "res://design_system.json"
const TOOL_PATH := "addons/design_system/tools/gen_ui_tokens.gd"
const REGENERATE_HINT := "Regenera con: godot --headless --path . --script res://addons/design_system/tools/gen_ui_tokens.gd"
const FUNDAMENTALS := "2-fundamentos.md"

## Constant groups after the colours: JSON section, comment line.
const SIMPLE_GROUPS := [
	["spacing", "# spacing"],
	["radius", "# radius"],
	["border", "# border"],
	["outline", "# outline"],
	["size", "# size"],
	["layer", "# layer"],
	["opacity", "# opacity"],
]

## JSON sections whose tokens tokens.css writes with their value as it is.
const CSS_GROUPS := ["spacing", "radius", "border", "outline", "size", "opacity", "layer"]

## Every section that holds a "tokens" list, in either layer.
const TOKEN_SECTIONS := ["color", "spacing", "radius", "border", "outline", "size", "layer", "opacity", "shadow"]

var _config := {}
var _palette := {}
## Ids of the game's two themes (color.themes, by "role").
var _theme_normal := ""
var _theme_contrast := ""
## Token names of the core (base.json) and of the game (its own tokens and its overrides).
var _core_names: PackedStringArray = []
var _game_names: PackedStringArray = []
## The CSS variables the core's bundle.css may use: the core's tokens and font families.
var _core_css: PackedStringArray = []
var _errors: PackedStringArray = []


func _init() -> void:
	# A runtime error below (a bad JSON) would hang a --script run; this deferred quit(1) ends
	# it, and the quit(code) of a normal run replaces it.
	quit(1)
	var config: Variant = _read_json(CONFIG_PATH)
	if not config is Dictionary:
		return
	_config = config
	var args := OS.get_cmdline_user_args()
	if "--files" in args:
		_print_files()
		quit(0)
		return
	var base: Variant = _read_json(_config["base"])
	var game: Variant = _read_json(_config["tokens"])
	if not base is Dictionary or not game is Dictionary:
		return
	var json := _merge(base, game)
	if not _errors.is_empty():
		for error in _errors:
			printerr("gen_ui_tokens: %s" % error)
		return
	var gd_text := _build(json)
	var css_text := _build_css(json)
	if "--check" in args:
		quit(_check(gd_text, css_text))
		return
	if _write(_config["gd_out"], gd_text) and _write(_config["css_out"], css_text):
		quit(0)


func _read_json(path: String) -> Variant:
	var json: Variant = JSON.parse_string(FileAccess.get_file_as_string(path))
	if not json is Dictionary:
		printerr("gen_ui_tokens: no se pudo leer %s" % path)
	return json


## The paths the hook watches: the sources, the generated files and the docs folders.
func _print_files() -> void:
	for path: String in [_config["base"], _config["tokens"], CONFIG_PATH]:
		print("ds-file: source %s" % _plain(path))
	for key: String in ["gd_out", "css_out"]:
		print("ds-file: generated %s" % _plain(_config[key]))
	for dir_path: String in _config["docs"]:
		print("ds-file: docs %s" % _plain(dir_path))


## "res://a/b" -> "a/b": the path as git and the docs write it.
func _plain(path: String) -> String:
	return path.trim_prefix("res://")


func _write(path: String, text: String) -> bool:
	var file := FileAccess.open(path, FileAccess.WRITE)
	if file == null:
		printerr("gen_ui_tokens: no se pudo escribir %s" % path)
		return false
	file.store_string(text)
	file.close()
	print("gen_ui_tokens: escrito %s" % path)
	return true


#region Merge

## base.json and the game's tokens.json as one tokens.json of a single layer: per section the
## core's tokens first (with the game's "overrides" applied), then the game's. A clash goes to
## _errors.
func _merge(base: Dictionary, game: Dictionary) -> Dictionary:
	if not _read_themes(game):
		return {}
	var merged := {}
	var core := {}
	for section: String in TOKEN_SECTIONS:
		var tokens: Array = []
		for token: Dictionary in _section_tokens(base, section):
			var own := token.duplicate(true)
			if section == "color":
				own["value"] = _theme_value(own["value"])
			tokens.append(own)
			core[own["name"]] = own
		merged[section] = {"tokens": tokens}
	var base_type: Dictionary = base["type"]
	var groups: Array = base_type["groups"].duplicate(true)
	for group: Dictionary in groups:
		for style: Dictionary in group["styles"]:
			core[style["name"]] = style
	_core_names = PackedStringArray(core.keys())
	var families: Dictionary = base_type["families"].duplicate()
	for family: String in families:
		_core_css.append("font-%s" % family)
	_core_css.append_array(_core_names)
	_apply_overrides(game, core)
	for section: String in TOKEN_SECTIONS:
		for token: Dictionary in _section_tokens(game, section):
			if _no_clash(token["name"], core):
				merged[section]["tokens"].append(token)
				_game_names.append(token["name"])
	var game_type: Dictionary = game.get("type", {})
	for group: Dictionary in game_type.get("groups", []):
		for style: Dictionary in group["styles"]:
			if _no_clash(style["name"], core):
				_game_names.append(style["name"])
		groups.append(group)
	var game_families: Dictionary = game_type.get("families", {})
	for family: String in game_families:
		if not families.has(family):
			_errors.append("type.families: la familia «%s» no está en el núcleo" % family)
		families[family] = game_families[family]
	merged["type"] = {"fonts": game_type.get("fonts", []), "families": families, "groups": groups}
	return merged


## The ids of the game's normal and high-contrast themes; false (and an error) if one is missing.
func _read_themes(game: Dictionary) -> bool:
	for theme: Dictionary in game["color"]["themes"]:
		match theme.get("role", ""):
			"normal":
				_theme_normal = theme["id"]
			"contrast":
				_theme_contrast = theme["id"]
	if _theme_normal.is_empty() or _theme_contrast.is_empty():
		_errors.append("color.themes de %s necesita un tema con \"role\": \"normal\" y otro con \"role\": \"contrast\"" % _plain(_config["tokens"]))
		return false
	return true


## A core colour value with the game's theme ids: {"normal": a, "contrast": b} -> {id: a, id: b}.
func _theme_value(value: Variant) -> Variant:
	if value is Dictionary:
		return {_theme_normal: value["normal"], _theme_contrast: value["contrast"]}
	return value


func _section_tokens(json: Dictionary, section: String) -> Array:
	if json.has(section):
		return json[section]["tokens"]
	return []


## The game's "overrides": each names a core token and gives the fields it replaces.
func _apply_overrides(game: Dictionary, core: Dictionary) -> void:
	for entry: Dictionary in game.get("overrides", []):
		var token_name: String = entry["name"]
		if not core.has(token_name):
			_errors.append("override de un token que el núcleo no tiene: %s" % token_name)
			continue
		var token: Dictionary = core[token_name]
		for field: String in entry:
			if field != "name":
				token[field] = entry[field]
		_game_names.append(token_name)


## false (and an error) if a game token takes the name of a core token.
func _no_clash(token_name: String, core: Dictionary) -> bool:
	if core.has(token_name):
		_errors.append("el token «%s» del juego pisa uno del núcleo: dale su valor en \"overrides\"" % token_name)
		return false
	return true

#region Check

## All the checks of --check; 0 if every one passes, else 1 (each failure is printed).
func _check(gd_text: String, css_text: String) -> int:
	var failed := 0
	failed += _compare(_config["gd_out"], gd_text)
	failed += _compare(_config["css_out"], css_text)
	var docs: Array = _config["docs"]
	failed += _check_documented(_core_names, docs.slice(0, 1), "del núcleo")
	failed += _check_documented(_game_names, docs.slice(1), "del juego")
	failed += _check_css_vars(css_text)
	if failed == 0:
		print("gen_ui_tokens: %s y %s al día, tokens documentados, variables CSS resueltas" % [
			String(_config["gd_out"]).get_file(), String(_config["css_out"]).get_file()])
	return 1 if failed > 0 else 0


## 0 if the file is `text`, else 1 and the first differing line.
func _compare(path: String, text: String) -> int:
	var current := FileAccess.get_file_as_string(path)
	if current == text:
		return 0
	var have := current.split("\n")
	var want := text.split("\n")
	for i in maxi(have.size(), want.size()):
		var a := have[i] if i < have.size() else "<fin del archivo>"
		var b := want[i] if i < want.size() else "<fin del archivo>"
		if a != b:
			printerr("%s:%d: distinto del generado. Tiene: %s | Debería: %s" % [_plain(path), i + 1, a, b])
			break
	printerr(REGENERATE_HINT)
	return 1


## 1 if some name is not written as `name` in the 2-fundamentos.md or components/*.md of `dirs`.
func _check_documented(names: PackedStringArray, dirs: Array, layer_name: String) -> int:
	var docs := ""
	var where: PackedStringArray = []
	for dir_path: String in dirs:
		docs += _docs_text(dir_path)
		where.append(_plain(dir_path))
	var missing: PackedStringArray = []
	for token_name in names:
		if not docs.contains("`%s`" % token_name):

	if missing.is_empty():
		return 0
	printerr("Tokens %s sin documentar en 2-fundamentos.md ni components/*.md de %s (%d): %s" % [
		layer_name, ", ".join(where), missing.size(), ", ".join(missing)])
	return 1


func _docs_text(dir_path: String) -> String:

## 1 if a bundle.css uses a var(--x) that `css_text` does not define; the first bundle is the
## core's, which may use only the core's variables.
func _check_css_vars(css_text: String) -> int:
	var used := RegEx.new()
	used.compile("var\\(--([\\w-]+)")
	var bundles: Array = _config["bundles"]
	var failed := 0
	for i in bundles.size():
		var path: String = bundles[i]
		var missing: PackedStringArray = []
		var outside: PackedStringArray = []
		for hit in used.search_all(FileAccess.get_file_as_string(path)):
			var token_name := hit.get_string(1)
			if not css_text.contains("\t--%s:" % token_name):
				if not token_name in missing:
					missing.append(token_name)
			elif i == 0 and not token_name in _core_css and not token_name in outside:
				outside.append(token_name)
		if not missing.is_empty():
			printerr("%s usa variables que %s no define: %s" % [
				_plain(path), _plain(_config["css_out"]), ", ".join(missing)])
			failed = 1
		if not outside.is_empty():
			printerr("%s es el del núcleo y usa variables del juego: %s" % [_plain(path), ", ".join(outside)])
			failed = 1
	return failed

## tokens.css: the custom properties the bundle.css files read. The normal theme's colours in
## :root, the ones that differ in high contrast under [data-theme="<its id>"].
func _build_css(json: Dictionary) -> String:
	var out: PackedStringArray = []
	out.append("/* Generado por %s desde %s y %s. No se edita a mano: cambia tokens.json y regenera. */" % [
		TOOL_PATH, _plain(_config["tokens"]), _plain(_config["base"])])
	out.append(":root {")
	var contrast: PackedStringArray = []
	_fill_palette(json["color"]["tokens"])
	for token: Dictionary in json["color"]["tokens"]:
		var in_game := _resolve(token["value"], _theme_normal)
		out.append("\t--%s: %s;" % [token["name"], in_game])
		var in_contrast := _resolve(token["value"], _theme_contrast)
		if in_contrast != in_game:
			contrast.append("\t--%s: %s;" % [token["name"], in_contrast])
	for section: String in CSS_GROUPS:
		for token: Dictionary in json[section]["tokens"]:
			out.append("\t--%s: %s;" % [token["name"], token["value"]])
	out.append("\t--shadow-window: %s;" % json["shadow"]["tokens"][0]["value"])
	var families: Dictionary = json["type"]["families"]
	for family: String in families:
		out.append("\t--font-%s: %s;" % [family, families[family]])
	out.append("}")
	out.append("")
	out.append("[data-theme=\"%s\"] {" % _theme_contrast)
	out.append_array(contrast)
	out.append("}")
	return "\n".join(out) + "\n"


func _fill_palette(tokens: Array) -> void:
	_palette.clear()
	for token: Dictionary in tokens:
		_palette[token["name"]] = token["value"]


func _add_colors(out: PackedStringArray, tokens: Array) -> void:
	_fill_palette(tokens)
	var game: PackedStringArray = []
	var contrast: PackedStringArray = []
	for token: Dictionary in tokens:
		var token_name: String = token["name"]
		var in_game := _resolve(token["value"], _theme_normal)
		game.append("\t&\"%s\": Color(\"%s\")," % [token_name, in_game])
		var in_contrast := _resolve(token["value"], _theme_contrast)
		if in_contrast != in_game:
			contrast.append("\t&\"%s\": Color(\"%s\")," % [token_name, in_contrast])
	out.append("const %s := {" % _const_name(_theme_normal))
	out.append_array(game)
	out.append("}")
	out.append("")
	out.append("const %s := {" % _const_name(_theme_contrast))
	out.append_array(contrast)
	out.append("}")
	out.append("")


## The hex of a token value for one theme; `{name}` references are followed.
func _resolve(value: Variant, theme: String) -> String:
	var text: String = value[theme] if value is Dictionary else value
	if text.begins_with("{") and text.ends_with("}"):
		return _resolve(_palette[text.substr(1, text.length() - 2)], theme)
	return text


func _add_simple_group(out: PackedStringArray, tokens: Array, comment: String) -> void:
	out.append(comment)
	for token: Dictionary in tokens:
		out.append("const %s := %s" % [_const_name(token["name"]), _number(token["value"])])
	out.append("")


## Writes the TYPE_* constants and the font paths (empty for a family the game gives no font);
## returns the rows of the TYPE table.
func _add_type_constants(out: PackedStringArray, type: Dictionary) -> PackedStringArray:
	var rows: PackedStringArray = []
	out.append("# Tipografía: tamaño en px y peso (wght) de cada estilo.")
	for group: Dictionary in type["groups"]:
		for style: Dictionary in group["styles"]:
			var base := "TYPE_%s" % _const_name(style["name"])
			out.append("const %s_SIZE := %s" % [base, _number(style["fontSize"])])
			out.append("const %s_WEIGHT := %d" % [base, int(style["fontWeight"])])
			rows.append("\t&\"%s\": [%s, %d, FAMILY_%s, %s]," % [
				style["name"], _number(style["fontSize"]), int(style["fontWeight"]),
				String(group["family"]).to_upper(), _float(style["lineHeight"])])
	out.append("")
	var fonts: Array = type["fonts"]
	for family: String in type["families"]:
		var path := ""
		for font: Dictionary in fonts:
			if font["role"] == family:
				path = font["godot_path"]
		out.append("const FONT_%s_PATH := \"%s\"" % [family.to_upper(), path])
	return rows


func _add_type_table(out: PackedStringArray, type: Dictionary, rows: PackedStringArray) -> void:
	out.append("")
	for family: String in type["families"]:
		out.append("const FAMILY_%s := &\"%s\"" % [family.to_upper(), family])
	out.append("## Type style -> [size px, weight (wght), family, line height] (tokens.json, type.groups).")
	out.append("const TYPE := {")
	out.append_array(rows)
	out.append("}")


func _add_shadow(out: PackedStringArray, token: Dictionary) -> void:
	var css: String = token["value"]
	var color := ""
	for part in css.split(" "):
		if part.begins_with("#"):
			color = part
	var godot: Dictionary = token["godot"]
	var offset: Array = godot["offset"]
	out.append("")
	out.append("## %s (tokens.json: \"%s\"; in Godot shadow_size %d, offset (%d, %d))." % [
		token["name"], css, int(godot["size"]), int(offset[0]), int(offset[1])])
	out.append("const SHADOW_COLOR := Color(\"%s\")" % color)
	out.append("const SHADOW_SIZE := %d" % int(godot["size"]))
	out.append("const SHADOW_OFFSET := Vector2(%d, %d)" % [int(offset[0]), int(offset[1])])


## "space-1" -> "SPACE_1", "alto-contraste" -> "ALTO_CONTRASTE".
func _const_name(token_name: String) -> String:
	return token_name.replace("-", "_").to_upper()


## "56px" -> "56", "0.9" -> "0.9", "1" -> "1": px stripped, an integer unless it has a point.
func _number(value: String) -> String:
	var plain := value.trim_suffix("px")
	if plain.contains("."):
		return plain
	return str(int(plain))


## A JSON number as GDScript float text ("1.0", "1.05").
func _float(value: float) -> String:
	return str(value)

#endregion
```

```python
    return [t["name"] for t in section["tokens"]]

    return {s["name"]: (g["family"], s["fontSize"], s["lineHeight"], s["fontWeight"])
            for g in type_["groups"] for s in g["styles"]}
```

```bash
#!/usr/bin/env bash
# Pre-commit del design system (núcleo): UiTokens y tokens.css al día, tokens documentados y sin
# valores de interfaz a mano. Las rutas las da gen_ui_tokens.gd -- --files (design_system.json).
# El juego lo llama desde su .githooks/pre-commit, que se activa una vez por clon:
# git config core.hooksPath .githooks

tools=res://addons/design_system/tools
staged=$(git diff --cached --name-only)
# Sin nada que el design system lea, ni se arranca Godot.
if ! echo "$staged" | grep -qE '\.(gd|json|md|css)$'; then
  exit 0
fi

if [ -f tools/godot.cmd ]; then
  godot=(./tools/godot.cmd)
elif command -v godot >/dev/null 2>&1; then
  godot=(godot)
else
  echo "pre-commit: no hay Godot (tools/godot.cmd ni godot en el PATH); se salta la comprobación. La publicación la repite." >&2
  exit 0
fi

# Un script de Godot que falla por dentro puede quedarse colgado: con `timeout`, 120 s como máximo.
if command -v timeout >/dev/null 2>&1; then
  godot=(timeout 120 "${godot[@]}")
fi

files=$("${godot[@]}" --headless --path . --script "$tools/gen_ui_tokens.gd" -- --files | tr -d '\r' | sed -n 's/^ds-file: //p')
if [ -z "$files" ]; then
  echo "pre-commit: gen_ui_tokens.gd -- --files no ha dado ninguna ruta (¿falta design_system.json?)." >&2
  exit 1
fi
watched=$(echo "$files" | cut -d' ' -f2-)
locked=$(echo "$files" | grep -E '^(source|generated) ' | cut -d' ' -f2-)

hit=0
while IFS= read -r path; do
  [ -z "$path" ] && continue
  case "$path" in
    *.gd) hit=1 ;;
  esac
  while IFS= read -r watch; do
    case "$path" in
      "$watch" | "$watch"/*) hit=1 ;;
    esac
  done <<< "$watched"
  [ "$hit" -eq 1 ] && break
done <<< "$staged"
if [ "$hit" -eq 0 ]; then
  exit 0
fi

# Las comprobaciones leen el árbol de trabajo, no lo preparado: si las fuentes o los generados
# tienen cambios sin añadir, lo que se comprueba no es lo que se confirma.
unstaged=$(git diff --name-only -- $locked)
if [ -n "$unstaged" ]; then
  echo "pre-commit: hay cambios sin añadir en las fuentes o los generados del design system: añádelos al commit. Sin añadir:" >&2
  echo "$unstaged" >&2
  exit 1
fi
```

~~~markdown
La interfaz de Villaclaro es una capa clásica de RPG de consola que flota sobre un mundo 3D low-poly luminoso: ventanas azul marino con marco blanco, texto blanco, dorado para lo importante y un color fijo para cada dato del héroe. Este sistema la ordena para que crezca sin perder esa identidad. Todo valor sale de un token, todo color tiene un significado y la selección se ve igual con teclado, ratón o dedo.

## Las dos capas

- **El núcleo** ([`addons/design_system/`](../../../addons/design_system/README.md)): las herramientas, los tokens genéricos (escalas, medidas, los diez estilos de texto y los semánticos de superficie, marco y texto), la base del tema (`DsTheme`), el cursor (`MenuCursor`) y las guías de [fundamentos](../../../addons/design_system/docs/2-fundamentos.md), [interacción](../../../addons/design_system/docs/3-interaccion.md), [accesibilidad](../../../addons/design_system/docs/4-accesibilidad.md) y [Godot](../../../addons/design_system/docs/5-godot.md). Es igual en todos los juegos y no se edita desde aquí.
- **La capa de Villaclaro** (esta carpeta): su identidad, su [voz y tono](1-voz-y-tono.md), su paleta, sus fuentes, los valores que da a los tokens del núcleo y sus tokens propios ([fundamentos](2-fundamentos.md)), su [tabla de contraste](4-accesibilidad.md), la [migración](6-migracion.md) y las fichas de sus componentes. Sus rutas están en `design_system.json`, en la raíz del juego.

## Principios

1. **El mundo primero.** Ventanas translúcidas, pequeñas y en las esquinas; nunca tapan la acción sin motivo.
2. **Un color, un significado.** Rojo es PV, azul es PM, verde es EXP, dorado es «mira aquí» o dinero. Si un color ya significa algo, no se usa para otra cosa.
3. **Siempre se sabe dónde estás.** La fila elegida lleva el cursor dorado ▶ y un fondo, en cualquier dispositivo.
4. **Teclado, ratón y dedo por igual.** Todo se puede hacer con los tres; en móvil nada mide menos de `touch-target`.
5. **Legible sobre cualquier escena.** Las ventanas llevan sombra; el texto sobre el mundo lleva contorno.
6. **Nunca solo color.** Estados, comparaciones y marcas del mapa llevan siempre palabra, forma o signo.

## Cómo está organizado

- **`tokens.json`**: la capa de Villaclaro sobre el `base.json` del núcleo (`"extends"`).
  - **Paleta base** (`navy-*`, `gold-*`, `red-*`, `blue-*`, `green-*`…): los colores en bruto. No se usan directamente en la interfaz.
  - **`"overrides"`**: el valor que Villaclaro da a los semánticos del núcleo (`surface-*`, `border-*`, `text-*`): el azul marino, el blanco y el dorado.
  - **Tokens propios**: `stat-*` (barras del héroe), `status-*` (estados de combate), `element-*` y `effect-*` (efectos), `map-*` (marcas del mapa), `world-*` (referencia del mundo), los rótulos dorados (`text-display*`, `text-outline-warm`), sus medidas, sus opacidades y las capas de pantalla `layer-*`.
- **Temas**: `juego` (el normal) y `alto-contraste` (opción de accesibilidad: ventanas opacas, texto a 7:1 o más). Solo cambian los semánticos.
- **Tipografía**: `display` es Baloo 2, para rótulos, logotipo y números; `ui` es Nunito, para todo lo demás. Los diez estilos son los del núcleo, de `display-xl` (96 px) a `micro` (16 px); `body` (24 px) es la base.
- **Lo generado**: `scripts/ui/ui_tokens.gd` (`UiTokens`) y `tokens.css`, desde el `base.json` del núcleo y este `tokens.json`. No se editan a mano.

## Reglas rápidas

- Escribe `text-primary` sobre `surface-window`; las descripciones en `caption` con `text-secondary`.
- Títulos de ventana en `title-s` con `text-accent`. El oro siempre en `text-money`.
- Una ventana: `surface-window`, marco `border-3` `border-window`, `radius-m`, relleno `space-4` × `space-3`, `shadow-window`.
- Separa ventanas con `space-4` y despégalas del borde de la pantalla con `space-6`.
- Texto sobre el mundo: blanco con `outline-m` en `text-outline`, o dorado `text-display` con `outline-l` en `text-outline-warm`.
- Nunca escribas un color o un tamaño a mano en un script: usa `UiTokens` ([Godot](../../../addons/design_system/docs/5-godot.md)).

## Iconografía

No hay fuente de iconos: la interfaz se apoya en el texto. Los pocos pictogramas se dibujan en código para que se vean igual en la web:
- el botón ☰: tres barras blancas de 32 × 5;

- las marcas de misión «!» y «?»: texto 3D en `display`;
~~~

~~~markdown
Las reglas generales (4,5:1 en el tema normal, 7:1 en el de alto contraste, nunca solo color) están en la [accesibilidad del núcleo](../../../addons/design_system/docs/4-accesibilidad.md). Aquí, los pares comprobados con los valores de Villaclaro y lo que hace su tema de alto contraste.

## Contraste

Pares comprobados en `juego`:

| Texto | Sobre | Contraste |
| --- | --- | --- |
| `text-primary` | `surface-window-solid` | 19,5:1 |
| `text-secondary` | `surface-window-solid` | 10:1 |
| `text-disabled` | `surface-window-solid` | 5,1:1 |
| `text-accent` | `surface-window-solid` | 14,2:1 |
| `text-negative` | `surface-window-solid` | 7,2:1 |
| blanco | `stat-hp` / `stat-mp` / `stat-exp` | 5,4 / 4,9 / 5,4:1 |
| blanco | insignias | 6,1–7,1:1 |
| cursor `border-focus` | `surface-selected` | 12,8:1 |

El verde de la barra de EXP pasó de #2e9e42 (3,5:1 con blanco, solo legible gracias al contorno) a `green-600` #237a33 (5,4:1).

## Tema «Alto contraste»

La opción de Opciones, junto a «Texto grande»: ventanas opacas (`navy-950`), texto secundario y desactivado más claros, separadores visibles (7:1) e insignias más oscuras.

## Nunca solo color

- Estados: insignia con la palabra.
- Comparaciones: ▲/▼ con su signo.
- Marcas del mapa: leyenda en la página Mapa.
- PV críticos: texto naranja y latido.
- Avisos: palabra de tono («Misión cumplida», «Guardado»).

## Otras opciones

Texto grande (×1,25), velocidad del texto, velocidad del combate, temblor de cámara y teclas reasignables.
~~~
