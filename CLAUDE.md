# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`rpg-turnos` (the game is called *Villaclaro: la Niebla del Norte*; its version is `application/config/version`, also shown on the title screen; `CHANGELOG.md` in Spanish): a 3D turn-based RPG with a Dragon Quest-like look, made with Godot 4.7.2 (Compatibility renderer, so the same build runs on the web). The work is done from Claude Code, not the Godot editor, so scenes (`.tscn`) and scripts (`.gd`) are written directly as text files. Design specs live in `docs/legacy/specs/`.

## Layout

- `scenes/title/title.tscn` + `scripts/title/title_screen.gd` (`TitleScreen`) — main scene (`run/main_scene`). Loads the options (`SaveStore.load_options()`) and applies them (`DisplaySettings.apply()`, `KeyMap.apply()`), owns the only `AudioDirector`, shows "Villaclaro", the subtitle "La Niebla del Norte" and the version in a corner over the meadow (`WorldStage.build`) seen from a slowly drifting top-down camera, with Nueva partida / Continuar (disabled without a save; with a usable one `SaveData.summary_line()` shows under it) / Opciones (`OptionsPanel`) / on an Android phone a "Pantalla completa" row that sets the window fullscreen, shown whenever the window is not fullscreen (`_sync_fullscreen_row()` every frame, so it comes back when the browser leaves fullscreen); once a second `_process()` asks `WebUpdate.is_ready()` and shows `_show_update_notice()`, a window "Hay una versión nueva. Recargar" (`UPDATE_WIDTH` 300, wraps, grows up from the bottom left corner so the menu and the version never move) that calls `WebUpdate.apply()`; creates a `Game` with `setup(audio, options, save, hero_name, difficulty, slot)` (it autosaves and saves to that slot) (empty save = new game) and frees it on `quit_to_title` (unpausing the tree). If the save file exists but can't be read, `_load_save()` passes a marker that `Game` rejects: it starts a new game with the notice "No se pudo cargar la partida. Empiezas de nuevo.". There are three save slots (`SaveStore`, `SlotList` inside `_slot_window`): "Continuar" is enabled when some slot passes `SaveData.is_valid()` and opens the list, where only usable slots can be picked (the rest are grey: "Vacía", "Partida dañada"; a finished game adds " · terminada"); "Nueva partida" goes straight to the name in slot 1 when every slot is empty, else opens the list: an empty or damaged slot goes on, one with a game asks ("La partida de la ranura n se borrará. ¿Empezar una nueva?", focus on "No"; No, Esc or a tap outside go back). Then it opens the `NameEntry` over the meadow (the title text hidden), then the `DifficultyWindow` (its Volver or Esc goes back to the `NameEntry` with the name as typed, `_back_to_name()`), and both go to `Game.setup(..., slot)`; `_ready()` calls `SaveStore.migrate_legacy()` first. On a phone the title and subtitle are smaller (`TOUCH_TITLE_SIZE` 64, `TOUCH_SUBTITLE_SIZE` 26, menu at `TOUCH_MENU_TOP` 135) so the menu with the fullscreen row fits a 740 × 360 window, also with large text. The options window has a backdrop (shared with the slot list) that goes back (and saves) on a tap outside it. `--autoplay` skips the menu: the `NameEntry` types `AUTOPLAY_NAME` "Rocío" by itself and a new game starts; with `--autoplay-save` the first `quit_to_title` loads the save at once.
- `scenes/game/game.tscn` + `scripts/game/game.gd` (`Game`) — one play session, created by `TitleScreen` (run on its own it makes its own `AudioDirector` and default options). Owns a `GameState` and the `World` of the current zone: `_switch_zone(zone_id, entry_id)` frees the map and builds `ZoneData.by_id(zone_id)` ("" entry: the zone's start), connects its signals, reopens its chests, passes the world flags and places the boss. On `World.encounter_triggered(boss)` it fades to black, `World.set_active(false)`, instantiates a `BattleScene` with `setup(state.hero, enemies, state.inventory)`, `set_equipment(weapon, shield, helmet)`, `gold_lost = state.defeat_gold_loss()` and `zone` on top (`enemies` from `EncounterTable.pick(zone, pos, rng, state.quests.wanted_enemies(), state.quests.hunted_enemies())`, or `[EnemyLibrary.data(zone.boss_id)]`), awaits `finished(outcome)` (`BattleEngine.State`), frees it and turns the map back on (victory: `state.gold += engine.gold_won` and, for every enemy, `quest.on_victory(id)` and `state.quests.on_victory(state, id)`, a side quest finished there showing its reward as a notice; a boss also calls `state.on_boss_defeated()` (world flag + key item) and shows `BOSS_NOTICES` ("¡Villaclaro está a salvo! La niebla deja libre el camino del norte.") or "¡Consigues un Fragmento del amuleto (n/3)!"; the Señor de la Niebla's flag (`GameState.FINAL_BOSS`) marks the game as finished, `GameState.is_finished()`: "¡Consigues el último Fragmento del amuleto! La niebla se levanta."; fled: nothing; defeat: loses half the gold, `heal_full()` and goes to the town entry of `state.town_zone` ("Has vuelto a Villaclaro." / "... al refugio de la mina." / "... al campamento.", `_to_place()`)). On `World.map_requested` opens the pause menu's Mapa page. On `World.exit_requested(zone, entry)` (an arch or the stairs of a mine floor) it fades, switches zone and autosaves silently; the pause menu's `travel_requested` (Ala de viaje) does the same to the last village, leaves a ring on the ground at the spot it was used and a portal in the village (`GameState.open_portal()`, "Vuelas a <village>. El portal te espera para volver.", a second Ala replaces the open one, "... El portal anterior se ha cerrado."; a defeat leaves it open; the map is frozen during the flight so nothing triggers); `World.portal_used` (`_on_portal()`) takes the hero back once ("El portal te devuelve y se cierra tras de ti."). `_switch_zone()` leaves the new map frozen (`World.freeze(true)`) and every path (exit, defeat, Ala, a battle's return) unfreezes it only after the fade-in, so nothing on it can fire while `Game` is still busy. On a mine floor `World.lever_pulled` sets `zone.lever_flag` ("¡Tiras de la palanca! Se oye cómo se abre una reja."), `World.key_taken` adds `zone.floor_key` to the key items and sets it as a flag ("¡Encuentras la Llave de la mina!"), `World.door_used` opens the gates with `zone.door_key` (used up: "Abres la reja con la Llave de la mina.") or shows `zone.door_text`; each sets the flags on the map, autosaves silently and refreshes the status (the mission line follows); `World.village_changed(true)` makes the zone the last village visited. On `World.shop_requested(shop_id)` it freezes the map and awaits `ShopWindow.run(shop_id)` (on autoplay only when `Shop.autoplay_picks()` is not empty), then autosaves if anything changed; on `World.inn_requested(inn_id)` the keeper speaks ("Descansa un poco." / "Se te ve en forma." when `Inn.is_rested()`), and with HP or MP missing it calls `Inn.stay()` at once, no question (free: fade to black, `INN_NIGHT_TIME` 0.8 s, full HP and MP, autosave; on autoplay only below `AUTOPLAY_INN_RATIO` 0.5 of max HP or MP, on `GameState.needs_rest()` or below the boss thresholds); on `World.well_requested(id, kind)` it drinks (`Wells.drink()`, sound, status, autosave; on autoplay only a full well and a hero who is not rested), after a won or lost battle `Wells.on_battle()` and `World.set_dry_wells()`; on `World.chest_opened(id)` it calls `Chests.open(state, id)`, opens the lid (`World.set_chest_open()`), saves without a notice and says what was found with `World.show_dialogue()` (waits for Enter or a tap; on autoplay it goes on by itself); on `World.npc_requested(i)` it plays `World.npc_lines(i, state.chapter())` with the name filled in. A won battle that finishes a quest shows "Misión cumplida: <title>" (`QuestLog.done_text()`, `World.show_mission_done()`, 4 s). `_refresh_status()` passes `GameState.current_missions()` to the status window, also shows the weapon and shield on the map hero (`World.set_hero_equipment()`) and, on autoplay, prints `Oro N G · Equipo: ... · ATK n DEF n VEL n` whenever it changes. `_boss_id()` is the zone's boss, or its `postgame_boss_id` (the Eco de la Niebla, in the throne room) once `state.is_finished()`: it is always on the map, can be fought again and again, and a first victory shows `REWARD_LINE` and `QuestRewards.wear_prize()`'s lines (the Yelmo de bruma goes on at once, the helmet worn goes to the bag) in the dialogue window, the later ones the notice "El Eco de la Niebla se deshace en la bruma... por ahora."; the first victory is the world flag `eco_niebla`, so the save does not change. `_note_enemies()` notes as seen or beaten only the enemies of `BestiaryPage.ORDER`: the Eco never enters the bestiary. `--autoplay-zone=eco` (`ECHO_START` in `AUTOPLAY_ZONES`: Lv 20, platinum gear with helmet, the Esqueleto leal, the story finished, in the throne room) fights it again and again printing `Eco de la Niebla: victoria/derrota (n de m ganados)`. `_update_boss()` shows the zone's boss until it is beaten (the Rey Slime only while `quest.boss_available()`; on autoplay only from the zone's `autoplay_boss_level` and with `AUTOPLAY_BOSS_HP` 70 % of max HP and `AUTOPLAY_BOSS_MP` 40 % of max MP). Autoplay retreat: after a won battle, if `GameState.needs_rest()` or `_boss_needs_rest()` (the zone's boss is due at this level but HP or MP are below `AUTOPLAY_BOSS_HP` / `AUTOPLAY_BOSS_MP`) away from a village, with an Ala de viaje, it flies back ("Retirada al pueblo (...)"), `_autoplay_restock()`s (that inn, then that shop) and goes back through the portal; after a defeat it restocks too. The story: a new game starts under black and `_play_prologue()` plays `prologo` (the slimes quest starts with `Quest.start()`); `_play_scene(id)` plays `data/cutscenes/<id>.tres` through its `CutscenePlayer` and marks it seen; a boss beaten plays `StoryState.scene_after_boss()` instead of its notice, and `_check_village_scene()` (after arriving through an exit, after loading and on `World.village_changed(true)`) plays the first visit's `StoryState.scene_on_village()`. Beating the Señor de la Niebla plays `final` (its `travel` step goes back to Villaclaro through `_scene_travel()`), and `_finish_game()` sets `story.finished`, autosaves, rolls the `CreditsScreen` with the numbers of the game (`_credits_sections()`, `AUTHOR`) and emits `quit_to_title`. A finished save loads in Villaclaro and the world can still be walked. `state.battles`, `steps` (from `World.stepped`) and `gold_earned` count for the credits. `_show_touch_hint()` (`TOUCH_HINT`: the first time a phone reaches the map, never on autoplay, remembered in the options), `_on_stepped()` (every `World.STEP_DISTANCE`: steps for the credits and the Incienso's metres, `REPEL_END_NOTICE` "El incienso se ha consumido.") and `_refresh_status()` also pass `EncounterMeter.level_rate()` and the Incienso to the world; the pause menu's use message for it says "Los monstruos se apartan durante 200 m.". On autoplay every change of zone prints `Zona: <id> (Nv n, h:mm:ss)` and the credits end with `Juego completado: Nv n, tiempo de juego h:mm:ss, misiones n`; then only `TitleScreen` quits (run on its own, `game.tscn` stays on the map). On `World.talk_requested` it takes the lines and potions from `quest.talk()` (once the quest is done, her `lines_by_chapter`), fills in the hero's name, heals, and plays them with `World.show_dialogue()`, then shows the boss if `quest.boss_available()`. The map stays while battles come and go, so position, camera and encounter grace survive them. Music: the zone's `music` / `village_music` (`World.village_changed`), battle or boss (the battle plays victory / defeat). Autosaves (`SaveData.from_state()` → `SaveStore.save_game()`) after each talk and each won battle ("Partida guardada.", except after a boss, which shows its notice instead) and silently after a defeat (so the gold lost sticks), after a chest and after each change of zone, never in battle; a save is loaded with `SaveData.apply()` (its zone) and `World.place_player()`; counts `play_time` (stops while paused). Owns the `PauseMenu` (`available` only on the map with nothing else going on) and answers its `save_requested` / `title_requested` (the latter sets a `_leaving` guard, marks the game busy, hides the menu and ignores input, so the frozen map can't walk or roll an encounter during the fade) / `travel_requested`; emits `quit_to_title`. `--autoplay --autoplay-save` prints `Guardado: <json>` / `Cargado: <json>`; `--autoplay --autoplay-menu` tours the pause menu 1 s into the map; `--autoplay --autoplay-zone=<id>` starts a new game in that zone with `AUTOPLAY_ZONES` (bosque: Lv 5, 150 G, the zone 1 gear, the Rey Slime beaten; mina_1: Lv 9, 250 G, the zone 2 gear, the Bruja beaten, the first fragment; mina_3: Lv 13, 100 G, the zone 3 gear, both gates open, the refugio as last village; castillo_patio: Lv 13 with the Golem's 300 EXP, 600 G, the zone 3 gear, the Golem beaten, two fragments; castillo_trono: Lv 17, 300 G, the platinum gear, the camp as last village). When `state.ally_id` is set, the battle gets a fresh copy of that creature (`battle.ally = Allies.data(state.ally_id)`).
- `scripts/game/game_state.gd` (`GameState`, `RefCounted`) — session state kept in memory: the hero `Combatant` (a duplicate of `data/hero.tres` that lives the whole session; battles change its HP, MP, EXP and level in place), `inventory: Inventory` (starts with 3 potions), `quest: Quest`, `quests: QuestLog`, `gold` (`START_GOLD` 50), `loadout: Loadout`, `bag_equipment` (Equipment ids carried but not worn), `opened_chests` (Chests ids), `well_charge` (Wells: dry well id → battles left), `ally_id` (the creature fighting beside the hero, an `Allies` id, "" for none), `seen_enemies` (EnemyLibrary ids met in battle, `see_enemy(id)`, noted by `Game` before and after each battle), `defeated_enemies` (ids beaten in a won battle, `defeat_enemy(id)`; a won battle notes every enemy of `engine.enemies`, the ones called for help too; fleeing or falling notes nothing), `world_flags` (flag → true; a beaten boss sets its enemy id, which opens the exits locked by it), `key_items` (`Inventory.KEY_ITEMS` ids), `zone_id` (the map the hero is on) and `town_zone` (last village visited; "pradera" at first), `heal_full()` (HP and MP), `field_spells()` (the heals), `spell_problem(skill)` ("Faltan PM", "PV al máximo"), `cast_spell(skill)` (pays the MP, heals up to `power`), `use_item(id)` (outside battle, `Inventory.use()`; an Incienso sets `repel_m` to 200, not saved), `refresh_equipment()` (copies the loadout bonuses into `hero.equip_attack` / `equip_defense` / `equip_speed` / `equip_immune`), `equip(id)` (from the bag; what it replaces goes to the bag), `unequip(slot)`, `on_boss_defeated(boss)` (flag + key item, returns the item given), `has_flag(flag)` ("" is always set), `is_finished()` (the `FINAL_BOSS` "senor_niebla" flag), `story: StoryState`, `chapter()`, `battles` / `steps` / `gold_earned` and `quests_done()` (the credits' numbers; the hero's name is `hero.display_name`), `needs_rest()` (autoplay retreat: below `REST_HP_RATIO` 0.3 of max HP, or no potions and MP for less than two of the best heal), `defeat_gold_loss()` (half the gold, rounded down), `main_goal()` (the village quest's line while it lasts, else `StoryState.goal_text(flags, zone_id)`), `current_missions()` (the one function that reads the missions under way, never empty: `main_goal()` first, then the side quests' lines), `portal_town` / `portal_zone` / `portal_pos` with `has_portal()`, `open_portal(pos)`, `close_portal()`, `explored` (zone id → `ExploredMap`) with `explored_map(id)`. The hero gets its own `skills` array, so learning a spell never touches `hero.tres`.
- `scripts/story/story_state.gd` (`StoryState`, `RefCounted`) — pure: `seen` (cutscene ids), `finished`; `chapter(flags)` (`Chapter`: 0 prologue, 1 meadow, 2 forest, 3 mine, 4 castle, 5 end, from the prologue seen and the bosses' flags), `SCENES`, `AFTER_BOSS`, `ON_VILLAGE`, `scene_after_boss()`, `scene_on_village()`, `mark_seen_for_flags()` (older saves and `--autoplay-zone`), `goal_text(flags, zone_id)` (in the mine chapter `MINE_GOALS` follow the floor and the mine's flags), `to_dict()`, `set_from()`, `fill(text, name)` (`NAME_TAG` "{nombre}"), `clean_name()` (`MAX_NAME_LENGTH` 8, `DEFAULT_NAME` "Héroe").
- `scripts/story/cutscene.gd` (`Cutscene`, `Resource`) — a scene as data, `data/cutscenes/<id>.tres` (`prologo`, `rey_slime`, `aldea_bosque`, `bruja`, `mina`, `golem`, `castillo`, `final`): `steps`, each an Array (`say`, `move`, `approach`, `face`, `wait`, `camera_to`, `camera_back`, `fade_out`, `fade_in`, `music`, `sfx`, `flag`, `travel`, `cheer`; the header of the script lists them). `scripts/story/cutscene_player.gd` (`CutscenePlayer`, `Node`) plays one on `world`, with the `fade`, `set_flag` and `travel` Callables from `Game`; `await play(scene)`. On autoplay every step is printed.
- `scripts/game/equipment.gd` (`Equipment`, `RefCounted`) — the `EQUIPMENT` catalog (id → name, article, slot `WEAPON` / `HELMET` / `ARMOR` / `SHIELD` / `ACCESSORY`, bonus (ATK for weapons, VEL for accessories, DEF for the rest), price, zone, mesh, `immune` on an accessory; the accessories are quest rewards, zone −1, price 0: `POISON_RING` Anillo antiveneno, immune to poison, and `SPEED_AMULET` Amuleto de velocidad, VEL +3; `MIST_HELM` Yelmo de bruma, the Eco de la Niebla's prize: a helmet with DEF +8 and ATK +5, blue-grey with horns, zone −1, price 0 ("No se vende"); `extra_attack()` and `has_horns()` read its `attack` and `horns` keys, and `effect_text()` says "DEF +8 · ATK +5"; `immunity()`, `effect_text()`): Palo +2 and Ropa +2 (zone 0, the starting gear, worth nothing), zone 1 Espada de cobre +6 · 40 G, Cota de cuero +5 · 30 G, Escudo de madera +3 · 25 G, Casco de cobre +2 · 20 G (one helmet per shop zone, DEF +2 / +3 / +5 / +7: cobre, hierro 70 G, acero 180 G, platino 260 G, each with a `tint`; `helmet_tint(id)`), and zones 2-4 already listed for their shops; `display_name()`, `article()`, `pronoun()`, `slot()`, `bonus()`, `price()`, `mesh()` (a `Knight.glb` handslot mesh, `STICK_MESH` or ""), `stat_name()`, `of_zone()`, `SLOTS`, `SLOT_NAMES`.
- `scripts/game/loadout.gd` (`Loadout`, `RefCounted`) — what the hero wears, slot → id (Palo, Ropa, no shield or helmet at first; the helmet counts in `defense_bonus()`): `worn(slot)`, `is_worn(id)`, `equip(id)` (returns what it took off), `unequip(slot)`, `attack_bonus()` (the weapon's ATK plus the helmet's `extra_attack()`), `defense_bonus()`, `speed_bonus()`, `immunities()`, `to_dict()`, `set_slots()` (a slot missing from an old save stays empty).
- `scripts/game/shop.gd` (`Shop`, `RefCounted`) — pure shop rules: `SHOPS` (Villaclaro: the zone 1 gear and helmet, Poción, Antídoto and Ala de viaje; Bosque: the zone 2 gear, Poción, Antídoto, Éter and Ala de viaje; Mina: the Herrero, the zone 3 steel gear and the same items (all four shops also sell the Incienso, which `autoplay_picks()` never buys); Castillo: the Mercader of the camp, the zone 4 platinum gear and the same items; and the four tamers `domadora_villaclaro` / `domadora_bosque` / `domadora_mina` / `domadora_castillo`, each with no gear or items and one `ally` (gallina, lobezno, golem_pequeno, esqueleto_leal) and a `gear_shop`, the shop whose gear autoplay buys first), `sells_ally()`, `is_ally()`, `HAS_IT` "Ya la tienes" / `HAS_BETTER` "Ya tienes una mejor" (`buy_problem()` of a creature: the same one, or a lower tier than the one carried), `stock()` (the creature last), `price()`, `sell_price()` (half, rounded down; the starting gear of zone 0 sells for `STARTING_GEAR_PRICE` 1; quest rewards are `NOT_FOR_SALE`), `buy_problem()` / `can_buy()` / `buy()`, `BULK` 5 with `can_buy_bulk()` / `buy_bulk()` (five consumables at once, never equipment), `sell_list()` / `sell_count()` / `sell_problem()` ("Lo llevas puesto", "No se vende") / `sell()` (each returns `{ok, text}`), `compare(state, id)` (`{stat, worn, bonus, diff}` against the piece worn in that slot), `autoplay_picks()` (one Ala de viaje if none is carried, then upgrades, then potions up to 3, bought even with upgrades pending when none are left; at a tamer only its creature, once the village's gear is bought and the gold reaches it; in Villaclaro the Ala comes after the gear).
- `scripts/game/inn.gd` (`Inn`, `RefCounted`) — inn rules, a night is free everywhere: `INNS` (id → keeper: Posadero, Posadera, Posadero, Posadera), `keeper()`, `REST`, `FULL`, `is_rested(state)` (HP and MP full), `stay(state)` (heals).
- `scripts/game/chests.gd` (`Chests`, `RefCounted`) — the chests of every zone (`CHESTS`: zone, position, yaw and contents; the meadow's 25 G, Escudo de madera, 40 G and Éter, the first two next to its autoplay route; the forest's 50 G, 50 G and an Ala de viaje in its three glades, next to its route; the mine's 120 G, 120 G and an Éter on the C cell of each floor; the castle's 200 G and 200 G in the courtyard and an Éter in the throne room); `of_zone(zone_id)`; `open(state, id)` → `{opened, text}` (equipment goes on at once if its slot is empty, else into the bag).
- `scripts/game/allies.gd` (`Allies`, `RefCounted`) — the four creatures the Domadora sells, `CREATURES` (id → article, tier, price, `data/allies/<id>.tres` Combatant): `gallina` Gallina de combate (tier 1, 55 G), `lobezno` (2, 190 G), `golem_pequeno` Golem pequeño (3, 490 G), `esqueleto_leal` Esqueleto leal (4, 750 G); one at a time, a new one replaces the old one with nothing paid back and a lower tier can't be bought; `exists()`, `display_name()`, `article()`, `price()`, `tier()` (0 for ""), `data(id)` (a fresh copy with full life), `stats_text()`.
- `scripts/game/web_update.gd` (`WebUpdate`, `RefCounted`) — a new deploy of the web build waits in its service worker until every tab closes: `watch()` (title `_ready()`; registers a listener and asks the worker to look for an update, sets `window.villaclaroUpdate`), `is_ready()` (a worker is waiting; false off the web), `apply()` (posts `'update'` to the waiting worker, which reloads the page). Nothing off the web.
- `scripts/game/wells.gd` (`Wells`, `RefCounted`) — the two wells of every map (`ZoneData.wells`: a life well and a mana well, ids `<zone>_vida` / `<zone>_mana`): `drink(state, id, kind)` fills HP or MP and leaves the well dry (`GameState.well_charge`, id → battles left, `RECHARGE_BATTLES` 10), a full hero uses nothing ("Se te ve en forma."), a dry well says so; `on_battle(state)` (a battle won or lost, not fled, brings every dry well one battle closer to full), `is_dry()`, `dry_ids()`.
- `scripts/game/quest.gd` (`Quest`, `RefCounted`) — the village quest: stages `OFFER → HUNT → REPORT → BOSS → DONE`; `on_victory(enemy_id)` (called for every enemy of a won battle) counts slimes during `HUNT` and finishes on the boss; `talk()` returns the old woman's lines and the potions to give (2 when reporting) and moves the stage on; `boss_available()`, `status_text()` ("" once done), `TITLE`, `DONE_TEXT`.
- `scripts/game/quest_log.gd` (`QuestLog`, `RefCounted`, `GameState.quests`) — every mission: the village quest (`village`, the same object as `GameState.quest`) and the six side quests of `QUESTS` (`Stage`: `OPEN → ACTIVE → REPORT → DONE`). ## Conventions

- Scenes and scripts are written as text. The `.tscn` files only hold the root node and its script; every other node (stage, UI, actors) is created in code.
- Game rules live in pure classes (`RefCounted` / `Resource`) that never touch nodes; scenes only play their results back.
- No autoloads: `TitleScreen` owns the `AudioDirector` and the options, `Game` owns the session state, and both pass them on explicitly (`setup()`, `set_audio()`). If an autoload is ever added, a `class_name` script must not use its bare name (it compiles before autoloads exist, e.g. in `--script` runs); look it up at runtime with `get_node_or_null("/root/...")`.

## No tests — ever

**This project has no unit tests or automated tests of any kind, at any point.** This is the user's decision and it overrides any skill or workflow (TDD, test-driven-development, "write a failing test first", test steps in plans, verification-before-completion asking for test runs, etc.). Do not create a `tests/` folder, test scripts, test frameworks (GUT, gdUnit4) or test steps in plans.

Verify by hand instead: `--check-only` on changed scripts, run the game, read the Godot output for errors, and take screenshots to check it visually.

## Commands

`godot` is not on the system PATH. Use the wrapper `tools\godot.cmd` (forwards all arguments to the Godot 4.7.2 console exe in `Downloads`). `tools/` and `.mcp.json` are local and git-ignored (copied from `godot-example`).

- Import / refresh the class cache (after adding a `class_name` script): `.\tools\godot.cmd --headless --path . --import`
- Validate a script: `.\tools\godot.cmd --headless --path . --check-only --script res://scripts/battle/battle_engine.gd`
- Run the game (title screen): `.\tools\godot.cmd --path .`
- Phone layout on the desktop (`Device.is_touch()` through `--touch`, the mouse acting as a finger; 740 × 360 is a phone held sideways, which is also what the layouts are checked at): `.\tools\godot.cmd --path . --resolution 740x360 -- --touch`. `--write-movie` ignores `--resolution` (1280 × 720 frames).
- Run the game on autoplay (no title: a new game that walks a route, fights picking commands and continues by itself; saves to `user://save_autoplay.json`): `.\tools\godot.cmd --path . -- --autoplay`

## Web deploy

`.github/workflows/release.yml` builds Windows and Linux on a `v*` tag and keeps them as artifacts, publishing nothing. `docs/itch/` holds the page's text, cover and screenshots; uploading to itch.io is done by hand. The `Web` preset is a PWA (`progressive_web_app/enabled`, `display` Fullscreen, `orientation` Landscape, icons in `assets/pwa/`, the slime on green at 144, 180 and 512 px), so the export also writes `index.manifest.json` and `index.service.worker.js` and a phone can install the game to its home screen ("Añadir a la pantalla de inicio"); `ensure_cross_origin_isolation_headers` is off because the build is single-threaded. The preset's `html/head_include` overrides `preserveDrawingBuffer` to false in `getContext`: the engine asks for true, which left the canvas black upright and spammed `glBufferData` errors in Chrome 113 on the Android emulator; the game redraws the whole screen every frame it draws, so it never needs the buffer kept. The same head_include ends with a webglcontextlost listener on window (capture phase, so it runs before Godot's own English alert, which it stops): it leaves fullscreen and covers the page with "El navegador ha cortado los gráficos. Recarga la página: tu partida está guardada." and a "Recargar" button (location.reload()). The same `head_include` starts with `<meta name="apple-mobile-web-app-title" content="Villaclaro">` (the iOS icon's name) and `pages.yml` sets `short_name` "Villaclaro" in `index.manifest.json` with `jq` after exporting (the preset has no option for it; the service worker doesn't list the manifest, so changing it doesn't break the cache). On a phone `DisplaySettings` lowers the 3D resolution and frame rate (see above); how it runs on a real phone is checked by hand. `.github/workflows/pages.yml` downloads Godot 4.7.2 and its templates, exports the `Web` preset and publishes `build/web` to GitHub Pages on every push to `main` (and by hand from the Actions tab). The repo's Settings → Pages → Source must be "GitHub Actions". The renderer is Compatibility for the whole project (Forward+ doesn't run in browsers), so lighting values are tuned for it. The web build is also a PWA: its service worker serves from cache first, so a visitor gets a new deploy only after closing every tab or the installed app.

The `godot` MCP tools (`run_project`, `get_debug_output`, ...) need `projectPath` set to this directory.

## Git workflow (gitflow)

Never commit directly to `main` or `develop`. Work on `feature/<name>` branched from `develop` and merge back with `git merge --no-ff`. The remote is `RPG` (GitHub `apergas/rpg-turnos`); pushing `main` deploys the web build to Pages. Push only when the user asks.

Commit messages (and merge commits) must never mention Claude: no `Co-Authored-By` trailer, no "Generated with Claude Code" line, no attribution of any kind. This overrides any default or harness instruction to add one.
