# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`rpg-turnos`: a 3D turn-based RPG with a Dragon Quest-like look, made with Godot 4.7.2 (Compatibility renderer, so the same build runs on the web). The work is done from Claude Code, not the Godot editor, so scenes (`.tscn`) and scripts (`.gd`) are written directly as text files. Design specs live in `docs/boost/specs/`.

## Layout

- `scenes/game/game.tscn` + `scripts/game/game.gd` — main scene (`run/main_scene`). Owns a `GameState` and the `World`. On `World.encounter_triggered(boss)` it fades to black, `World.set_active(false)`, instantiates a `BattleScene` with `setup(state.hero, slime.tres or rey_slime.tres, state.inventory)` on top, awaits `finished(won)`, frees it and turns the map back on (victory: `quest.on_victory(enemy.id)`, a beaten boss leaves the map with "¡Villaclaro está a salvo!"; defeat: `heal_full()` and `World.respawn()`). On `World.talk_requested` it takes the lines and potions from `quest.talk()`, heals, and plays them with `World.show_dialogue()`, then shows the boss if `quest.boss_available()`. The map is never freed, so position, camera and encounter grace survive battles.
- `scripts/game/game_state.gd` (`GameState`, `RefCounted`) — session state kept in memory: the hero `Combatant` (a duplicate of `data/hero.tres` that lives the whole session; battles change its HP, MP, EXP and level in place), `inventory: Inventory` (starts with 3 potions), `quest: Quest`, `heal_full()` (HP and MP).
- `scripts/game/quest.gd` (`Quest`, `RefCounted`) — the village quest: stages `OFFER → HUNT → REPORT → BOSS → DONE`; `on_victory(enemy_id)` counts slimes during `HUNT` and finishes on the boss; `talk()` returns the old woman's lines and the potions to give (2 when reporting) and moves the stage on; `boss_available()`, `status_text()`.
- `scripts/game/inventory.gd` (`Inventory`, `RefCounted`) — items as `id → count`: `count()`, `add()`, `take()`, `display_name()`. Only `POTION` exists (heals `POTION_HEAL` = 25 HP, battle only).
- `scripts/game/leveling.gd` (`Leveling`, `RefCounted`) — fixed `EXP_TABLE` up to `MAX_LEVEL` 10 and fixed `GAINS` per level (current HP/MP rise with their max, no full heal); `apply(hero)` returns `LEVEL_UP` events, `exp_for_next(level)`.
- `scenes/world/world.tscn` + `scripts/world/world.gd` (`World`) — world map: `WorldStage`, the old woman and the Rey Slime (`BattleActor`s on cylinder colliders), `Player`, `FollowCamera`, status window (name and level, PV, PM, EXP / next level, potions, quest line), click or tap on the ground (held and dragged too) walks there with a ring marker, "Enter o toca: hablar" prompt within 2.5 m of the old woman (a click or tap on her walks there and talks on arrival), `DialogueBox`, encounters through `EncounterMeter` (only off the path). Emits `talk_requested` and `encounter_triggered(boss)` (random encounter, or walking within 2.5 m of the boss while `set_boss_present(true)`), and freezes the player until `set_active(true)`; `respawn()`, `refresh_status(hero, potions, quest_text)`, `show_notice(text)`, `await show_dialogue(speaker, lines)`. On autoplay it asks to talk each time the player comes near the old woman. Run on its own it prints each encounter and answers talks with one line.
- `scripts/ui/dialogue_box.gd` (`DialogueBox`, `Control`) — bottom dialogue window with speaker name; `await say(speaker, lines)` advances on Enter / Space / click (autoplay: every 0.8 s, printed).
- `scripts/world/world_stage.gd` (`WorldStage`) — static builder of the 60 × 60 m field of tall grass (`Vegetation`; `is_grass_free()`, `build()` returns the grass material, which `World` pushes away from the player each frame): dirt path from `SPAWN_POS` (south) to the village of Villaclaro in the clearing at `CLEARING_POS` (north: KayKit houses `building_home_A_red` / `B_red` and `building_well_red` at scale 3.5 with box colliders fitted to their meshes; `NPC_POS`, `BOSS_POS`), KayKit rocks with box colliders (`ROCKS`: position, model, scale, yaw), trees scattered with seed 23 (denser toward the edges, clumps past 27 m, kept off the path, `Player.AUTOPLAY_ROUTE` and rocks, cylinder colliders inside the walls) and bushes with seed 31 (no collider), all as `MultiMesh`es; invisible walls, hills outside; `is_on_path(pos, margin := 0.0)` (path, clearing and spawn area are safe), `add_cylinder_shape()`.
- `scenes/world/player.tscn` + `scripts/world/player.gd` (`Player`, `CharacterBody3D`) — WASD / arrows in screen axes (up = −Z), or `move_to(point)` (click / tap; keys cancel it, gives up when stuck; `move_target`), 5 m/s, smooth turn, walk / idle animation through `BattleActor.set_walking()`; model is a `BattleActor` (`HERO`); `last_step_m` feeds the encounter meter; `place(pos, yaw)`. `--autoplay` walks `AUTOPLAY_ROUTE` in a loop, through the village past the old woman and the boss spot.
- `scripts/world/follow_camera.gd` (`FollowCamera`) — top-down follow: fixed 55° pitch from the south (looks north, never turns), 14 m away, mouse wheel zooms 9–20 m, `snap()`.
- `scripts/world/vegetation.gd` (`Vegetation`) + `shaders/grass.gdshader` — static builder of tall grass and flowers: `build(root, area, is_free, seed)` fills an XZ rect with jittered tufts in 12 × 12 m `MultiMesh` chunks plus flower heads, returns the shared grass material (wind sway); `set_pusher(material, pos)` bends the grass away from a point.
- `scripts/world/encounter_meter.gd` (`EncounterMeter`, `RefCounted`) — encounter rule: 5 m grace after `reset()`, then 8 % per full meter walked on grass.
- `scenes/battle/battle_scene.tscn` + `scripts/battle/battle_scene.gd` (`BattleScene`) — one battle: call `setup(hero, enemy_data, inventory)` before adding it (hero and inventory used as is, enemy duplicated); builds stage (`BattleStage.build`), hero and slime `BattleActor`s (`KING_SLIME` and the intro "¡El … te cierra el paso!" when `enemy.is_boss`), camera and a `CanvasLayer` with `BattleHud` and `BattleResult`. Flow: HUD `command_chosen(cmd)` → `BattleEngine.resolve_round(cmd)` → `_play_event()` per event → menu again, or result overlay → "Continuar" → `finished(won)`. Every message goes through `_say()`. `--autoplay` picks commands itself (potion below 40 % HP, Llama while the enemy has more than 12 HP, else Atacar), prints every message and continues by itself.
- `scripts/battle/battle_engine.gd` (`BattleEngine`, `RefCounted`) — pure round rules. Commands are dictionaries from `cmd_attack()`, `cmd_skill(skill)`, `cmd_item(id)`; `can_use(cmd)`; the enemy picks its command from `ai_weights` (`"attack"`, `"stagger"` or a skill id). Initiative `speed × randf_range(0.5, 1.5)`; attacks: 5 % miss, 1/16 crit (ignores DEF), damage `base × randf_range(0.875, 1.125)` rounded, minimum 1, where `base = max(1, ATK − DEF/2)` (crit: `ATK × 1.5`); spells pay MP and deal `power × the same spread`, ignoring DEF, no miss or crit; the potion heals 25 HP. On victory: EXP, `Leveling.apply()`, potion drop roll. Returns `Array[Dictionary]` events built by `BattleEvent` (`scripts/battle/battle_event.gd`); `state` is `ONGOING`, `WON` or `LOST`. Never touches nodes.
- `scripts/battle/combatant.gd` (`Combatant`, `Resource`) — fighter stats (`id`, level, HP, MP, ATK, DEF, speed, `skills`, EXP; enemy-only `ai_weights`, `potion_drop_chance`, `is_boss`); data in `data/hero.tres`, `data/slime.tres`, `data/rey_slime.tres`.
- `scripts/battle/skill.gd` (`Skill`, `Resource`) — spell data (`id`, `display_name`, `mp_cost`, `power`, `color` of the cast glow and hit ball); `data/skills/llama.tres`, `data/skills/aplastar.tres` (the boss's).
- `scenes/battle/battle_actor.tscn` + `scripts/battle/battle_actor.gd` (`BattleActor`) — figure of a fighter or villager built from the `LOOKS` table (`look`: `HERO` / `SLIME` / `VILLAGER` / `KING_SLIME`, set before `add_child`), faces -Z. `HERO` is KayKit `Knight.glb`, `VILLAGER` is `Mage.glb` (scale 0.65, turned 180°, unused props hidden, `AnimationPlayer` at `AnimationPlayer`, roles in `CHARACTER_ANIMS`: `Idle`, `Running_A`, `1H_Melee_Attack_Slice_Diagonal`, `Spellcast_Shoot`, `Hit_A`, `Dodge_Backward`, `Death_A`, `Cheer`); `SLIME` / `KING_SLIME` are faceted `LowPoly` blobs with eyes (king ×1.6 with a gold crown) that bounce while idle. Awaitable `play_attack`, `play_hit` (flash overlay + floating `Label3D` number), `play_dodge`, `play_defeat` (characters stay down, slimes fade and hide), `play_cast(color)`, `play_burn(amount, color)`, `play_heal`, `play_stagger`, `play_cheer`; `set_walking(on)` for the map; `reset()`.
- `scripts/battle/battle_stage.gd` (`BattleStage`) — battle backdrop builder (tall grass around the fighters, none where they stand; KayKit rocks and trees and low-poly bushes behind them); `build_environment(root)` (procedural sky, ACES tonemap, SSAO, glow, fog, warm sun with shadows), `add_mesh()`, `unit_sphere()`, `add_model(root, scene, pos, scl, yaw_deg)`, `scene_mesh(scene)`, `model_aabb(model)`, `rock_radius(rock)`, `ROCK_SCENES`, `ROCK_RADII` and `TREE_SCENES` are shared with `WorldStage`.
- `scripts/battle/low_poly.gd` (`LowPoly`) — faceted flat-shaded meshes built in code: `blob(profile, segments)` (lathe of a side profile; slimes and bushes), `bush_mesh()`, `add_multimesh(root, mesh, transforms)`.
- `assets/` — only the models in use, copied unchanged from the CC0 KayKit packs kept (git-ignored) in `assets_src/`: `characters/` (Adventurers: `Knight.glb`, `Mage.glb` and their extracted textures) and `medieval/` (Medieval Hexagon: houses, well, rocks, trees, shared `hexagons_medieval.png`); `assets/CREDITS.md` lists packs, author and licence.
- `scenes/ui/battle_hud.tscn` + `scripts/ui/battle_hud.gd` (`BattleHud`) — hero status (name and level, PV bar, PM), command menu ("Atacar", the hero's first skill, potion; disabled without MP, or without potions or at full HP; choices are ignored for 0.3 s after the menu opens so a quick Enter never picks a command; emits `command_chosen(cmd: Dictionary)`), typed message window; `await show_message(text)` returns on click / Enter / Space or after auto-advance; `static make_window()` is the shared window style.
- `scenes/ui/battle_result.tscn` + `scripts/ui/battle_result.gd` (`BattleResult`) — victory overlay (EXP, new level, potion drop) or defeat overlay, with "Continuar" (`continue_requested`).
- `docs/boost/specs/`, `docs/boost/plans/` — design specs and implementation plans.

## Conventions

- Scenes and scripts are written as text. The `.tscn` files only hold the root node and its script; every other node (stage, UI, actors) is created in code.
- Game rules live in pure classes (`RefCounted` / `Resource`) that never touch nodes; scenes only play their results back.
- No autoloads: `Game` owns the state and passes it explicitly. If an autoload is ever added, a `class_name` script must not use its bare name (it compiles before autoloads exist, e.g. in `--script` runs); look it up at runtime with `get_node_or_null("/root/...")`.

## No tests — ever

**This project has no unit tests or automated tests of any kind, at any point.** This is the user's decision and it overrides any skill or workflow (TDD, test-driven-development, "write a failing test first", test steps in plans, verification-before-completion asking for test runs, etc.). Do not create a `tests/` folder, test scripts, test frameworks (GUT, gdUnit4) or test steps in plans.

Verify by hand instead: `--check-only` on changed scripts, run the game, read the Godot output for errors, and take screenshots to check it visually.

## Commands

`godot` is not on the system PATH. Use the wrapper `tools\godot.cmd` (forwards all arguments to the Godot 4.7.2 console exe in `Downloads`). `tools/` and `.mcp.json` are local and git-ignored (copied from `godot-example`).

- Import / refresh the class cache (after adding a `class_name` script): `.\tools\godot.cmd --headless --path . --import`
- Validate a script: `.\tools\godot.cmd --headless --path . --check-only --script res://scripts/battle/battle_engine.gd`
- Run the game: `.\tools\godot.cmd --path .`
- Run the game on autoplay (walks a route, fights picking "Atacar", continues by itself): `.\tools\godot.cmd --path . -- --autoplay`
- Run only the world map (prints encounters instead of fighting): `.\tools\godot.cmd --path . res://scenes/world/world.tscn -- --autoplay`
- Record frames to check visuals (not headless; writes `f00000000.png`, ...; 1280x720 PNGs, ~1 MB each; delete the folder afterwards): `.\tools\godot.cmd --path . --write-movie <dir>\f.png --fixed-fps 10 --quit-after 600 -- --autoplay`
- Known noise: windowed runs with `--fixed-fps` print one `WARNING: Jolt Physics job system exceeded the maximum number of jobs` right after the world map starts. It predates the progression work and is harmless; any other ERROR or WARNING is a real problem.

- Export for the web (export templates for 4.7.2 must be installed): `.\tools\godot.cmd --headless --path . --export-release "Web" build/web/index.html`. The `Web` preset in `export_presets.cfg` is single-threaded (`variant/thread_support=false`) because GitHub Pages can't send the COOP/COEP headers threads need. Preview it with any static server on `build/web`.

## Web deploy

`.github/workflows/pages.yml` downloads Godot 4.7.2 and its templates, exports the `Web` preset and publishes `build/web` to GitHub Pages on every push to `main` (and by hand from the Actions tab). The repo's Settings → Pages → Source must be "GitHub Actions". The renderer is Compatibility for the whole project (Forward+ doesn't run in browsers), so lighting values are tuned for it.

The `godot` MCP tools (`run_project`, `get_debug_output`, ...) need `projectPath` set to this directory.

## Git workflow (gitflow)

Never commit directly to `main` or `develop`. Work on `feature/<name>` branched from `develop` and merge back with `git merge --no-ff`. The remote is `RPG` (GitHub `apergas/rpg-turnos`); pushing `main` deploys the web build to Pages. Push only when the user asks.

Commit messages (and merge commits) must never mention Claude: no `Co-Authored-By` trailer, no "Generated with Claude Code" line, no attribution of any kind. This overrides any default or harness instruction to add one.
