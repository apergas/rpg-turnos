# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`rpg-turnos`: a 3D turn-based RPG with a Dragon Quest-like look, made with Godot 4.7.2 (Compatibility renderer, so the same build runs on the web). The work is done from Claude Code, not the Godot editor, so scenes (`.tscn`) and scripts (`.gd`) are written directly as text files. Design specs live in `docs/boost/specs/`.

## Layout

- `scenes/title/title.tscn` + `scripts/title/title_screen.gd` (`TitleScreen`) — main scene (`run/main_scene`). Loads the options (`SaveStore.load_options()`), owns the only `AudioDirector`, shows "Villaclaro" over the meadow (`WorldStage.build`) seen from a slowly drifting top-down camera, with Nueva partida / Continuar (disabled without a save) / Opciones (`OptionsPanel`); creates a `Game` with `setup(audio, options, save)` (empty save = new game) and frees it on `quit_to_title` (unpausing the tree). If the save file exists but can't be read, `_load_save()` passes a marker that `Game` rejects: it starts a new game with the notice "No se pudo cargar la partida. Empiezas de nuevo.". `--autoplay` skips the title and starts a new game; with `--autoplay-save` the first `quit_to_title` loads the save at once.
- `scenes/game/game.tscn` + `scripts/game/game.gd` (`Game`) — one play session, created by `TitleScreen` (run on its own it makes its own `AudioDirector` and default options). Owns a `GameState` and the `World`. On `World.encounter_triggered(boss)` it fades to black, `World.set_active(false)`, instantiates a `BattleScene` with `setup(state.hero, enemies, state.inventory)` on top (`enemies` from `EncounterTable.pick(ZONE, player position, rng)`, or `[rey_slime.tres]`), awaits `finished(outcome)` (`BattleEngine.State`), frees it and turns the map back on (victory: `state.gold += engine.gold_won` and `quest.on_victory(id)` for every enemy, a beaten boss leaves the map with "¡Villaclaro está a salvo!"; fled: nothing; defeat: `heal_full()` and `World.respawn()`). `_update_boss()` shows the Rey Slime while `quest.boss_available()` (on autoplay only from `AUTOPLAY_BOSS_LEVEL` 5). On `World.talk_requested` it takes the lines and potions from `quest.talk()`, heals, and plays them with `World.show_dialogue()`, then shows the boss if `quest.boss_available()`. The map is never freed, so position, camera and encounter grace survive battles. Music: map, village (`World.village_changed`), battle or boss (the battle plays victory / defeat). Autosaves (`SaveData.from_state()` → `SaveStore.save_game()`) after each talk and each won battle ("Partida guardada.", except after the boss, which shows the safe-village notice instead), never in battle; a save is loaded with `SaveData.apply()` and `World.place_player()`; counts `play_time` (stops while paused). Owns the `PauseMenu` (`available` only on the map with nothing else going on) and answers its `save_requested` / `title_requested` (the latter sets a `_leaving` guard, marks the game busy, hides the menu and ignores input, so the frozen map can't walk or roll an encounter during the fade); emits `quit_to_title`. `--autoplay --autoplay-save` prints `Guardado: <json>` / `Cargado: <json>`; `--autoplay --autoplay-menu` tours the pause menu 1 s into the map.
- `scripts/game/game_state.gd` (`GameState`, `RefCounted`) — session state kept in memory: the hero `Combatant` (a duplicate of `data/hero.tres` that lives the whole session; battles change its HP, MP, EXP and level in place), `inventory: Inventory` (starts with 3 potions), `quest: Quest`, `gold` (won in battle, saved; shops come in phase 4), `heal_full()` (HP and MP), `use_item(id)` (outside battle, `Inventory.use()`). The hero gets its own `skills` array, so learning a spell never touches `hero.tres`.
- `scripts/game/quest.gd` (`Quest`, `RefCounted`) — the village quest: stages `OFFER → HUNT → REPORT → BOSS → DONE`; `on_victory(enemy_id)` (called for every enemy of a won battle) counts slimes during `HUNT` and finishes on the boss; `talk()` returns the old woman's lines and the potions to give (2 when reporting) and moves the stage on; `boss_available()`, `status_text()`.
- `scripts/game/inventory.gd` (`Inventory`, `RefCounted`) — items as `id → count`: `count()`, `add()`, `take()`, `to_dict()`, `set_items()`. `ITEMS` table (name, article, effect `hp` / `mp` / `cure`, value, price, usable in `battle` / `field`) in `IDS` order: `POTION` (30 PV, 8 G), `ETHER` (15 PM, 30 G), `ANTIDOTE` (cures poison, 10 G, battle only). `problem(id, combatant, in_battle)` says why it can't be used now ("" if it can: "PV al máximo", "Solo en combate", ...); `use(id, combatant, in_battle)` → `{used, effect, amount, status, reason}`, shared by `BattleEngine` and the pause menu; `display_name()`, `article()`.
- `scripts/game/leveling.gd` (`Leveling`, `RefCounted`) — fixed `EXP_TABLE` up to `MAX_LEVEL` 20 (12, 35, 62, 96, 180, ... 3600) and fixed `GAINS` per level (PV +6, PM +3, ATK +2, DEF +1, VEL +1; current HP/MP rise with their max, no full heal); `apply(hero)` returns `LEVEL_UP` events, each followed by a `LEARN` event when the hero's `learn` table teaches a spell at that level; `sync_skills(hero)` (after loading), `exp_for_next(level)`.
- `scripts/game/game_options.gd` (`GameOptions`, `RefCounted`) — music and effects volume (0..1, defaults 0.7 / 0.8) and `text_speed` (`SLOW` / `NORMAL` / `FAST`, `char_time()` 0.05 / 0.025 / 0.008 s per character); `to_dict()`, `from_dict()`.
- `scripts/game/save_data.gd` (`SaveData`, `RefCounted`) — pure: `from_state(state, player_pos, play_time)` → `Dictionary` (`version` 2, hero level / EXP / HP / MP / base stats, inventory, quest stage and kills, gold, position `[x, z]`, play time; version 1 saves are refused); `apply(state, data)` → `{valid, position, play_time}` (state untouched when not valid; JSON numbers come back as floats; spells come back with `Leveling.sync_skills()`); `is_valid(data)`.
- `scripts/game/save_store.gd` (`SaveStore`, `RefCounted`) — JSON files: `user://save.json` (`user://save_autoplay.json` on `--autoplay` runs) and `user://options.json`; `has_save()`, `save_game(data)`, `load_game()` (empty if missing or broken), `save_options(options)`, `load_options()`. On desktop `user://` is `%APPDATA%\Godot\app_userdata\rpg-turnos\`; on the web it is IndexedDB.
- `scenes/world/world.tscn` + `scripts/world/world.gd` (`World`) — world map: `WorldStage`, the old woman and the Rey Slime (`BattleActor`s on cylinder colliders), `Player`, `FollowCamera`, status window (name and level, PV, PM, EXP / next level, potions, quest line), click or tap on the ground (held and dragged too) walks there with a ring marker, "Enter o toca: hablar" prompt within 2.5 m of the old woman (a click or tap on her walks there and talks on arrival), `DialogueBox`, encounters through `EncounterMeter` (only off the path). Emits `talk_requested`, `village_changed(inside)` (within `CLEARING_RADIUS` of `CLEARING_POS`) and `encounter_triggered(boss)` (random encounter, or walking within 2.5 m of the boss while `set_boss_present(true)`), and freezes the player until `set_active(true)`; `respawn()`, `place_player(pos)`, `player_position()`, `in_village()`, `set_audio(audio)` (footstep every 1.6 m, encounter and dialogue sounds), `refresh_status(hero, potions, quest_text)`, `show_notice(text)`, `await show_dialogue(speaker, lines)`. On autoplay it asks to talk each time the player comes near the old woman. Run on its own it prints each encounter and answers talks with one line.
- `scripts/ui/dialogue_box.gd` (`DialogueBox`, `Control`) — bottom dialogue window with speaker name; `await say(speaker, lines)` advances on Enter / Space / click (autoplay: every 0.8 s, printed); `set_audio()` plays the dialogue sound when it opens.
- `scripts/world/world_stage.gd` (`WorldStage`) — static builder of the 60 × 60 m field of tall grass (`Vegetation`; `is_grass_free()`, `build()` returns the grass material, which `World` pushes away from the player each frame): dirt path from `SPAWN_POS` (south) to the village of Villaclaro in the clearing at `CLEARING_POS` (north: KayKit houses `building_home_A_red` / `B_red` and `building_well_red` at scale 3.5 with box colliders fitted to their meshes; `NPC_POS`, `BOSS_POS`), KayKit rocks with box colliders (`ROCKS`: position, model, scale, yaw), trees scattered with seed 23 (denser toward the edges, clumps past 27 m, kept off the path, `Player.AUTOPLAY_ROUTE` and rocks, cylinder colliders inside the walls) and bushes with seed 31 (no collider), the trees and bushes each drawn as a `MultiMesh` (houses, well and rocks are individual model instances); invisible walls, hills outside; `is_on_path(pos, margin := 0.0)` (path, clearing and spawn area are safe), `add_cylinder_shape()`.
- `scenes/world/player.tscn` + `scripts/world/player.gd` (`Player`, `CharacterBody3D`) — WASD / arrows in screen axes (up = −Z), or `move_to(point)` (click / tap; keys cancel it, gives up when stuck; `move_target`), 5 m/s, smooth turn, walk / idle animation through `BattleActor.set_walking()`; model is a `BattleActor` (`HERO`); `last_step_m` feeds the encounter meter; `place(pos, yaw)`. `--autoplay` walks `AUTOPLAY_ROUTE` in a loop, through the village past the old woman and the boss spot.
- `scripts/world/follow_camera.gd` (`FollowCamera`) — top-down follow: fixed 55° pitch from the south (looks north, never turns), 14 m away, mouse wheel zooms 9–20 m, `snap()`.
- `scripts/world/vegetation.gd` (`Vegetation`) + `shaders/grass.gdshader` — static builder of tall grass and flowers: `build(root, area, is_free, seed)` fills an XZ rect with jittered tufts in 12 × 12 m `MultiMesh` chunks plus flower heads, returns the shared grass material (wind sway); `set_pusher(material, pos)` bends the grass away from a point.
- `scripts/world/encounter_meter.gd` (`EncounterMeter`, `RefCounted`) — encounter rule: 15 m grace after `reset()`, then 0.6 % per full meter walked on grass (a battle every ~180 m).
- `scripts/world/encounter_table.gd` (`EncounterTable`, `RefCounted`) — which enemies come: `ZONES` (zone 1: `[Slime]`, `[Slime]`, `[Murciélago]`, `[Seta]`, `[Slime, Slime]`, `[Slime, Murciélago]`, same weight) and `START_FORMATIONS` (`[Slime]`, `[Slime, Slime]`) within `START_RADIUS` 20 m of `WorldStage.SPAWN_POS`; `pick(zone, pos, rng)`, `near_start(pos)`.
- `scenes/battle/battle_scene.tscn` + `scripts/battle/battle_scene.gd` (`BattleScene`) — one battle against one or two enemies: call `setup(hero, enemies: Array[Combatant], inventory)`, `set_audio(audio)` and set `char_time` before adding it (hero and inventory used as is, enemies duplicated, two with the same name become "Slime A" / "Slime B"; without audio it is silent); builds stage (`BattleStage.build`), the hero and one `BattleActor` per enemy (`LOOKS` by data id; a pair stands left and right of `ENEMY_POS`, `PAIR_OFFSET` 1.5 m), camera, the blinking yellow target arrow (`_show_arrow(index)`, from `BattleHud.target_changed`; `_pick_target(screen)` turns clicks into enemies) and a `CanvasLayer` with `BattleHud` and `BattleResult`. Flow: HUD `command_chosen(cmd)` (asleep: `cmd_none()`) → `BattleEngine.resolve_round(cmd)` → `_play_event()` per event → menu again, or result overlay → "Continuar" → `finished(outcome)` (fled: at once). Every message goes through `_say()` (`_the()` / `_ending()` give "el / la" and "-o / -a" from `Combatant.female`). A call for help moves the caller to the left and grows the helper on the right. Effects: hit, crit, miss, fire on spell casts, potion, heal, level up, accept on "Continuar"; music: victory fanfare on the VICTORY event, defeat when the hero falls. `--autoplay`: `BattleAutoplay` picks (shown with `BattleHud.demo()`), flees from every 5th normal battle and defends in the first round of the 2nd, 7th...; prints every message and continues by itself. Run on its own: a poisoned Lv 3 hero with 3 potions and an antidote against a Slime and a Murciélago, quits at the end ("Fin del combate (estado N)").
- `scripts/battle/battle_engine.gd` (`BattleEngine`, `RefCounted`) — pure round rules for the hero against `enemies: Array[Combatant]` (fighters are ints: `BattleEvent.HERO` = −1 or an enemy index). Commands are dictionaries from `cmd_attack(target)`, `cmd_skill(skill, target)`, `cmd_item(id)`, `cmd_defend()`, `cmd_flee()`, `cmd_none()`; `problem(cmd)` (why not: "Faltan PM", "Silencio", item reasons), `can_use(cmd)`, `alive_enemies()`, `has_boss()`, `flee_chance()`. Each enemy picks when its turn comes, from `ai_weights` (`"attack"`, `"stagger"` or a skill id), or calls its `help` once below 50 % HP while fewer than `MAX_ENEMIES` 2 stand. Initiative `speed × randf_range(0.5, 1.5)` (defending or fleeing, the hero goes first); attacks: 5 % miss, 1/16 crit (ignores DEF), damage `base × randf_range(0.875, 1.125)` rounded, minimum 1, where `base = max(1, total ATK − total DEF/2)` (crit: `ATK × 1.5`), may cause the attacker's `attack_status`; spells pay MP: damage `power × the same spread × 1.5 weak / 0.5 resist`, ignoring DEF, no miss or crit, may cause their status; heals restore `power`. Defend halves the damage taken that round (rounded up, min 1). Flee: `clamp(0.5 + (hero VEL − mean enemy VEL) × 0.05, 0.2, 0.95)`; against a boss only `NO_ESCAPE`, no turn passes. Status (`Combatant.status`): poison 8 % max HP at the end of each round; sleep loses the turn, 50 % to wake at the end of each round, damage wakes; silence 3 rounds without spells; all cleared when the battle ends. On victory: `exp_won`, `gold_won`, `Leveling.apply()`, each enemy's `drops` rolls (`drops_won`). Returns `Array[Dictionary]` events built by `BattleEvent` (`scripts/battle/battle_event.gd`); `state` is `ONGOING`, `WON`, `LOST` or `FLED`. Never touches nodes.
- `scripts/battle/battle_autoplay.gd` (`BattleAutoplay`, `RefCounted`) — pure command picker for `--autoplay` and balance checks: below 40 % HP heals (Curar, else potion), with no heal defends below 25 % (never twice in a row); antidote when poisoned, ether when MP can't pay a heal; otherwise aims at the weakest enemy and casts the spell that hurts most (weaknesses count) only when it beats an attack by ×1.5, keeping MP for two heals. `choose(engine)`.
- `scripts/battle/combatant.gd` (`Combatant`, `Resource`) — fighter stats (`id`, `female`, level, HP, MP, base `attack` / `defense` plus hero-only `equip_attack` / `equip_defense` (Palo +2, Ropa +2 until phase 4; `total_attack()` / `total_defense()`), speed, `skills`, hero-only `learn` (level → Skill), EXP; enemy-only `exp_reward`, `gold_reward`, `ai_weights`, `weak` / `resist` (elements), `drops` (item id → chance), `attack_status` / `attack_status_chance`, `help` (Combatant it calls), `is_boss`); battle-only `status` (status → rounds, −1 until cured). Data in `data/hero.tres`, `data/slime.tres`, `data/bat.tres` (Murciélago), `data/mushroom.tres` (Seta saltarina), `data/rey_slime.tres`.
- `scripts/battle/skill.gd` (`Skill`, `Resource`) — spell data (`id`, `display_name`, `mp_cost`, `power`, `color` of the cast glow and hit ball, `element` `fire` / `ice` / `thunder` / "", `kind` `damage` / `heal` / `status`, `targets` `one` / `all`, `status`, `status_chance`; `needs_target()`); `data/skills/`: `llama`, `curar`, `llamarada`, `rayo`, `curar_mas` (the hero's), `aplastar` (Rey Slime), `esporas` (Seta: sleep 30 %).
- `scenes/battle/battle_actor.tscn` + `scripts/battle/battle_actor.gd` (`BattleActor`) — figure of a fighter or villager built from the `LOOKS` table (`look`: `HERO` / `SLIME` / `VILLAGER` / `KING_SLIME` / `BAT` / `MUSHROOM`, set before `add_child`), faces -Z. `HERO` is KayKit `Knight.glb`, `VILLAGER` is `Mage.glb` (scale 0.65, turned 180°, unused props hidden, `AnimationPlayer` at `AnimationPlayer`, roles in `CHARACTER_ANIMS`: `Idle`, `Running_A`, `1H_Melee_Attack_Slice_Diagonal`, `Spellcast_Shoot`, `Hit_A`, `Dodge_Backward`, `Death_A`, `Cheer`); `SLIME` / `KING_SLIME` are faceted `LowPoly` blobs with eyes (king ×1.6 with a gold crown) that bounce while idle; `BAT` hovers at 1.1 m flapping two box wings; `MUSHROOM` is a stem with eyes and a spotted hemisphere cap (×1.4) that bounces. Awaitable `play_attack`, `play_hit(amount, crit, tag)` (flash overlay + floating `Label3D` number, `tag` "¡Débil!" / "¡Resiste!" under it), `play_dodge`, `play_defeat` (characters stay down, the rest fade and hide), `play_cast(color)`, `play_burn(amount, color, tag)`, `play_heal(amount, color)`, `play_status(color, amount)`, `play_appear()`, `play_stagger`, `play_cheer`; `top_height()`; `set_walking(on)` for the map; `reset()`.
- `scripts/battle/battle_stage.gd` (`BattleStage`) — battle backdrop builder (tall grass around the fighters, none where they stand; KayKit rocks and trees and low-poly bushes around them); `build_environment(root)` (procedural sky, ACES tonemap, SSAO, glow, fog, warm sun with shadows), `add_mesh()`, `unit_sphere()`, `add_model(root, scene, pos, scl, yaw_deg)`, `scene_mesh(scene)`, `model_aabb(model)`, `rock_radius(rock)`, `ROCK_SCENES`, `ROCK_RADII` and `TREE_SCENES` are shared with `WorldStage`.
- `scripts/battle/low_poly.gd` (`LowPoly`) — faceted flat-shaded meshes built in code: `blob(profile, segments)` (lathe of a side profile; slimes and bushes), `bush_mesh()`, `add_multimesh(root, mesh, transforms)`.
- `assets/` — only the models in use, copied unchanged from the CC0 KayKit packs kept (git-ignored) in `assets_src/`: `characters/` (Adventurers: `Knight.glb`, `Mage.glb` and their extracted textures) and `medieval/` (Medieval Hexagon: houses, well, rocks, trees, shared `hexagons_medieval.png`); `assets/CREDITS.md` lists packs, author and licence.
- `scenes/ui/battle_hud.tscn` + `scripts/ui/battle_hud.gd` (`BattleHud`) — `set_engine(engine)`; hero status (name and level, PV with status badges Veneno / Sueño / Silencio, PV bar, PM; `update_status()`), command window (`MENU_WIDTH` 340) with pages `MAIN` (Atacar · Hechizos · Objetos · Defender · Huir), `SPELLS`, `ITEMS` (rows that can't be used are grey with the reason, e.g. "Poción ×3  (PV al máximo)") and `TARGET` (with two enemies standing, Atacar and one-target spells ask "¿A quién?" and emit `target_changed(index)`, −1 hides the arrow; `pick_target: Callable` maps clicks to enemies). Keys are read in `_input()`: W / S or ↑ / ↓ move, A / D or ← / → aim, Enter / Space / E accept, Esc / Q / Backspace / X go back; a click on an enemy aims, a second click confirms, a click elsewhere goes back. Choices are ignored for 0.3 s after the menu opens so a quick Enter never picks a command; emits `command_chosen(cmd: Dictionary)`. `await demo(cmd)` walks the menus to cmd (autoplay). Typed message window (`char_time` seconds per character); `await show_message(text)` returns on click / Enter / Space / E or after auto-advance; `set_audio()` adds cursor, accept and cancel sounds; `static make_window()` is the shared window style.
- `scenes/ui/battle_result.tscn` + `scripts/ui/battle_result.gd` (`BattleResult`) — victory overlay (EXP, new level, gold, items left) or defeat overlay, with "Continuar" (`continue_requested`).
- `scripts/ui/options_panel.gd` (`OptionsPanel`, `VBoxContainer`) — music and effects sliders (0-100 % in steps of 10) and text speed (Lenta / Normal / Rápida), applied at once; `setup(options, audio)`, `focus_first()`, `back()` (saves the options, emits `closed`). Used by the title and the pause menu.
- `scripts/ui/pause_menu.gd` (`PauseMenu`, `Control`, `PROCESS_MODE_ALWAYS`) — Esc / P or the ☰ button (top right, three `ColorRect` bars) open it while `available`; sets `get_tree().paused`. Pages: main (Estado, Objetos, Guardar, Opciones, Volver al título, Cerrar), Estado (stats, gold, spells), Objetos ("Usar" on every item; greyed with the reason when it can't be used outside battle now), Opciones (`OptionsPanel`), confirmation before the title. Signals `save_requested` (answered with `show_save_result(ok)`), `title_requested`, `state_changed`; `tour()` for `--autoplay-menu`.
- `scripts/audio/music_library.gd` (`MusicLibrary`) — original tracks as note tables (`TRACKS`: bpm, loop, lead duty, bars of tokens like `"F#5/4"` = note / length in sixteenths, `r` rest, drums `k` / `s` / `h`): title, map, village (waltz), battle, boss loop; victory and defeat don't. `build(id)` synthesizes square lead, triangle bass and noise drums into a cached `AudioStreamWAV` (22050 Hz, 16-bit mono, `LOOP_FORWARD` over the whole track); `to_stream()`, `peak()`, `clear_cache()`.
- `scripts/audio/sfx_library.gd` (`SfxLibrary`) — sfxr-style effects as parameter dictionaries (`SOUNDS`: wave, pitch slide or notes, time, volume, decay); `build(id)` cached; `clear_cache()`.
- `scripts/audio/audio_director.gd` (`AudioDirector`, `Node`, `PROCESS_MODE_ALWAYS`) — not an autoload; two music players with a 0.5 s cross-fade (`play_music(id)`, `stop_music()`), 6 effect players (`play_sfx(id)`), `set_volumes(music, sfx)`. Muted on autoplay (prints `Música: <id>`); headless and `--write-movie` runs never call `play()` (their audio drivers would leak the playbacks at exit). Empties the caches when it leaves the tree.
- `docs/boost/specs/`, `docs/boost/plans/` — design specs and implementation plans.

## Conventions

- Scenes and scripts are written as text. The `.tscn` files only hold the root node and its script; every other node (stage, UI, actors) is created in code.
- Game rules live in pure classes (`RefCounted` / `Resource`) that never touch nodes; scenes only play their results back.
- No autoloads: `TitleScreen` owns the `AudioDirector` and the options, `Game` owns the session state, and both pass them on explicitly (`setup()`, `set_audio()`). If an autoload is ever added, a `class_name` script must not use its bare name (it compiles before autoloads exist, e.g. in `--script` runs); look it up at runtime with `get_node_or_null("/root/...")`.

## No tests — ever

**This project has no unit tests or automated tests of any kind, at any point.** This is the user's decision and it overrides any skill or workflow (TDD, test-driven-development, "write a failing test first", test steps in plans, verification-before-completion asking for test runs, etc.). Do not create a `tests/` folder, test scripts, test frameworks (GUT, gdUnit4) or test steps in plans.

Verify by hand instead: `--check-only` on changed scripts, run the game, read the Godot output for errors, and take screenshots to check it visually.

## Commands

`godot` is not on the system PATH. Use the wrapper `tools\godot.cmd` (forwards all arguments to the Godot 4.7.2 console exe in `Downloads`). `tools/` and `.mcp.json` are local and git-ignored (copied from `godot-example`).

- Import / refresh the class cache (after adding a `class_name` script): `.\tools\godot.cmd --headless --path . --import`
- Validate a script: `.\tools\godot.cmd --headless --path . --check-only --script res://scripts/battle/battle_engine.gd`
- Run the game (title screen): `.\tools\godot.cmd --path .`
- Run the game on autoplay (no title: a new game that walks a route, fights picking commands and continues by itself; saves to `user://save_autoplay.json`): `.\tools\godot.cmd --path . -- --autoplay`
- Whole quest on autoplay, headless (about a minute; the Rey Slime comes out at Lv 5; ends with `Misión cumplida`): `.\tools\godot.cmd --headless --path . --fixed-fps 10 --quit-after 60000 -- --autoplay`
- One test battle (poisoned Lv 3 hero against a Slime and a Murciélago; quits when it ends; play it with the keyboard or the mouse, or add `-- --autoplay`): `.\tools\godot.cmd --path . res://scenes/battle/battle_scene.tscn`
- Save round trip: `.\tools\godot.cmd --headless --path . --fixed-fps 10 --quit-after 6000 -- --autoplay --autoplay-save` (the `Guardado:` and `Cargado:` JSON lines must be identical). Delete `%APPDATA%\Godot\app_userdata\rpg-turnos\save_autoplay.json` afterwards.
- Pause menu frames: `.\tools\godot.cmd --path . --write-movie <dir>\f.png --fixed-fps 10 --quit-after 110 -- --autoplay --autoplay-menu` (☰ shows after MENU_TOUR_DELAY 1.0 s, then the main page, Estado, Objetos and Opciones appear every TOUR_STEP 1.5 s).
- Run one session without the title: `.\tools\godot.cmd --path . res://scenes/game/game.tscn -- --autoplay`
- Run only the world map (prints encounters instead of fighting): `.\tools\godot.cmd --path . res://scenes/world/world.tscn -- --autoplay`
- Record frames to check visuals (not headless; writes `f00000000.png`, ...; 1280x720 PNGs, ~1 MB each; delete the folder afterwards): `.\tools\godot.cmd --path . --write-movie <dir>\f.png --fixed-fps 10 --quit-after 600 -- --autoplay`
- Known noise: runs with `--fixed-fps` (headless or windowed) may print one `WARNING: Jolt Physics job system exceeded the maximum number of jobs` after the world map starts. It predates the progression work and is harmless; any other ERROR or WARNING is a real problem.

- Export for the web (export templates for 4.7.2 must be installed): `.\tools\godot.cmd --headless --path . --export-release "Web" build/web/index.html`. The `Web` preset in `export_presets.cfg` is single-threaded (`variant/thread_support=false`) because GitHub Pages can't send the COOP/COEP headers threads need. Preview it with any static server on `build/web`.

## Web deploy

`.github/workflows/pages.yml` downloads Godot 4.7.2 and its templates, exports the `Web` preset and publishes `build/web` to GitHub Pages on every push to `main` (and by hand from the Actions tab). The repo's Settings → Pages → Source must be "GitHub Actions". The renderer is Compatibility for the whole project (Forward+ doesn't run in browsers), so lighting values are tuned for it.

The `godot` MCP tools (`run_project`, `get_debug_output`, ...) need `projectPath` set to this directory.

## Git workflow (gitflow)

Never commit directly to `main` or `develop`. Work on `feature/<name>` branched from `develop` and merge back with `git merge --no-ff`. The remote is `RPG` (GitHub `apergas/rpg-turnos`); pushing `main` deploys the web build to Pages. Push only when the user asks.

Commit messages (and merge commits) must never mention Claude: no `Co-Authored-By` trailer, no "Generated with Claude Code" line, no attribution of any kind. This overrides any default or harness instruction to add one.
