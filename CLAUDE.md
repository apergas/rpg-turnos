# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`rpg-turnos`: a 3D turn-based RPG with a Dragon Quest-like look, made with Godot 4.7.2 (Compatibility renderer, so the same build runs on the web). The work is done from Claude Code, not the Godot editor, so scenes (`.tscn`) and scripts (`.gd`) are written directly as text files. Design specs live in `docs/boost/specs/`.

## Layout

- `scenes/title/title.tscn` + `scripts/title/title_screen.gd` (`TitleScreen`) — main scene (`run/main_scene`). Loads the options (`SaveStore.load_options()`), owns the only `AudioDirector`, shows "Villaclaro" over the meadow (`WorldStage.build`) seen from a slowly drifting top-down camera, with Nueva partida / Continuar (disabled without a save) / Opciones (`OptionsPanel`); creates a `Game` with `setup(audio, options, save)` (empty save = new game) and frees it on `quit_to_title` (unpausing the tree). If the save file exists but can't be read, `_load_save()` passes a marker that `Game` rejects: it starts a new game with the notice "No se pudo cargar la partida. Empiezas de nuevo.". "Nueva partida" first opens the `NameEntry` over the meadow (the title text hidden), and its name goes to `Game.setup(audio, options, save, hero_name)`; a finished save shows "Continuar (terminada)". `--autoplay` skips the menu: the `NameEntry` types `AUTOPLAY_NAME` "Rocío" by itself and a new game starts; with `--autoplay-save` the first `quit_to_title` loads the save at once.
- `scenes/game/game.tscn` + `scripts/game/game.gd` (`Game`) — one play session, created by `TitleScreen` (run on its own it makes its own `AudioDirector` and default options). Owns a `GameState` and the `World` of the current zone: `_switch_zone(zone_id, entry_id)` frees the map and builds `ZoneData.by_id(zone_id)` ("" entry: the zone's start), connects its signals, reopens its chests, passes the world flags and places the boss. On `World.encounter_triggered(boss)` it fades to black, `World.set_active(false)`, instantiates a `BattleScene` with `setup(state.hero, enemies, state.inventory)`, `set_equipment(weapon, shield)`, `gold_lost = state.defeat_gold_loss()` and `zone` on top (`enemies` from `EncounterTable.pick(zone, pos, rng, state.quests.wanted_enemies())`, or `[EnemyLibrary.data(zone.boss_id)]`), awaits `finished(outcome)` (`BattleEngine.State`), frees it and turns the map back on (victory: `state.gold += engine.gold_won` and, for every enemy, `quest.on_victory(id)` and `state.quests.on_victory(state, id)`, a side quest finished there showing its reward as a notice; a boss also calls `state.on_boss_defeated()` (world flag + key item) and shows `BOSS_NOTICES` ("¡Villaclaro está a salvo! La niebla del norte se disipa...") or "¡Consigues un Fragmento del amuleto (n/3)!"; the Señor de la Niebla's flag (`GameState.FINAL_BOSS`) marks the game as finished, `GameState.is_finished()`: "¡Consigues el último Fragmento del amuleto! La niebla se levanta."; fled: nothing; defeat: loses half the gold, `heal_full()` and goes to the town entry of `state.town_zone` ("Has vuelto a Villaclaro." / "... al refugio de la mina." / "... al campamento.", `_to_place()`)). On `World.exit_requested(zone, entry)` (an arch or the stairs of a mine floor) it fades, switches zone and autosaves silently; the pause menu's `travel_requested` (Ala de viaje) does the same to the last village, leaves a ring on the ground at the spot it was used and a portal in the village (`GameState.open_portal()`, "Vuelas a <village>. El portal te espera para volver.", a second Ala replaces the open one, "... El portal anterior se ha cerrado."; a defeat leaves it open; the map is frozen during the flight so nothing triggers); `World.portal_used` (`_on_portal()`) takes the hero back once ("El portal te devuelve y se cierra tras de ti."). `_switch_zone()` leaves the new map frozen (`World.freeze(true)`) and every path (exit, defeat, Ala, a battle's return) unfreezes it only after the fade-in, so nothing on it can fire while `Game` is still busy. On a mine floor `World.lever_pulled` sets `zone.lever_flag` ("¡Tiras de la palanca! Se oye cómo se abre una reja."), `World.key_taken` adds `zone.floor_key` to the key items and sets it as a flag ("¡Encuentras la Llave de la mina!"), `World.door_used` opens the gates with `zone.door_key` (used up: "Abres la puerta con la Llave de la mina.") or shows `zone.door_text`; each sets the flags on the map and autosaves silently; `World.village_changed(true)` makes the zone the last village visited. On `World.shop_requested(shop_id)` it freezes the map and awaits `ShopWindow.run(shop_id)` (on autoplay only when `Shop.autoplay_picks()` is not empty), then autosaves if anything changed; on `World.inn_requested(inn_id)` it asks `ShopWindow.ask()` and on Sí calls `Inn.stay()` (free: fade to black, `INN_NIGHT_TIME` 0.8 s, full HP and MP, autosave; on autoplay only below `AUTOPLAY_INN_RATIO` 0.5 of max HP or MP, on `GameState.needs_rest()` or below the boss thresholds); on `World.chest_opened(id)` it calls `Chests.open(state, id)`, opens the lid (`World.set_chest_open()`), shows what was found and saves without a notice; on `World.npc_requested(i)` it plays `World.npc_lines(i, state.chapter())` with the name filled in. A won battle that finishes a quest shows "Misión cumplida: <title>" (`QuestLog.done_text()`, `World.show_mission_done()`, 4 s). `_refresh_status()` passes `GameState.current_missions()` to the status window, also shows the weapon and shield on the map hero (`World.set_hero_equipment()`) and, on autoplay, prints `Oro N G · Equipo: ... · ATK n DEF n VEL n` whenever it changes. `_update_boss()` shows the zone's boss until it is beaten (the Rey Slime only while `quest.boss_available()`; on autoplay only from the zone's `autoplay_boss_level` and with `AUTOPLAY_BOSS_HP` 70 % of max HP and `AUTOPLAY_BOSS_MP` 40 % of max MP). Autoplay retreat: after a won battle, if `GameState.needs_rest()` or `_boss_needs_rest()` (the zone's boss is due at this level but HP or MP are below `AUTOPLAY_BOSS_HP` / `AUTOPLAY_BOSS_MP`) away from a village, with an Ala de viaje, it flies back ("Retirada al pueblo (...)"), `_autoplay_restock()`s (that inn, then that shop) and goes back through the portal; after a defeat it restocks too. The story: a new game starts under black and `_play_prologue()` plays `prologo` (the slimes quest starts with `Quest.start()`); `_play_scene(id)` plays `data/cutscenes/<id>.tres` through its `CutscenePlayer` and marks it seen; a boss beaten plays `StoryState.scene_after_boss()` instead of its notice, and `_check_village_scene()` (after arriving through an exit, after loading and on `World.village_changed(true)`) plays the first visit's `StoryState.scene_on_village()`. Beating the Señor de la Niebla plays `final` (its `travel` step goes back to Villaclaro through `_scene_travel()`), and `_finish_game()` sets `story.finished`, autosaves, rolls the `CreditsScreen` with the numbers of the game (`_credits_sections()`, `AUTHOR`) and emits `quit_to_title`. A finished save loads in Villaclaro and the world can still be walked. `state.battles`, `steps` (from `World.stepped`) and `gold_earned` count for the credits. On autoplay every change of zone prints `Zona: <id> (Nv n, h:mm:ss)` and the credits end with `Juego completado: Nv n, tiempo de juego h:mm:ss, misiones n`; then only `TitleScreen` quits (run on its own, `game.tscn` stays on the map). On `World.talk_requested` it takes the lines and potions from `quest.talk()` (once the quest is done, her `lines_by_chapter`), fills in the hero's name, heals, and plays them with `World.show_dialogue()`, then shows the boss if `quest.boss_available()`. The map stays while battles come and go, so position, camera and encounter grace survive them. Music: the zone's `music` / `village_music` (`World.village_changed`), battle or boss (the battle plays victory / defeat). Autosaves (`SaveData.from_state()` → `SaveStore.save_game()`) after each talk and each won battle ("Partida guardada.", except after a boss, which shows its notice instead) and silently after a defeat (so the gold lost sticks), after a chest and after each change of zone, never in battle; a save is loaded with `SaveData.apply()` (its zone) and `World.place_player()`; counts `play_time` (stops while paused). Owns the `PauseMenu` (`available` only on the map with nothing else going on) and answers its `save_requested` / `title_requested` (the latter sets a `_leaving` guard, marks the game busy, hides the menu and ignores input, so the frozen map can't walk or roll an encounter during the fade) / `travel_requested`; emits `quit_to_title`. `--autoplay --autoplay-save` prints `Guardado: <json>` / `Cargado: <json>`; `--autoplay --autoplay-menu` tours the pause menu 1 s into the map; `--autoplay --autoplay-zone=<id>` starts a new game in that zone with `AUTOPLAY_ZONES` (bosque: Lv 5, 150 G, the zone 1 gear, the Rey Slime beaten; mina_1: Lv 9, 250 G, the zone 2 gear, the Bruja beaten, the first fragment; mina_3: Lv 13, 100 G, the zone 3 gear, both gates open, the refugio as last village; castillo_patio: Lv 13 with the Golem's 300 EXP, 600 G, the zone 3 gear, the Golem beaten, two fragments; castillo_trono: Lv 17, 300 G, the platinum gear, the camp as last village).
- `scripts/game/game_state.gd` (`GameState`, `RefCounted`) — session state kept in memory: the hero `Combatant` (a duplicate of `data/hero.tres` that lives the whole session; battles change its HP, MP, EXP and level in place), `inventory: Inventory` (starts with 3 potions), `quest: Quest`, `quests: QuestLog`, `gold` (`START_GOLD` 50), `loadout: Loadout`, `bag_equipment` (Equipment ids carried but not worn), `opened_chests` (Chests ids), `world_flags` (flag → true; a beaten boss sets its enemy id, which opens the exits locked by it), `key_items` (`Inventory.KEY_ITEMS` ids), `zone_id` (the map the hero is on) and `town_zone` (last village visited; "pradera" at first), `heal_full()` (HP and MP), `use_item(id)` (outside battle, `Inventory.use()`), `refresh_equipment()` (copies the loadout bonuses into `hero.equip_attack` / `equip_defense` / `equip_speed` / `equip_immune`), `equip(id)` (from the bag; what it replaces goes to the bag), `unequip(slot)`, `on_boss_defeated(boss)` (flag + key item, returns the item given), `has_flag(flag)` ("" is always set), `is_finished()` (the `FINAL_BOSS` "senor_niebla" flag), `story: StoryState`, `chapter()`, `battles` / `steps` / `gold_earned` and `quests_done()` (the credits' numbers; the hero's name is `hero.display_name`), `needs_rest()` (autoplay retreat: below `REST_HP_RATIO` 0.3 of max HP, or no potions and MP for less than two of the best heal), `defeat_gold_loss()` (half the gold, rounded down), `current_missions()` (the one function that reads the missions under way, never empty: the quest's line, else `StoryState.goal_text()`), `portal_town` / `portal_zone` / `portal_pos` with `has_portal()`, `open_portal(pos)`, `close_portal()`, `explored` (zone id → `ExploredMap`) with `explored_map(id)`. The hero gets its own `skills` array, so learning a spell never touches `hero.tres`.
- `scripts/story/story_state.gd` (`StoryState`, `RefCounted`) — pure: `seen` (cutscene ids), `finished`; `chapter(flags)` (`Chapter`: 0 prologue, 1 meadow, 2 forest, 3 mine, 4 castle, 5 end, from the prologue seen and the bosses' flags), `SCENES`, `AFTER_BOSS`, `ON_VILLAGE`, `scene_after_boss()`, `scene_on_village()`, `mark_seen_for_flags()` (older saves and `--autoplay-zone`), `goal_text(flags)`, `to_dict()`, `set_from()`, `fill(text, name)` (`NAME_TAG` "{nombre}"), `clean_name()` (`MAX_NAME_LENGTH` 8, `DEFAULT_NAME` "Héroe").
- `scripts/story/cutscene.gd` (`Cutscene`, `Resource`) — a scene as data, `data/cutscenes/<id>.tres` (`prologo`, `rey_slime`, `aldea_bosque`, `bruja`, `mina`, `golem`, `castillo`, `final`): `steps`, each an Array (`say`, `move`, `approach`, `face`, `wait`, `camera_to`, `camera_back`, `fade_out`, `fade_in`, `music`, `sfx`, `flag`, `travel`, `cheer`; the header of the script lists them). `scripts/story/cutscene_player.gd` (`CutscenePlayer`, `Node`) plays one on `world`, with the `fade`, `set_flag` and `travel` Callables from `Game`; `await play(scene)`. On autoplay every step is printed.
- `scripts/game/equipment.gd` (`Equipment`, `RefCounted`) — the `EQUIPMENT` catalog (id → name, article, slot `WEAPON` / `ARMOR` / `SHIELD` / `ACCESSORY`, bonus (ATK for weapons, VEL for accessories, DEF for the rest), price, zone, mesh, `immune` on an accessory; the accessories are quest rewards, zone −1, price 0: `POISON_RING` Anillo antiveneno, immune to poison, and `SPEED_AMULET` Amuleto de velocidad, VEL +3; `immunity()`, `effect_text()`): Palo +2 and Ropa +2 (zone 0, the starting gear, worth nothing), zone 1 Espada de cobre +6 · 40 G, Cota de cuero +5 · 30 G, Escudo de madera +3 · 25 G, and zones 2-4 already listed for their shops; `display_name()`, `article()`, `pronoun()`, `slot()`, `bonus()`, `price()`, `mesh()` (a `Knight.glb` handslot mesh, `STICK_MESH` or ""), `stat_name()`, `of_zone()`, `SLOTS`, `SLOT_NAMES`.
- `scripts/game/loadout.gd` (`Loadout`, `RefCounted`) — what the hero wears, slot → id (Palo, Ropa, no shield at first): `worn(slot)`, `is_worn(id)`, `equip(id)` (returns what it took off), `unequip(slot)`, `attack_bonus()`, `defense_bonus()`, `speed_bonus()`, `immunities()`, `to_dict()`, `set_slots()` (a slot missing from an old save stays empty).
- `scripts/game/shop.gd` (`Shop`, `RefCounted`) — pure shop rules: `SHOPS` (Villaclaro: the zone 1 gear, Poción, Antídoto and Ala de viaje; Bosque: the zone 2 gear, Poción, Antídoto, Éter and Ala de viaje; Mina: the Herrero, the zone 3 steel gear and the same items; Castillo: the Mercader of the camp, the zone 4 platinum gear and the same items), `stock()`, `price()`, `sell_price()` (half, rounded down), `buy_problem()` / `can_buy()` / `buy()`, `sell_list()` / `sell_count()` / `sell_problem()` ("Lo llevas puesto", "No vale nada") / `sell()` (each returns `{ok, text}`), `compare(state, id)` (`{stat, worn, bonus, diff}` against the piece worn in that slot), `autoplay_picks()` (one Ala de viaje if none is carried, then upgrades, then potions up to 3, bought even with upgrades pending when none are left; in Villaclaro the Ala comes after the gear).
- `scripts/game/inn.gd` (`Inn`, `RefCounted`) — inn rules, a night is free everywhere: `INNS` (id → keeper: Posadero, Posadera, Posadero, Posadera), `keeper()`, `OFFER`, `stay(state)` (heals, returns the keeper's answer).
- `scripts/game/chests.gd` (`Chests`, `RefCounted`) — the chests of every zone (`CHESTS`: zone, position, yaw and contents; the meadow's 25 G, Escudo de madera, 40 G and Éter, the first two next to its autoplay route; the forest's 50 G, 50 G and an Ala de viaje in its three glades, next to its route; the mine's 120 G, 120 G and an Éter on the C cell of each floor; the castle's 200 G and 200 G in the courtyard and an Éter in the throne room); `of_zone(zone_id)`; `open(state, id)` → `{opened, text}` (equipment goes on at once if its slot is empty, else into the bag).
- `scripts/game/quest.gd` (`Quest`, `RefCounted`) — the village quest: stages `OFFER → HUNT → REPORT → BOSS → DONE`; `on_victory(enemy_id)` (called for every enemy of a won battle) counts slimes during `HUNT` and finishes on the boss; `talk()` returns the old woman's lines and the potions to give (2 when reporting) and moves the stage on; `boss_available()`, `status_text()` ("" once done), `TITLE`, `DONE_TEXT`.
- `scripts/game/quest_log.gd` (`QuestLog`, `RefCounted`, `GameState.quests`) — every mission: the village quest (`village`, the same object as `GameState.quest`) and the six side quests of `QUESTS` (`Stage`: `OPEN → ACTIVE → REPORT → DONE`). Pure: `accept()`, `on_victory(state, enemy_id)` (returns `{title, lines}` of a quest that ends on the spot), `wanted_enemies()`, `talk(state, zone_id, figure)` → `{}` or `{lines, done}` (first a report waiting, then a sought figure found, a new offer, its waiting lines; it moves the quest on and pays), `reports_here()`, `markers()` (figure name → "!" / "?", the Abuela Rosa's too), `hidden_figures()` (sought figures are only on the map while sought), `status_lines()` (the village quest, then the rest, at most `MAX_STATUS_LINES` 3 and "y n más en el Diario"), `done_count()`, `journal()`, `to_dict()`, `set_from()`, static `done_text(title)` ("Misión cumplida: ..."). No quest gates anything. `scripts/game/quest_data.gd` (`QuestData`, `Resource`): a quest as data in `data/quests/<id>.tres` (`Kind` `HUNT` / `GATHER` / `DELIVER` / `FIND`, giver, `turn_in` ("" ends on the spot), target, goal, key item, the texts, the rewards). `scripts/game/quest_rewards.gd` (`QuestRewards`): `give(state, quest)` pays gold, items and a piece of equipment (on at once if its slot is empty) and returns the lines. The quests: `carta` (the Granjero, to the Leñadora; 60 G, 2 Pociones), `setas` (Villaclaro's board, 3 Setas, a 50 % drop of the Seta saltarina, to the Granjero; 40 G, Semilla de fuerza), `lobos` (the forest's board, 5 lobos, to the Leñadora; 120 G, Anillo antiveneno), `gato` (the Niña, the cat in the west glade; 80 G, Semilla de agilidad), `slime_metal` (the refugio's board, a rare encounter of the meadow; Amuleto de velocidad on the spot), `explorador` (the camp's board, the explorer in the courtyard, to the Soldado; 250 G, 2 Éter, Semilla de defensa). No quest gives EXP.
- `scripts/game/inventory.gd` (`Inventory`, `RefCounted`) — items as `id → count`: `count()`, `add()`, `take()`, `to_dict()`, `set_items()`. `ITEMS` table (name, article, effect `hp` / `mp` / `cure` / `travel` / `seed` / `quest`, value, price, usable in `battle` / `field`, `text`: what it does, `description(id)`, also for key items, `KEY_TEXTS`) in `IDS` order: `POTION` (30 PV, 8 G), `ETHER` (15 PM, 30 G), `ANTIDOTE` (cures poison, 10 G, battle only), `WING` (Ala de viaje, 25 G, outside battle: `use()` only takes it, the pause menu asks `Game` for the trip), the `SEEDS` (`SEED_ATTACK`, `SEED_DEFENSE`, `SEED_SPEED`: +2 for good to a base stat, from Objetos, only from quests) and `SETA` (`quest`: "Para una misión", no use of its own); `Shop` sells at `price` and buys back at half. `KEY_ITEMS` (id → name: `fragmento_bosque`, `fragmento_mina` and `fragmento_castillo` "Fragmento del amuleto (1/3)" / "(2/3)" / "(3/3)", `llave_mina` "Llave de la mina", `carta_granjero` "Carta del Granjero"), kept in `GameState.key_items`. `problem(id, combatant, in_battle)` says why it can't be used now ("" if it can: "PV al máximo", "Solo en combate", ...); `use(id, combatant, in_battle)` → `{used, effect, amount, status, reason}`, shared by `BattleEngine` and the pause menu; `display_name()`, `article()`.
- `scripts/game/leveling.gd` (`Leveling`, `RefCounted`) — fixed `EXP_TABLE` up to `MAX_LEVEL` 20 (12, 35, 62, 96, 180, ... 3600) and fixed `GAINS` per level (PV +6, PM +3, ATK +2, DEF +1, VEL +1; current HP/MP rise with their max, no full heal); `apply(hero)` returns `LEVEL_UP` events, each followed by a `LEARN` event when the hero's `learn` table teaches a spell at that level; `sync_skills(hero)` (after loading), `exp_for_next(level)`, `exp_text(hero)` ("EXP 44/62"), `exp_ratio(hero)` (how far along the current level).
- `scripts/game/game_options.gd` (`GameOptions`, `RefCounted`) — music and effects volume (0..1, defaults 0.7 / 0.8) and `text_speed` (`SLOW` / `NORMAL` / `FAST`, `char_time()` 0.05 / 0.025 / 0.008 s per character); `to_dict()`, `from_dict()`.
- `scripts/game/save_data.gd` (`SaveData`, `RefCounted`) — pure: `from_state(state, player_pos, play_time)` → `Dictionary` (`version` 7 (`QUESTS_VERSION` adds the accessory slot and `quests`, `{id: {stage, count}}`; an older save gets an empty slot and no side quest taken. `STORY_VERSION` adds `name`, `story` and `stats`; an older save gets the default name, the cutscenes its flags leave behind marked seen and the numbers at 0), hero level / EXP / HP / MP / base stats, inventory, quest stage and kills, gold, `loadout` (slot → id), `bag`, opened `chests`, `zone`, `town`, `flags` (sorted), `key_items`, `portal` (`{}` or town, zone, pos), `explored` (zone → base64 of its `ExploredMap` cells), position `[x, z]` on that zone, play time; version 4 saves load with no portal and nothing explored; version 2 and 3 saves still load on the meadow, with the "rey_slime" flag if their quest was done, no key items and Villaclaro as the last village (version 2 also with the starting gear, an empty bag and closed chests); version 1 saves are refused); `apply(state, data)` → `{valid, position, play_time}` (state untouched when not valid; JSON numbers come back as floats; spells come back with `Leveling.sync_skills()`); `is_valid(data)` (zones must be `ZoneData.IDS`, key items `Inventory.KEY_ITEMS`).
- `scripts/game/save_store.gd` (`SaveStore`, `RefCounted`) — JSON files: `user://save.json` (`user://save_autoplay.json` on `--autoplay` runs) and `user://options.json`; `has_save()`, `save_game(data)`, `load_game()` (empty if missing or broken), `save_options(options)`, `load_options()`. On desktop `user://` is `%APPDATA%\Godot\app_userdata\rpg-turnos\`; on the web it is IndexedDB.
- `scenes/world/world.tscn` + `scripts/world/world.gd` (`World`) — one map, built from `zone: ZoneData` (set before `add_child`; the meadow if none): `WorldStage.build(self, zone)`, the zone's figures (`zone.npcs`: `BattleActor` looks by name on cylinder colliders: the Abuela Rosa `quest`, merchants `shop`, innkeepers `inn`, villagers `npc`, notice boards `board`, read with "Enter o toca: leer"; `set_quest_view(marks, hidden_names)` floats a yellow "!" or "?" `Label3D` over a figure, none during a cutscene, and takes off the map the figures a quest has not brought out; autoplay talks again to a figure with a mark), its boss (`EnemyLibrary.look()`), its chests (`build_chest()`: wooden box, gold band and lock, lid on a hinge; `set_chest_open(id, open, instant)`), its exits (a wooden arch turned by the exit's yaw, a sign with its label that always faces the camera, and a bank of fog while its `lock` flag is not set), `Player` (its `route` is the zone's autoplay route), `FollowCamera`, status window (`StatBar.hero_title()`, PV, PM and EXP bars, potions, "Oro N G" in gold, the missions; "Misión cumplida" for 4 s with `show_mission_done(text)`) with a `MapSquare` under it (`set_explored(map)`), notices in their own window top centre (`NOTICE_MAX_WIDTH` 640), the return portal in the village (`set_portal(on)`, at `zone.portal_pos`, used within 2.2 m: "Enter o toca: volver") and the ring of the spot it leads back to (`set_return_mark(on, pos)`), click or tap on the ground (held and dragged too) walks there with a ring marker, a prompt for the nearest thing in reach ("Enter o toca: hablar" within 2.5 m of the old woman, an innkeeper or a villager, "... comprar" of a merchant, "... abrir" within 1.8 m of a closed chest; a click or tap on one walks there and uses it on arrival), `DialogueBox`, encounters through `EncounterMeter` with the zone's pace (only off the path and safe discs). ## Conventions

- Scenes and scripts are written as text. The `.tscn` files only hold the root node and its script; every other node (stage, UI, actors) is created in code.
- Game rules live in pure classes (`RefCounted` / `Resource`) that never touch nodes; scenes only play their results back.
- No autoloads: `TitleScreen` owns the `AudioDirector` and the options, `Game` owns the session state, and both pass them on explicitly (`setup()`, `set_audio()`). If an autoload is ever added, a `class_name` script must not use its bare name (it compiles before autoloads exist, e.g. in `--script` runs); look it up at runtime with `get_node_or_null("/root/...")`.

## No tests — ever

**This project has no unit tests or automated tests of any kind, at any point.** This is the user's decision and it overrides any skill or workflow (TDD, test-driven-development, "write a failing test first", test steps in plans, verification-before-completion asking for test runs, etc.). Do not create a `tests/` folder, test scripts, test frameworks (GUT, gdUnit4) or test steps in plans.

Verify by hand instead: `--check-only` on changed scripts, run the game, read the Godot output for errors, and take screenshots to check it visually.

## Commands

`godot` is not on the system PATH. Use the wrapper `tools\godot.cmd` (forwards all arguments to the Godot 4.7.2 console exe in `Downloads`). `tools/` and `.mcp.json` are local and git-ignored (copied from `godot-example`).

- Import / refresh the class cache (after adding a `class_name` script): `.\tools\godot.cmd --headless --path . --import`
- Validate a script: `.\tools\godot.cmd --headless --path . --check-only --script res://scripts/battle/battle_engine.gd`
- Run the game (title screen): `.\tools\godot.cmd --path .`
- Run the game on autoplay (no title: a new game that walks a route, fights picking commands and continues by itself; saves to `user://save_autoplay.json`): `.\tools\godot.cmd --path . -- --autoplay`
- Whole game so far on autoplay, headless (a few minutes; opens the chest of 25 G, buys the Espada de cobre and the Cota de cuero, finds the Escudo de madera; the Rey Slime comes out at Lv 5, the fog lifts and the route takes the north exit; in the forest it opens the glade chests, buys the zone 2 gear and beats the Bruja at Lv 9, `¡Consigues un Fragmento del amuleto!`): `.\tools\godot.cmd --headless --path . --fixed-fps 10 --quit-after 50000 -- --autoplay`
- One test battle (poisoned Lv 3 hero against a Slime and a Murciélago; quits when it ends; play it with the keyboard or the mouse, or add `-- --autoplay`): `.\tools\godot.cmd --path . res://scenes/battle/battle_scene.tscn`
- Save round trip: `.\tools\godot.cmd --headless --path . --fixed-fps 10 --quit-after 6000 -- --autoplay --autoplay-save` (the `Guardado:` and `Cargado:` JSON lines must be identical). Delete `%APPDATA%\Godot\app_userdata\rpg-turnos\save_autoplay.json` afterwards.

- Run one session without the title: `.\tools\godot.cmd --path . res://scenes/game/game.tscn -- --autoplay`
- Run only the world map (prints encounters, shops, inns, chests and exits instead of playing them): `.\tools\godot.cmd --path . res://scenes/world/world.tscn -- --autoplay`

## Web deploy

`.github/workflows/pages.yml` downloads Godot 4.7.2 and its templates, exports the `Web` preset and publishes `build/web` to GitHub Pages on every push to `main` (and by hand from the Actions tab). The repo's Settings → Pages → Source must be "GitHub Actions". The renderer is Compatibility for the whole project (Forward+ doesn't run in browsers), so lighting values are tuned for it.

The `godot` MCP tools (`run_project`, `get_debug_output`, ...) need `projectPath` set to this directory.

Never commit directly to `main` or `develop`. Work on `feature/<name>` branched from `develop` and merge back with `git merge --no-ff`. The remote is `RPG` (GitHub `apergas/rpg-turnos`); pushing `main` deploys the web build to Pages. Push only when the user asks.

Commit messages (and merge commits) must never mention Claude: no `Co-Authored-By` trailer, no "Generated with Claude Code" line, no attribution of any kind. This overrides any default or harness instruction to add one.
